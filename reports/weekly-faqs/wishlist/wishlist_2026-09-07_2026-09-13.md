## 1. Getting Started / Wishlist Page Setup & Links

### Q1: Wishlist page shows only the title, no content, even though the app embed is confirmed ON
**Frequency:** ~1 session
**Standard answer:** First confirm the page the customer is viewing is actually the app's own generated page. Joy Wishlist only renders content on its auto-created page at the `/pages/joy-wishlist` URL — if a different page (e.g. one manually created at `/pages/wishlist`) is being used instead, it will only ever show its title with no content, since the app has nothing to render there. Check the exact URL under **Content → Pages** and compare it against the app's real generated page. If they don't match, either update the store's menu/links to point at the correct `/pages/joy-wishlist` page, or ask the team to help reconcile which page should be used.
🆕 new — not covered by the existing "Wishlist page is blank" causes in `ref_getting-started` (navigation, app embed, hidden content block), which don't mention a page-handle mismatch as a cause.

### Q2: The wishlist heart icon or a menu link leads to a "Page not found" (404) error
**Frequency:** ~1 session
**Standard answer:** This is almost always a page-link issue, not a broken app page — a menu item or a link inside another page's content was set up manually and points at an old, incorrect, or duplicate page handle (e.g. `/pages/pages-joy-wishlist-1`) instead of the app's real generated wishlist page. Check **Content → Pages** for the actual current wishlist page handle and update the menu item or link to point there instead. If the original generated page genuinely can't be found, the team can create a new one for the store.
🆕 new — related to, but distinct from, the already-documented "Wishlist page is locked to `/pages/joy-wishlist` and can't render on a separate custom page" note in `ref_wishlist-design` — that note doesn't address the 404/broken-link symptom specifically.

## 2. Icon & Button Custom Positioning / Styling (recurring, COVERED)

### Q3: Reposition the wishlist icon (mobile header icon conflicting with other icons, collection-page icon left↔right, spacing between icon and search/cart icons)
**Frequency:** ~3 sessions
**Standard answer:** None of these are self-serve toggles — the header icon's default position is fixed left of the profile/bag icon, and repositioning elsewhere (mobile nav conflicts, moving a collection-page icon to a specific side, adjusting spacing) needs a custom CSS/code change from the team. Share the theme name and the exact desired position/spacing, and the team applies it on request — no collaborator/theme access needed for a styling-only change like this.
🔁 recurring (matches `ref_wishlist-design` § Wishlist Access / § Styling & CSS customization limits)

### Q4: Match the wishlist item-count badge (the small number circle) styling to the cart icon's badge
**Frequency:** ~1 session
**Standard answer:** The item-count badge's color fields are self-serve (Wishlist Access → General settings → Number of items color), but matching exact sizing/position/font details to another icon's badge (e.g. the cart icon) goes beyond those fields — collect the exact CSS spec and the team applies it on request; no collaborator/theme access needed.
🔁 recurring (matches `ref_wishlist-design` § Styling & CSS customization limits)

### Q5: Place the wishlist button directly on top of the product image instead of next to Add to Cart
**Frequency:** ~1 session
**Standard answer:** This isn't supported today — the wishlist button can only be positioned next to Add to Cart via the standard toggles or a team-applied custom-CSS reposition; it can't render directly on top of the product image. This has been logged as a feature request.
🔁 recurring (matches `ref_wishlist-design` § Wishlist Button, "Also not feasible today" note, verbatim)

## 3. Custom Icon Upload

### Q6: A custom-uploaded icon (e.g. an SVG) doesn't appear on the storefront
**Frequency:** ~1 session
**Standard answer:** Before treating this as a display bug, check whether the icon is actually rendering but blending into the header background color (e.g. a dark custom icon on a dark header) — this is a common cause and not a bug. Recommend either switching back to the default app icon, which is designed for visibility across header styles, or re-uploading the custom icon in a color with better contrast against that header.
🆕 new — `ref_wishlist-design` documents the recommended upload spec (1:1 ratio, under 200kb) but not this specific "invisible due to low contrast" failure mode.

## 4. Integrations

### Q7: Does connecting Joy Wishlist to Klaviyo require installing Joy Loyalty?
**Frequency:** ~1 session
**Standard answer:** Yes — there's no standalone/direct Klaviyo connection inside Joy Wishlist. Wishlist events (items added, price drops, back-in-stock) reach Klaviyo only through an installed, Klaviyo-connected Joy Loyalty app acting as the middleware. Setup is a 4-step flow shown on the Wishlist **Settings** page: (1) install & connect Joy Loyalty to Klaviyo, (2) pick which wishlist events to forward inside Joy Loyalty, (3) enable those wishlist event triggers on the Joy Loyalty side, (4) flip the wishlist event sync toggle on the Wishlist Settings page.
🔁 recurring (matches `ref_integrations` § Klaviyo and `ref_settings` § Klaviyo event sync, verbatim) — see the "What changed" note above re: an incorrect answer given mid-chat by a human agent before being corrected.

## 5. Theme & Template Setup

### Q8: Do I need to add the Wishlist Button block separately to every product page template?
**Frequency:** ~1 session
**Standard answer:** Yes — if a store has multiple product page templates (e.g. from a page-builder app), the Wishlist Button block needs to be added individually to each template via Theme Editor; it doesn't automatically apply across all of them from a single setup.
🔁 recurring (matches `ref_wishlist-design` § Not yet available and `case_wishlist-button-not-showing`, verbatim)

### Q9: Wishlist app conflicts with the theme's own built-in wishlist feature (e.g. MINIMOG)
**Frequency:** ~1 session
**Standard answer:** Some themes (MINIMOG is a known example) ship with their own native wishlist icon/page, which can create duplicate icons or URL mismatches when Joy Wishlist is also active. The permanent fix is disabling the theme's native wishlist feature so only Joy Wishlist is active; the team can also apply custom JS/CSS to visually sync Joy Wishlist's icon with a theme's existing icon style, but making every part of a theme's native wishlist (including the items already saved under it) fully interchangeable with the app isn't supported.
🔁 recurring (matches `ref_wishlist-design` § Branding & known limitations, which names MINIMOG explicitly) — this window's specific case (session 12) was still open/unresolved with the tech team as of the last message (app settings not affecting items already rendered by the theme's native wishlist page); no new standard answer beyond the documented limitation, since there's no confirmed resolution yet to write down.

## 6. Roadmap / Feature Requests

### Q10: When will back-in-stock or price-drop notifications for wishlisted products be available?
**Frequency:** ~1 session
**Standard answer:** These aren't available yet — they're on the roadmap, but there's no confirmed release date to share. Merchant interest is logged and passed to the product team.
🔁 recurring (matches `ref_integrations` § Omnisend, verbatim)

### Q11: Can I filter or see which specific products are most-wishlisted (not just store-wide totals)?
**Frequency:** ~1 session
**Standard answer:** Not directly — the Dashboard only shows store-wide totals (Total Items Added, Unique Customers, Conversion Rate), with no per-product breakdown or filter. The closest workaround today is **Customers → Export CSV**, which lists individual product entries (title, variant, price, date added) per customer. A dedicated "most-wishlisted products" report is a repeatedly requested roadmap item, not currently available.
🆕 new (first time asked in a mined run) — already correctly documented in `ref_analytics`, no gap.

## 7. Language & Translations

### Q12: Does Joy Wishlist support Arabic? / which languages are supported
**Frequency:** ~1 session
**Standard answer:** Arabic isn't supported yet. Currently supported storefront translation languages are English, Spanish, French, German, Italian, Portuguese (Brazil), Japanese, and Chinese (Simplified), managed under **Settings → Translations**.
🔁 recurring (matches `ref_translations` § Where to manage it, verbatim)

### Q13: Text was edited in the correct place but the live storefront still shows the old text
**Frequency:** ~2 sessions
**Standard answer:** First hard-refresh or clear browser cache and check again — a stale cached page is the most common cause and isn't a saving failure (this resolved one of this window's two cases). If the correct edit location was used (Wishlist Design → Button compositions for the store's default language, or Settings → Translations for another language), the cache was cleared, and the old text still shows, this points to a backend sync issue rather than a translation-setup mistake — escalate to the tech team with the exact field and expected vs. actual text (this was the root cause in the other case this window, since fixed).
🔁 recurring — matches the existing correct-location guidance in `ref_translations`/`ref_wishlist-design`, but neither file currently gives the cache-first / escalate-if-persists troubleshooting sequence — see diff (PARTIAL).
