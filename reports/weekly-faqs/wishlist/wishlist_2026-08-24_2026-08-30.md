## 1. Getting Started

### Q1: Installing Joy Wishlist on a second store — do settings/design carry over automatically?
**Frequency:** ~1 session
**Standard answer:** Yes, you can install Joy Wishlist on another store and it has the same features available — but each store is separate, so Wishlist Access, Wishlist Button, Wishlist Page design, and Settings need to be configured fresh on the new store; nothing carries over automatically from the first store.
🆕 new — logged as a KB gap (see diff report), not currently documented in `ref_getting-started`.

## 2. Wishlist Button & Icon Placement

### Q2: Can the heart icon be placed directly on the product image instead of next to Add to Cart?
**Frequency:** ~1 session
**Standard answer:** This isn't currently supported — the wishlist heart icon can only be positioned next to the Add to Cart button (via the standard toggles or a team-applied custom-CSS reposition), not placed directly on top of the product image itself. This has been logged as a feature request for future development.
🆕 new — logged as a KB gap (see diff report).

### Q3: Add the wishlist icon to a specific spot in the main navigation bar (not the default header icon position)
**Frequency:** ~1 session
**Standard answer:** The built-in Header icon setting only supports the default left-of-profile/bag placement — matching a different nav bar layout (e.g. a specific desktop nav location styled like another site) needs custom work from the team. Share the exact desired position and, if matching another site's style, that site's URL, and the team applies it via custom CSS — no collaborator/theme access is needed for this kind of styling change.
🔁 recurring (same underlying custom-positioning flow as prior header-icon FAQs; the exact "match another site's nav bar style" request is new framing but the resolution path is the documented one)

### Q4: Add the wishlist icon to the mobile navigation bar specifically (not just the default mobile placement)
**Frequency:** ~1 session
**Standard answer:** The header icon's position isn't customizable to a different spot within the mobile nav — same limitation as desktop, where the icon only sits in its default position. This has been logged as a feature request; there's no confirmed way to add it as a separate top-nav item on mobile today.
🆕 new — logged as a KB gap (see diff report). *(Note for Liz: this was handled as a flat "not possible" — worth confirming with the team whether a custom-CSS nav-bar injection is genuinely infeasible or just not attempted, since other placement requests in this same window were resolved via custom CSS.)*

### Q5: Add to Wishlist button missing on most product pages (multiple product templates)
**Frequency:** ~1 session
**Standard answer:** The Wishlist Button block needs to be added to each product page template individually via Theme Editor — Show on product details page in the app only controls visibility, it doesn't auto-add the block to every template. If a store has multiple product templates, the team can add the block to all of them on request (needs Theme access via collaborator code).
🔁 recurring (matches `case_wishlist-button-not-showing` exactly)

### Q6: Header icon disappeared or shows a "theme doesn't support a header icon" message after duplicating/updating the theme
**Frequency:** ~1 session
**Standard answer:** When a theme is duplicated or majorly updated, the header icon's manual code customization doesn't automatically carry over to the new theme copy — even if both the app embed and Header icon toggle are already on. The team needs the exact theme name to re-add the icon's code to the new theme directly.
🔁 recurring (matches `case_header-icon-not-showing` exactly, including the duplicated-theme scenario)

### Q7: Header icon color can't switch between white and dark to match a transparent-to-solid scrolling header
**Frequency:** ~1 session
**Standard answer:** The icon/background color is a fixed, self-serve setting — it can't dynamically respond to a theme's scroll-based header color change (e.g. transparent → white on scroll). The practical options are: pick one color with good contrast across all header states, or make the header background consistent across all pages (not just the homepage) so the icon color stays consistent everywhere.
🔁 recurring — matches documented limitation in `ref_wishlist-design` § Wishlist Access General settings almost verbatim.

### Q8: Add to Wishlist button not available on the Search Results page
**Frequency:** ~1 session
**Standard answer:** The Wishlist button currently only injects on Home, Product, and Collection pages — it isn't supported on the Search Results page. This has been logged as feedback for future consideration.
🆕 new — logged as a KB gap (see diff report).

## 3. Cart Drawer Integration

### Q9: Cart drawer tab (or points redemption widget) enabled/embedded but still not rendering after switching themes
**Frequency:** ~2 sessions
**Standard answer:** First confirm the theme's cart type — the Wishlist cart-drawer option only works with the theme's native Shopify cart drawer, not a cart page or a third-party cart app. If it's a native drawer and the Joy Wishlist app embed is already ON for the new theme (**Online Store → Themes → Customize → App embeds**), but the tab still doesn't render, that points to a code-level compatibility issue with the specific theme, not a settings issue — the team needs to add it directly to that theme's code.
🆕 new — logged as a KB gap (see diff report): the KB documents cart-drawer *compatibility* (native vs. third-party) but has no case doc for "embed is on, drawer is native, tab still doesn't render" the way `case_header-icon-not-showing` covers the equivalent header-icon scenario.

## 4. Wishlist Page & Login Flow

### Q10: After a guest clicks Add to Wishlist and logs in, they land on the account page instead of returning to the page they were viewing
**Frequency:** ~1 session
**Standard answer:** By default, logging in from the wishlist login prompt redirects to the account page rather than back to the original page the guest was viewing. Redirecting back to the previous page after login is a custom behavior our team needs to set up — this isn't a self-serve setting today; share the request and, if possible, theme access so the team can implement it.
🆕 new — logged as a KB gap (see diff report), not currently documented in `ref_guest-wishlist` or `ref_wishlist-design`.

### Q11: Full product titles are truncated in the wishlist drawer/popup
**Frequency:** ~1 session
**Standard answer:** There's no confirmed self-serve setting to control title truncation length in the wishlist drawer/popup — this needs a custom adjustment from the team; share the request and the team will apply it.
🆕 new — logged as a minor KB gap (see diff report), low frequency.

## 5. Loyalty / VIP Integration

### Q12: Can a non-VIP customer add a VIP-tier-locked product (Joy Loyalty Exclusive Products) to their wishlist?
**Frequency:** ~1 session
**Standard answer:** Yes — as long as there's a wishlist button visible on that product's page, any customer (VIP or not) can add it to their wishlist. Joy Loyalty's VIP-tier product locking only affects **purchasing** (a non-VIP customer sees an unlock message like "Upgrade to Gold to buy this item" in place of Add to Cart) — it doesn't hide the product or its wishlist button from non-VIP customers, since Joy Wishlist and Joy Loyalty have no product-level integration today. There's currently no built-in way to hide VIP-restricted products from the general public or from wishlisting.
🆕 new — logged as a KB gap (see diff report): not documented in `ref_integrations` (Joy Loyalty section) or `ref_wishlist-design`.

## 6. Data Import / Export

### Q13: Can a file of customers and their existing wishlisted products be imported into Joy Wishlist?
**Frequency:** ~1 session
**Standard answer:** No — Joy Wishlist doesn't currently support importing a file of customers with their associated wishlisted products; wishlist items are only saved when a customer interacts with the storefront directly (clicking Add to Wishlist). This has been logged as a feature request.
🆕 new — logged as a KB gap (see diff report). Distinct from the already-documented "import from another wishlist app (e.g. Swym)" limitation in `ref_integrations` — this is about importing raw customer/product association data, not migrating from a competing app.
