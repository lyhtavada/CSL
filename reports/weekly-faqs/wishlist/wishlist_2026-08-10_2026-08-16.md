## 1. Getting Started

### Q1: Can Joy Wishlist be added to a website built on a different platform (not Shopify)?
**Frequency:** ~1 session
**Standard answer:** No — Joy Wishlist is a Shopify app and only works on a Shopify storefront. It can't be installed or embedded on a website built on another platform (e.g. WordPress, Wix, a custom-built site).
🆕 new (first time this exact question showed up)

## 2. Wishlist Widget & Button Display

### Q2: Can the header/button icon color be changed to an exact hex code?
**Frequency:** ~1 session
**Standard answer:** Yes — Icon color and Background color are self-serve fields under **Wishlist Design → Wishlist Access → General settings** (for the header icon) or **Wishlist Design → Wishlist Button → General settings** (for the per-product button), and accept a specific hex value directly. *(Note for Liz: the live chat this window treated this as a manual dev-team escalation instead of pointing to the self-serve color field — worth a quick heads-up to the team, not a KB gap.)*
🆕 new — training note, not a KB issue

### Q3: Can the wishlist icon's background be made transparent (remove the circle/ring behind it)?
**Frequency:** ~2 sessions
**Standard answer:** The Background color field (on both Wishlist Access and Wishlist Button General settings) only supports solid colors — there's no transparent/none value. Setting it to match the page background (e.g. white) results in an invisible icon, not a true transparent look. A genuinely transparent background needs custom CSS applied by the team — share the request and no collaborator/theme access is needed for this kind of styling change.
🔁 recurring (same topic as last run's Q6, KB already documents this limitation explicitly)

### Q4: Can the wishlist button/icon be resized and repositioned closer to the Add to Cart button?
**Frequency:** ~1 session
**Standard answer:** There's no built-in size or position setting for this — share the exact spec (target size in px, desired position) and the team applies it via custom CSS from the backend; no store/collaborator access is needed for this. Note: after any custom CSS resize/reposition fix, it's worth double-checking the whole page/section afterward — a change to one element can occasionally have a knock-on layout effect on a nearby unrelated element.
🔁 recurring (same underlying styling-request flow as prior repositioning FAQs)

### Q5: Header icon toggled on but not appearing on the storefront, or appears misaligned with cart/search icons
**Frequency:** ~3 sessions
**Standard answer:** Check two things first: (1) the app embed — **Online Store → Themes → Customize → App embeds → turn ON "Joy Wishlist"**, Save; (2) the **Header icon** toggle under **Wishlist Design → Wishlist Access**. If both are already on and it's still not showing or is misaligned, it's a code-level fit issue (not a settings issue) — the team applies a CSS adjustment once given the theme name. Note: by default the header icon can only sit to the **left** of the profile/bag icon — it can't be moved to the right. If the icon previously worked and disappeared after duplicating or majorly updating a theme, that's expected — manual code customization on the old theme doesn't carry over automatically to a new theme copy, even with app settings already on.
🔁 recurring (matches `case_header-icon-not-showing` exactly)

### Q6: Wishlist heart icon doesn't appear (or can't be repositioned) on "You may also like" / recommended-product card blocks
**Frequency:** ~2 sessions
**Standard answer:** The standard Wishlist Button toggles (**Show on product details page / collection page / home page**) cover those three page types, but recommendation-style blocks like "You may also like" use a different product-card layout that isn't automatically covered by those toggles — showing the icon there needs a separate setup applied by the team on request, it's not a flip-a-switch fix. Share the store URL and which recommendation block/section is affected so the team can apply it.
🆕 new — logged as a KB gap (see diff report). *(Note for Liz: one chat this window had the live agent say repositioning was "only supported for the Wishlist page," which conflicts with how the same kind of request was resolved via custom CSS on product cards in other chats — flagging as a possible agent-training inconsistency, not encoding either version into the KB patch until confirmed.)*

## 3. Cart Drawer Integration

### Q7: Does the Wishlist cart-drawer option work with any cart app, or only Shopify's native cart drawer?
**Frequency:** ~2 sessions
**Standard answer:** The cart drawer integration is built to work with the theme's **native Shopify cart drawer**. If a merchant uses a third-party cart app, compatibility isn't guaranteed since it depends on how that app renders the cart — this needs to be checked case by case with the team. Also, if the store only has a cart **page** (not a cart drawer) enabled in the theme, the Wishlist option won't have anywhere to render — the cart drawer itself needs to be enabled first before the team can help set up the Wishlist option inside it.
🆕 new — logged as a KB gap (see diff report), not currently documented anywhere in the live KB.

## 4. Wishlist Page & Access

### Q8: Customer can add items to their wishlist but can't find where to view the full saved list
**Frequency:** ~1 session
**Standard answer:** Go to **Wishlist Design → Wishlist Access** and enable at least one of: **Header icon** (near header/cart icon), **Floating button** (fixed on the storefront), or **Main menu page** (a normal menu link) — any one gives customers a way to open their full saved list. This is a different tab from **Wishlist Button** (the per-product add-to-wishlist heart icon) — a common mix-up.
🔁 recurring (documented since prior runs' access-setup FAQs)

### Q9: Do items saved to a customer's wishlist ever expire, or do they stay saved indefinitely?
**Frequency:** ~1 session
**Standard answer:** There's currently no expiry/retention-duration setting for wishlisted items — once a customer saves a product, it stays on their wishlist with no automatic time limit. (There is also no way to configure one today if a merchant wanted items to expire.)
🆕 new — logged as a KB gap (see diff report), not currently documented anywhere in the live KB.

### Q10: Can Wishlist content be embedded on a custom page instead of the app's default Wishlist page?
**Frequency:** ~1 session
**Standard answer:** No — the Wishlist page is automatically created by the app at the `/pages/joy-wishlist` URL, and Wishlist content can currently only render on that dedicated, app-generated page. It can't be embedded or rendered on a separate custom page (e.g. an existing page a merchant already built at a different URL). This includes cases where a merchant's wishlist widget shows saved items correctly but a separate custom "favorites" page on their site doesn't reflect them — that's the same underlying limitation.
🆕 new — logged as a KB gap (see diff report), not currently documented anywhere in the live KB.

## 5. Analytics / Customer Data

### Q11: How can I see exactly which products a specific customer added to their wishlist (not just a count)?
**Frequency:** ~1 session
**Standard answer:** The Customers table shows aggregate counts per customer (items added, total items paid, revenue), not individual products. For the specific product list, use **Export CSV** on the Customers page — it lists each product title, variant, price, and the date it was added, per customer. (Note: variant SKU isn't included in the export today — that's a known, already-logged product-feedback gap, not a bug.)
🔁 recurring (matches `ref_customers`, resolved the same way in chat)

## 6. Translations

### Q12: Is the previously-hardcoded wishlist text (empty-wishlist message, "Sign in," "Share wishlist") now translatable?
**Frequency:** ~3 sessions
**Standard answer:** Yes — this has shipped. Nearly all storefront-facing wishlist text, including the empty-wishlist message, the "Sign in" button, and the "Share wishlist" text, can now be translated per language under **Settings → Translations** (a separate page from Wishlist Design, which only edits the default language's text). Add a language, then open the Wishlist button / Wishlist page / Email capture & recovery sections to edit that language's version of every string. If a string isn't translated yet for a visitor's detected language, it falls back to the shop's default language, then to English.
🔁 recurring — **status changed since last run**: last week's FAQ said this text was hardcoded/untranslatable; it has since shipped and the live KB now explicitly documents it. No longer a gap.

**Frequency:** ~1 session
**Standard answer:** This was a display bug where the configured button text (e.g. under Wishlist Button → Button text) didn't match what rendered on the storefront. It has been fixed — configured text now displays correctly.
🆕 new — bug already fixed by time of chat, no diff action needed.

## 8. Edge Cases

### Q15: Leftover UI marks/elements remain after uninstalling a different (previously installed) wishlist app
**Frequency:** ~1 session
**Standard answer:** If a merchant switched to Joy Wishlist from another wishlist app (e.g. Wishlist Plus) and sees leftover UI elements after uninstalling the old app, that's code left behind by the other app, not something Joy Wishlist can remove — recommend contacting that app's support team, since they're best positioned to clean up their own leftover code/theme snippets.
🆕 new — logged as a minor KB gap (see diff report), low frequency.

### Q16: Feature request — integration with MCP/Claude
**Frequency:** ~1 session
**Standard answer:** An MCP (Model Context Protocol) connection isn't currently available for Joy Wishlist. This has been logged as a feature request and forwarded to the product team, with no confirmed timeline.
🆕 new — genuine feature request, no verifiable official answer beyond "not available, logged as feedback" (per `ref_case-handling` § Feature Requests) — no KB patch needed, too niche for a dedicated KB entry at this time.
