## 1. Getting Started / Setup

### Q1: Wishlist page shows blank / nothing appears on the page I created
**Frequency:** ~5 sessions
**KB coverage:** 🟡 PARTIAL — `getting-started.md` covers the two quickstart steps (Enable App + Save in Theme Editor) but not this specific symptom.
**Standard answer:** A blank Wishlist page is almost always one of two things:
1. The page hasn't been added to your store's navigation yet — go to **Shopify Admin → Content → Menus → Main menu → Add menu item → select the "My wishlist" page the app generated → Save**.
2. The app embed isn't enabled on the theme — go to **Online Store → Themes → Customize → App embeds → turn ON Joy Wishlist**, then Save.
Also double-check you're previewing the correct theme (draft vs. live) — several merchants were troubleshooting the wrong theme.

### Q2: Is Joy Wishlist free?
**Frequency:** 1 session (but likely underasked since it's a new app)
**KB coverage:** 🔴 GAP — no pricing info anywhere in KB.
**Standard answer:** As confirmed by agents in chat, the app is currently free. **Do not state plan limits or future pricing** — this was not otherwise documented; verify against chatty.net/pricing or the current Shopify listing before quoting anything beyond "currently free."

## 2. Wishlist Access — Header Icon & Floating Button

### Q3: How do I display/enable the wishlist icon in the header?
**Frequency:** ~30 sessions — the single most common request in the entire dataset.
**KB coverage:** 🟡 PARTIAL — `wishlist-design.md` documents the "Header icon" option under Wishlist Access, but almost every real session needed an agent to manually toggle it and then push a Theme Editor save, because merchants couldn't get it to visually appear from the setting alone.
**Standard answer:** Go to **Apps → Joy Wishlist → Wishlist Design → Wishlist Access**, enable **Header icon**, then open **Theme Editor** and click **Save** to apply the embed. Reload the storefront (hard refresh / incognito) to confirm. If it still doesn't appear after the toggle + save + refresh, the theme may need the app embed re-enabled (**Customize → App embeds → Joy Wishlist → ON**) or, for custom/non-standard themes, may need a manual CSS/selector fix from the tech team (grant Theme collaborator access to proceed).

### Q4: Can the header icon be positioned on the right side of the logo / bag icon / anywhere I want?
**Frequency:** ~8 sessions
**KB coverage:** 🔴 GAP — this constraint is not documented anywhere.
**Standard answer:** By default, the header icon can only be placed to the **left of the profile icon or shopping bag icon** — not to the right. Positioning is also theme-dependent; some themes (multi-menu, custom desktop/mobile nav, Plus custom themes) need the tech team to add custom CSS/selectors via Theme access to get it aligned with other header icons (search/account/cart). This is a common enough request that it should be flagged as a known limitation rather than promised as flexible.

### Q5: The header icon is still not showing even though I enabled it
**Frequency:** ~6 sessions
**KB coverage:** 🔴 GAP
**Standard answer:** Common root causes seen in chat: (1) app embed not saved in Theme Editor after toggling the setting, (2) the theme has a missing closing tag in `theme.liquid` preventing the app script from loading (theme-code bug, needs dev fix), (3) the theme has separate desktop/mobile menus and the app only injects into one — needs a script/selector added by the tech team, (4) settings reset after a theme update and need to be re-toggled. If basic toggle + reload doesn't work, escalate for Theme access and a manual code-level check.

### Q6: Can I use a floating wishlist button instead of / alongside the header icon?
**Frequency:** ~3 sessions
**KB coverage:** ✅ COVERED — `wishlist-design.md` documents Floating button, Main menu page, and Header icon as combinable access types with position options (top/center/bottom, left/right).

### Q7: Icon color/background — can I make it transparent, change background, or match theme colors automatically as header background changes?
**Frequency:** ~3 sessions
**KB coverage:** 🔴 GAP
**Standard answer:** Basic icon/background/border color and icon type (Heart/Star/Flag/custom) can be set under Wishlist Access → General settings. However, the app **cannot dynamically change color based on JS-driven theme events** (e.g. header color changing on scroll) — this is a real limitation confirmed by the dev team. Recommend picking one icon color with good contrast against all header states rather than promising dynamic matching.

## 3. Wishlist Button (Product / Collection Pages)

### Q8: The wishlist button isn't showing on my product page(s) — especially custom themes or multiple product templates
**Frequency:** ~10 sessions
**KB coverage:** 🔴 GAP — `wishlist-design.md` mentions enabling "Show on product details page" but doesn't cover custom-theme cases or multi-template stores.
**Standard answer:** For standard themes, enable **Wishlist Design → Wishlist Button → Show on product details page**, then add the Wishlist Button block via Theme Editor. For **custom/non-standard themes** where the block doesn't render (error like `"wishlist-button" not added. Liquid templates don't support sections and blocks"`), a snippet needs to be added manually to the theme code:
```
<div class="Joy-Wishlist-ButtonWrapper"></div>
```
Add this above `</body>` in theme.liquid, or use the product-card snippet:
```
<div class='Sun-Wishlist-ProductCard__Injection' data-product-id="{{ card_product.id }}" data-variant-id="{{ card_product.selected_or_first_available_variant.id }}"></div>
```
Full guide: `avadagroup.gitbook.io/joy-wishlist/getting-started/publish-your-docs/wishlist-button/add-snippet-code-to-theme-code`. **Important:** if the store has multiple product page templates, the button/block must be added to each template individually — this is the #1 cause of "button disappeared on this one product page" tickets.

### Q9: Can the wishlist button show on the home page / collection page thumbnails?
**Frequency:** ~5 sessions
**KB coverage:** 🟡 PARTIAL — `wishlist-design.md` mentions "Show on home/collection page" requires snippet code, but doesn't give the snippet or explain it needs per-template setup like Q8.
**Standard answer:** Enable **Show on home/collection page** under Wishlist Button settings. This generally requires the tech team to add the snippet/CSS to the theme for correct placement on thumbnails — same process and caveats as Q8.

### Q10: Do you have a snippet/custom code I can add myself to place the button anywhere?
**Frequency:** ~4 sessions
**KB coverage:** 🔴 GAP
**Standard answer:** Yes — the button injection snippet is:
```
<div class='Sun-Wishlist-ProductCard__Injection' data-product-id="{{ card_product.id }}" data-variant-id="{{ card_product.selected_or_first_available_variant.id }}"></div>
```
Guide: `avadagroup.gitbook.io/joy-wishlist/getting-started/publish-your-docs/wishlist-button/add-snippet-code-to-theme-code`. There is **no global custom placement code** that works for every theme — placement varies by theme structure, so results can vary and may need adjustment.

### Q11: Can the wishlist button be placed in the exact same row/block as "Buy it now" or "Add to cart"?
**Frequency:** ~2 sessions (one extensive)
**KB coverage:** 🔴 GAP
**Standard answer:** Not reliably possible — confirmed by the dev team as **not feasible**: the Wishlist button is built as its own separate theme section/block and cannot be merged into the same block as Buy Now/Add to Cart. The practical workaround agents use is adjusting the Wishlist button's width/padding/alignment via custom CSS so it visually sits close to the ATC row, not literally inside it. Set expectations accordingly rather than promising a merge.

## 4. Wishlist Design & Styling Customization

### Q12: Can you change the button/icon color, size, border-radius, alignment, font size, or margin?
**Frequency:** ~15 sessions — very common, almost always resolved via custom CSS pushed by the tech team.
**KB coverage:** 🟡 PARTIAL — `wishlist-design.md` covers the built-in color/icon settings in the app UI, but most real requests (border-radius, exact px alignment, matching a specific brand font/button style, reducing button size on specific templates) go beyond the UI and require the tech team to add custom CSS to the theme backend (requires Theme collaborator access).
**Standard answer:** Basic color/icon/button-text customization is self-serve via **Wishlist Design → Wishlist Button/Access → General settings**. For anything beyond that (custom border-radius, precise alignment/margins, matching another button's exact style, uppercase text, hiding on mobile only, etc.), our team can apply custom CSS on the backend — this requires Theme access via a Shopify collaborator code. Note: custom CSS can sometimes get reverted by theme updates or re-editing in Theme Editor; if a previously-fixed style reverts, it usually needs to be re-applied.

### Q13: There's no CSS editor in the app dashboard — can I add my own CSS?
**Frequency:** 1 session, likely representative of a broader ask
**KB coverage:** 🔴 GAP
**Standard answer:** There is currently no self-serve CSS editor in the app. All custom styling is applied by the support/tech team on request (requires Theme access).

### Q14: Product card image size/cropping, title/price font size on the wishlist page — can these be adjusted?
**Frequency:** ~3 sessions
**KB coverage:** 🔴 GAP
**Standard answer:** Image sizing (e.g., making product images larger/non-cropped, switching aspect ratio to square) and text sizing on wishlist page/product cards can be adjusted via custom CSS from the tech team — same access process as Q12.

## 6. Guest Wishlist & Customer Accounts

### Q18: Why do customers have to log in / create an account to use the wishlist?
**Frequency:** ~4 sessions — a common point of friction/confusion for merchants who expect guest wishlisting.
**KB coverage:** 🔴 GAP — this is a core policy question with no KB answer at all.
**Standard answer:** Customers must be logged in / have a Shopify account to add items to their wishlist and have it tracked. This is required because the app identifies and tracks each customer's wishlist by their account — there is currently no fully anonymous/guest wishlist tracking option in the merchant-facing app (see Q20 for the partial guest-email-capture flow, which is separate).

### Q19: Login/register error when trying to add to wishlist (New Customer Accounts theme)
**Frequency:** 1 session
**KB coverage:** 🔴 GAP
**Standard answer:** If the store uses Shopify's **New Customer Accounts**, the Login/Create Account buttons on the Wishlist page redirect to Shopify's native registration/login page — this can fail to open correctly inside the Theme Editor preview (Shopify manages the new account pages outside theme editor control), but works normally on the live/published site. This redirect destination cannot be changed by the app (it's a Shopify-level setting under **Settings → Checkout**).

### Q20: What is the "email capture" popup and how does guest tracking work?
**Frequency:** ~2 sessions
**KB coverage:** 🔴 GAP — `customers.md` doesn't mention guest/email-capture flow at all.
**Standard answer:** There's an optional **"Show email capture prompt"** setting. When enabled, a form appears for guests (not logged in) to leave their email, so their wishlist can be recovered later/on another device — but this does **not** create a Shopify customer account and these guests will **not** appear in the Customers list until they actually sign in to a real account. If this popup is unwanted, it can be disabled in Settings.

## 8. Translations / Multi-language

### Q23: Can I translate the Wishlist page text, empty-state message, sign-in banner, or share-wishlist text into another language?
**Frequency:** ~6 sessions — one of the most consistently unresolved requests in the whole dataset.
**KB coverage:** 🔴 GAP — `getting-started.md` only covers changing the app's admin UI language, not storefront-facing text translation.
**Standard answer:** Be precise about what IS and ISN'T translatable:
- **Page title & description** on the Wishlist page ARE editable/translatable — go to the Wishlist Page section in the app and edit the text directly.
- **Other built-in strings** — the empty-wishlist message ("Your wishlist is empty," "Continue shopping"), the login-modal text, the "Sign in" button, and the "Share wishlist" text are **hardcoded in the widget and not translatable from app settings today.** This has been a repeated, unresolved dev request across many merchants (some stores were told ~1-2 weeks ETA, but treat any timeline as unconfirmed unless verified live). Log as product feedback rather than promising a date.
- If a translation app is installed, note that some translation apps can override metafields and cause unexpected partial-translation behavior — worth checking before assuming it's an app bug.

### Q24: Can the shared-wishlist link use my custom domain instead of myshopify.com?
**Frequency:** 1 session
**KB coverage:** 🔴 GAP
**Standard answer:** Currently, the share-wishlist link is generated using the store's default `.myshopify.com` domain — there's no setting to switch it to a custom domain. Logged as product feedback for the dev team.

## 9. Analytics & Reporting

### Q25: Can I see the most popular / most-wishlisted products, or filter/sort by product?
**Frequency:** ~4 sessions
**KB coverage:** 🔴 GAP — `getting-started.md` only documents the 3 dashboard metrics (Total Items Added, Unique Customers, Conversion Rate) at a store-wide level; there's no per-product breakdown.
**Standard answer:** There is currently no dedicated analytics section showing which specific products are wishlisted most. The Customers export (Q21) is the closest workaround today, since it lists individual product entries per customer. A dedicated "most-wishlisted products" report has been requested repeatedly and forwarded to product — treat as roadmap item, not available.

### Q26: Do wishlist events sync to Meta Pixel / can I track "Add to Wishlist" for ad platforms?
**Frequency:** 2 sessions
**KB coverage:** 🔴 GAP
**Standard answer:** Yes — Wishlist events are published via `shopify.analytics.publish` and can be picked up by a **Custom Pixel**. Setup: **Shopify Admin → Settings → Customer Events → Add Custom Pixel**, subscribe to the `avada_wishlist:add` event, e.g.:
```js
analytics.subscribe('avada_wishlist:add', (event) => {
  fbq('trackCustom', 'AddToWishlist', {
    content_ids: [event.customData.productId],
    content_type: 'product',
    value: event.customData.value,
    currency: event.customData.currency,
    content_name: event.customData.handle
  });
});
```
For Meta specifically, merchants also needed to create a matching Custom Event ("add to wishlist") in Meta Events Manager for it to register correctly. If a merchant needs help setting up the Custom Pixel, offer to do it via Theme access.

## 13. Bugs / Technical Issues & Theme Conflicts

### Q32: Wishlist icon conflicts with another (native/theme-bundled) wishlist app already on the store
**Frequency:** 2 sessions (one extensive, MINIMOG theme case)
**KB coverage:** 🔴 GAP
**Standard answer:** If a theme has its own native wishlist (e.g. MINIMOG, or another installed wishlist app), duplicate heart icons or URL mismatches are common. The team can sometimes apply a temporary CSS fix to hide the conflicting icon, but the **permanent, correct fix is to disable the other wishlist app/feature** so only Joy Wishlist is active. Native theme wishlist integrations (matching a specific theme's built-in icon set/positions exactly) are not currently supported — this has been logged as a feature request per-theme, not a general capability.

### Q33: Clicking the wishlist icon redirects to the cart instead of opening the wishlist
**Frequency:** 1 session — resolved as a genuine bug
**KB coverage:** N/A (bug, not a KB topic)
**Standard answer:** This was a confirmed bug (icon incorrectly wired to the cart action) that was fixed after dev escalation. If a merchant reports this, escalate to the dev team rather than treating it as a CSS/config issue.

### Q34: The wishlist button/icon disappears intermittently or after a theme update
**Frequency:** ~3 sessions
**KB coverage:** 🔴 GAP
**Standard answer:** Common causes seen in chat: (1) custom CSS previously applied gets wiped when the theme is updated to a new version — needs to be re-applied by the tech team; (2) settings get reset in the app after certain theme changes and need re-toggling; (3) app embed gets disabled after switching themes. If it's intermittent with no clear trigger, escalate to dev for investigation rather than re-applying the same fix repeatedly.
