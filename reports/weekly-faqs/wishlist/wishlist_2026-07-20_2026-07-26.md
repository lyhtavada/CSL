## 1. Getting Started / Setup

### Q1: Merchant wants a full walkthrough — what the app does, enabling it, choosing widget access type, adding the product-page button, editing button text, adding to menu, wishlist page setup, email-capture config
**Frequency:** 1 session (long onboarding conversation)
**How resolved:** Wendy walked the merchant through each step in sequence: Enable App → Save in Theme Editor; choose access type (floating button / header icon / menu page); enable "Show on product details page" + add the block via Theme Editor; edit button text under Wishlist Button → General settings; add "My wishlist" page to the main menu (Content → Menus); configure the email-capture prompt under Settings → Configuration.
**Verdict:** COVERED — matches `ref_getting-started`, `ref_wishlist-design`, `ref_settings` closely, step for step. 🔁 recurring topic (onboarding), now much better covered than last run.

### Q2: Wishlist page shows completely blank after being set up
**Frequency:** 1 session
**How resolved:** Agent asked for a screenshot of the page's blocks in Theme Editor, requested collaborator/Theme access, and found the actual cause: the page was using the **default page template** with its **content block hidden**. Fix: assigned a **dedicated wishlist-page template** to the page and unhid the content block.
**Verdict:** 🟡 PARTIAL — see diff report. 🔁 recurring topic, 🆕 new specific root cause not previously documented.

## 2. Wishlist Access — Header Icon

### Q3: Wishlist icon (previously working, manually added) disappears after duplicating or updating the theme

**Verdict:** 🟡 PARTIAL — see diff report. 🔁 recurring topic (header icon not showing), 🆕 new specific trigger (theme duplication) not previously named as a symptom.

## 6. Hiding the Wishlist Icon in a Specific Section

### Q11: Hide the wishlist heart icon in one specific home-page section (e.g. "Product Pickup") without affecting the rest of the home page
**Frequency:** 2 sessions
**How resolved:** In both cases, the agent (Hana / Wendy) turned OFF the global "Show on home page" toggle — which hides the icon from **all** home-page sections, not just the one requested. Neither transcript shows the merchant objecting, but this is broader than what was asked.
**Verdict:** ✅ COVERED in KB terms (`case_hide-wishlist-icon` and `ref_wishlist-design` both correctly describe that a single-section hide needs custom CSS, not the global toggle) — flagging as a **process/QA note** in the diff report, not a KB content gap: real agent behavior didn't follow the KB's disambiguation flow (Step 1: ask for screenshot; distinguish "all sections" vs "just this one section" before acting).
