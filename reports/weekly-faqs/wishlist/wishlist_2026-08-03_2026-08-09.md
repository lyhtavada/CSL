## 1. Getting Started

### Q1: What does Joy Wishlist actually do — is it the same as the loyalty/cashback app?
**Frequency:** ~1 session
**Standard answer:** Joy Wishlist and Joy Loyalty are two separate apps. Joy Wishlist lets customers save products they're interested in for later, so they can easily find and purchase them when ready — it does not configure loyalty programs, points, or cashback. If you're looking to set up a loyalty/rewards/cashback program, that's handled in the separate **Joy Loyalty** app; please reach out to that app's support team instead.
🆕 new (first time this exact confusion — "can you help set up loyalty and cashback" — showed up in a Wishlist chat)

## 2. Wishlist Widget & Button Display

### Q2: A floating button appears on my homepage that I want removed — but support says it's not from Joy Wishlist. How do I tell?
**Frequency:** ~1 session
**Standard answer:** Joy Wishlist's own floating button is a heart-shaped icon (controlled under **Wishlist Design → Wishlist Access → Floating button** toggle) — it applies store-wide, not per-page. If the element you're seeing looks different (e.g. a plain circular button in a different position/style) it may be built into your **theme** or added by a **different app**. To check: go to **Shopify Admin → Apps** and see if another wishlist-type app is installed and disable it; if none is found, it's most likely a theme-native element, and our team can confirm by inspecting the page — if it turns out to be theme-built, you'd either find the toggle in your theme's own settings, grant us theme access so we can add a CSS snippet to hide it, or ask your theme's support team.
🆕 new — logged as a KB gap (see diff report), not previously documented as a disambiguation step.

### Q3: Wishlist icon isn't showing on home page product cards even though "Show on home page" is enabled
**Frequency:** ~1 session
**Standard answer:** Confirm the setting is on in **Wishlist Design → Wishlist Button → Show on home page**. If it's on but the icon still isn't visible, the **Wishlist Button block** also needs to be added manually in the Theme Editor for that page: go to **Online Store → Themes → Customize → select Home page → Add block (on your product card/section) → choose "Wishlist Button" → Save**. This is required because each theme's home page layout is different, so the app can't auto-inject the block into every section.
🔁 recurring (same root cause as prior runs' button-not-showing topic, applied here to the home page specifically)

### Q4: Header icon toggled on under Wishlist Access, but nothing appears on the storefront
**Frequency:** ~2 sessions
**Standard answer:** This is almost always one of two settings: (1) the app embed isn't enabled — go to **Online Store → Themes → Customize → App embeds → turn ON "Joy Wishlist"**, Save; (2) the **Header icon** toggle itself under **Wishlist Design → Wishlist Access** isn't on. If both are already on and it's still not showing (especially on a custom/multi-menu navigation theme), it's a code-level fit issue — our team can add a small CSS adjustment to position it correctly; please share your theme name so we can pass it to the tech team. Note: by default the header icon can only sit to the **left** of the profile/bag icon — it can't be moved to the right.
🔁 recurring (matches the header-icon-not-showing case doc pattern)

### Q5: Can the wishlist icon be changed to an outlined/border-only style instead of filled (like the cart icon)?
**Frequency:** ~1 session
**Standard answer:** There's no self-serve toggle for icon style (filled vs. outline) — icon type is limited to Heart/Star/Flag/custom upload under General settings. Share the exact look you'd like and our team can apply it via custom CSS from the backend; no store/collaborator access is needed for this kind of styling change.
🔁 recurring (same underlying styling-request flow as prior "icon customization" FAQs; the outline/border-only look specifically is already flagged in the KB as something the Background color field alone can't achieve — needs custom CSS)

### Q6: Can the wishlist icon be resized and given a transparent background (remove the white circle behind it)?
**Frequency:** ~1 session
**Standard answer:** The Background color field under Wishlist Design (Access or Button → General settings) only supports solid colors, not transparent — setting it to white won't give a true transparent look. For an exact size (e.g. 16×16px) and a genuinely transparent background, share the spec and our team will apply it via custom CSS from the backend; no collaborator code needed.
🔁 recurring (same topic as last run's Q6, KB now explicitly documents this limitation)

### Q7: "wishlist-button" not added — Liquid templates don't support sections and blocks (error adding the button to the product page)
**Frequency:** ~1 session
**Standard answer:** This error means your theme's product page is built as a single Liquid section that doesn't support adding app blocks via the Theme Editor — it's a theme-code limitation, not a Joy Wishlist setting issue. The fix needs a small snippet added directly to your theme code by our tech team. Please share your theme name (or grant our team theme/collaborator access) so we can add it for you.
🔁 recurring (identical error text and resolution as last run's Q3)

### Q8: How do I add the wishlist page link to my main menu manually (custom navigation)?
**Frequency:** ~1 session
**Standard answer:** Go to **Shopify Admin → Content → Menus → Main menu → Add menu item**, select the **"My wishlist"** page the app generated, then Save. Since it's a normal menu item, you can place it anywhere in a custom/non-standard navigation structure.
🔁 recurring (documented since the Dec 2025–Jul 2026 backfill run, resurfaced this window)

### Q9: Wishlist icon/button still not showing on product cards even though all settings are enabled (custom theme)
**Frequency:** ~1 session
**Standard answer:** When the relevant "Show on..." toggle is already on and the button/icon still doesn't appear, it's typically a theme-compatibility issue — our tech team identifies the correct product-card selector for your specific theme and adds it on the backend, then applies any needed CSS so the icon displays and sits correctly. Please share your store URL (and theme name if known) so the team can apply this for you.
🔁 recurring (same root cause/resolution pattern as the Liquid-block-error and header-icon cases — theme-specific backend fix)

### Q10: Can the wishlist heart icon's position on product cards be changed (e.g. it overlaps a quick-view button or sale/best-seller badges)?
**Frequency:** ~1 session
**Standard answer:** There's no built-in setting to reposition the icon on product cards — share the exact position you'd like (e.g. below the card, or a specific corner) and our team will apply it via custom CSS from the backend; no store access is needed for a store-wide styling change like this.
🔁 recurring (matches prior run's Q5 exactly — same reposition-request flow)

### Q11: Feature request — apply the Wishlist Button automatically across all product templates instead of adding it manually to each one
**Frequency:** ~1 session
**Standard answer:** Today, if a store uses multiple product page templates, the Wishlist Button block needs to be added individually to each template via the Theme Editor — there's no setting to auto-apply it across all templates at once. We understand this is extra work for stores with many product templates or frequently changing catalogs; this has been logged as product feedback for the team, with no confirmed timeline yet.
🆕 new — logged as a KB gap (see diff report), not previously documented as a roadmap item.

## 3. Translations

### Q12: Hardcoded widget text (empty-wishlist message, "Sign in," "Share wishlist") still shows in English on a non-English store
**Frequency:** ~1 session
**Standard answer:** These specific strings — the empty-wishlist message, "Sign in" button, and "Share wishlist" text — are hardcoded in the widget and aren't translatable from app settings today. This is a known, repeated request that hasn't shipped yet; it's logged as product feedback with no confirmed release date. (Note: the Wishlist Page title/description and the Login modal text — modal title/description, Create account/Log in button text — ARE editable per store under Wishlist Design.)
🔁 recurring (matches prior runs' translation-gap topic)

## 4. Settings / Sharing

### Q13: Wishlist recovery emails show my myshopify.com address instead of my store's custom domain
**Frequency:** ~1 session
**Standard answer:** This is self-serve: go to **Apps → Joy Wishlist → Settings → Custom domain**, and enter just your domain (e.g. `yourstore.com`, no `https://`, no trailing path). This replaces the default `.myshopify.com` domain on shared wishlist links and recovery emails/links. Leave it blank to keep the default. *(Note for Liz: the live chat this window escalated this to the dev team instead of pointing to this self-serve field — worth a quick heads-up to the team, not a KB issue.)*
🔁 recurring (this exact ask was previously logged as "not possible, no setting" in the Dec 2025–Jul 2026 backfill run — the app has since shipped a self-serve Custom domain field, so the correct answer has changed)

## 5. Analytics / Data Integrity

### Q14: Can a product's wishlist count be manually set or overridden in the backend (e.g. show 100 wishlists for a product with 0)?
**Frequency:** ~1 session
**Standard answer:** No — wishlist counts (both the per-product count shown on the storefront and the store-wide Dashboard totals) are always calculated automatically from real customer wishlist activity. There's no admin field or setting to manually preset or override a product's count. If your dev team has built custom code to write to this value, we can't confirm compatibility without our tech team reviewing it first — feel free to share details/screenshots of the code and we'll pass it along for review.
🆕 new — logged as a KB gap (see diff report), not previously documented.
