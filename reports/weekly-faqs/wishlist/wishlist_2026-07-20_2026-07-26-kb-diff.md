## PARTIAL detail

### Q2 — Blank wishlist page (hidden content block on default template)
`kb/reference/getting-started.md` § "Wishlist page is blank" lists exactly two causes: (1) page not added to navigation, (2) app embed not enabled on the theme. The real case in this window had a **third root cause**: the page was using Shopify's default page template, and the **page content block itself was toggled hidden** inside that template — unrelated to navigation or app embed. Support fixed it by assigning a dedicated `wishlist-page` template to the page and un-hiding the content block. Patch drafted (see payloads) adds this as cause #3.

### Q3 — Header icon missing after theme duplication/update
`kb/case/header-icon-not-showing.md` already has the right *resolution* branching (check embed, check header-icon toggle, if both already on → code-level issue → escalate), and the real chat followed exactly this flow to a correct outcome. What's missing is the **named symptom**: the file's Symptoms section doesn't call out "icon was previously added manually to a theme, then the merchant duplicates/updates that theme, and the icon + customization doesn't carry over" as a recognized trigger. Since this is a distinguishable, recurring scenario, patch drafted to add it explicitly, so the bot recognizes it faster instead of re-deriving it through the generic toggle-check flow.

### Q9 — Sign-in/login-modal button color and hover state
`kb/reference/wishlist-design.md` § Login modal documents that **text** is editable (Modal title/description, Create account button text, Log in button text) via Wishlist Design → Wishlist Page → Login modal. It does **not** say anything about **color/hover styling** for those buttons. The only "Button color" setting documented on that page (Text/Background/Border color) is explicitly for the wishlist-item add-to-cart button, not the login-modal's Create account/Log in buttons. A merchant asking to change the Sign In button's background color and hover effect has no documented self-serve path today — following the same pattern as every other styling-beyond-the-UI case in this KB (custom CSS from the tech team, no collaborator code needed), this should be stated explicitly rather than leaving the bot to either invent a setting or have no answer. Patch drafted.

## GAP detail

### Q6 — Custom wishlist icon upload spec (file format / dimensions)
`kb/reference/wishlist-design.md` § Wishlist Access → General settings lists "Icon type (Heart/Star/Flag/**custom upload**)" but gives no guidance on what file format or size the custom upload should be. Support's real-world answer (from this chat): recommend a 1:1 (square) ratio image under 200kb — not a hard app-enforced limit, just a practical recommendation. Patch drafted to add this as a short note next to the custom-upload option.

### Q8 — "Save for later" button broke after an icon-resize CSS change (no patch)
This surfaced as a side-effect of a custom CSS change (icon resize) rather than an independently reproducible bug or a documented setting. It doesn't have a clean, generalizable root cause to write into KB as a standalone fact — it reads more like "custom CSS changes can have knock-on layout effects on nearby elements; test the whole page after applying a fix," which is already implicit in `ref_wishlist-design`'s existing "custom CSS can be reverted by theme updates" caution. Not patched; flagged here as a callout for whoever handles future CSS-customization tickets to re-test surrounding elements, not just the one being changed.

### Q10 — Variant-level wishlist removal bug (no patch)
Confirmed by support as unexpected behavior (removing one variant removes all variants of the same product) and escalated to the dev/tech team for investigation. No fix, workaround, or setting was confirmed in this chat window — there is nothing verifiable to write into the KB yet. Per the rule against inventing answers, this is **not patched**. Flag for Liz to check with dev/TS on resolution status before any KB entry is written (e.g. "known issue, workaround: X" or "fixed in version Y").
