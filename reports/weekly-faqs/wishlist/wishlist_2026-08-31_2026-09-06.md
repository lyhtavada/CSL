## 1. App Activation & Setup

### Q1: App embed is ON and Header icon setting is ON, but the app dashboard still shows "inactive" and the header wishlist button doesn't work
**Frequency:** ~1 session
**Standard answer:** First confirm both are actually saved: **Online Store → Themes → Customize → App embeds → "Joy Wishlist" toggled ON → Save**, then in the Joy Wishlist dashboard click **Refresh** to re-check the active status. If the embed is confirmed ON in Theme Editor, the Header icon setting is confirmed ON, and the dashboard still reports inactive (or the header icon opens the wrong thing, e.g. the cart instead of the wishlist), this is a code-level/sync issue rather than a settings issue — escalate to the tech team with the shop domain and current theme name rather than repeating the same toggle checks.
🆕 new — not documented in `ref_getting-started` (which only covers the initial 2-step setup and "blank wishlist page" causes, not a post-setup "dashboard says inactive despite embed on") or `case_header-icon-not-showing` (which assumes the icon is simply missing, not that the dashboard itself reports inactive).

## 2. Icon/Button Custom Positioning & Styling (recurring, COVERED)

### Q2: Reposition the header icon so it lines up evenly with other header icons (account/cart) on desktop and mobile
**Frequency:** ~2 sessions
**Standard answer:** The header icon's default position is fixed left of the profile/bag icon and isn't self-serve adjustable beyond that — matching exact spacing/alignment with other header icons on a specific theme needs a custom CSS/code tweak from the team. Share the theme name (and confirm draft vs. live theme, since draft themes need the same custom code re-applied separately) and the team applies it on request; no collaborator code needed for a styling-only change like this.
🔁 recurring (matches documented `ref_wishlist-design` § Wishlist Access positioning limitation + § Styling & CSS customization limits)

### Q3: Position the wishlist icon on product thumbnails (collection/home page) at a specific corner (e.g. top-right)
**Frequency:** ~2 sessions
**Standard answer:** This is the enable/setup flow for the thumbnail wishlist button: share the store URL and the desired position (Top Left, Top Right, Center Left, Center Right, Bottom Left, or Bottom Right), and the team sets it up — this isn't a self-serve toggle.
🔁 recurring (matches `case_enable-wishlist-button-thumbnail` exactly)

### Q4: Change the wishlist button/heading font, font size, or color
**Frequency:** ~3 sessions
**Standard answer:** Font family, custom font sizing beyond the standard color pickers, and icon color changes on specific elements (e.g. the cart-drawer heart icon) aren't self-serve app settings — collect the exact spec (font name, target size in px, exact hex color, which element) and the team applies it via custom CSS/code on request. No collaborator/theme access is needed for this kind of styling-only change.
🔁 recurring (matches `ref_wishlist-design` § Styling & CSS customization limits)

### Q5: A previous custom CSS fix (e.g. resizing the wishlist icon) broke a different, unrelated element (wishlist popup layout)
**Frequency:** ~1 session
**Standard answer:** A custom CSS change to one element can occasionally have a knock-on effect on a nearby element if the applied selector is broader than intended (e.g. a class selector matching more buttons than the one targeted). Ask for a screenshot of the broken layout and, if possible, the exact CSS that was applied, then have the team scope the selector more precisely (e.g. add a size/variant qualifier) rather than removing the original fix.
🔁 recurring (matches `ref_wishlist-design` § Styling & CSS customization limits, "knock-on layout effect" note, almost verbatim)

### Q6: Manually adding the Wishlist Button snippet on an unpublished/draft theme, including when the requester doesn't own the store (managing a client's theme)
**Frequency:** ~1 session
**Standard answer:** There's no single snippet that works for every theme — the tech team needs to inspect that specific theme (including an unpublished/draft one) and add the correct snippet to the product card file directly; this normally needs Theme/collaborator access. If the person requesting doesn't have permission to grant that access (e.g. an agency or freelancer working on someone else's store), let them know the store owner needs to provide the collaborator code or approve the access request — access can't be substituted with a code snippet shared in chat, since the team can't safely apply untested code without being able to verify it in the theme first.
🆕 new (partial) — the general snippet-on-custom-theme flow is documented in `case_wishlist-button-not-showing`, but the specific "requester lacks permission to grant access because it's not their own store" scenario isn't addressed in `ref_collaborator-access` (which covers "staff vs. owner" and "collaborator limit reached," but not "requester has no relationship to the store's Shopify account at all").

## 3. Mobile & Desktop Nav Icon Placement

### Q7: Add the wishlist icon to the mobile navigation bar / mobile sidebar specifically (not the default mobile header position)
**Frequency:** ~1 session
**Standard answer:** The header icon's position isn't adjustable to a separate spot like the mobile nav bar via a self-serve setting — but this is not a hard "not possible": share the request with the team and they can implement a custom placement (e.g. adding it to the mobile sidebar menu) via dev work, similar to other custom positioning requests. Set expectations that this needs a dev task and may take longer than a settings change, especially around holidays/reduced support hours.
🔁 recurring, ⚠️ **correction to last run's answer** — last week's chat resolved this as a flat "not possible," which the prior diff report flagged as worth confirming. This week's session (16) shows the team did implement it as a custom dev task, delivering the icon on the mobile sidebar. The standard answer should follow the same "not self-serve but escalatable" pattern as Q2 above, not a flat decline.

## 4. Cart Drawer Integration

### Q8: Wishlist tab in the cart drawer isn't appearing after switching Shopify themes
**Frequency:** ~1 session
**Standard answer:** First confirm the new theme's cart type is the native Shopify cart drawer (not a cart page or third-party cart app) and that the Joy Wishlist app embed is ON for the new theme (**Online Store → Themes → Customize → App embeds**). If both are true and the tab still doesn't render, this is a code-level compatibility issue with that specific theme — escalate to the tech team with the theme name so they can add it directly to that theme's code.
🔁 recurring — 3rd confirmed occurrence across the last two windows (2 sessions in Aug 24–30, 1 more this window); still a live troubleshooting gap in the KB, priority raised.
