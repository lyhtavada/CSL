## 1. Getting Started

### Q1: How do I set up Joy from scratch, and what should I prioritize first?
**Frequency:** ~6 sessions 🔁 recurring
**Standard answer:** Follow the 5-step launch path: (1) define your goal — retention, AOV, or referrals; (2) pick one program type to start (Points is best for most stores); (3) configure earning + redeeming under **Joy Admin → Reward Programs**; (4) build a loyalty page via **Online Store → Themes → Customize → Add section → Joy Loyalty** (Essential+ only — see Q2 below for Starter); (5) enable the embed widget at **Theme Editor → App embeds → Joy Loyalty - Widget → Save**. No paid trial is required to build the whole program — all setup can be done on the free Starter plan, and upgrading later preserves every program, point balance, and customer record.

### Q2: I'm on the free Starter plan — how do customers reach the loyalty program without a dedicated loyalty page?
**Frequency:** ~2 sessions 🔁 recurring
**Standard answer:** The dedicated loyalty landing page requires **Essential ($29/mo) or above** — it's not available on Starter. On Starter, use the **widget deeplink** instead: add `#joy-home` to the store URL (e.g. `https://yourstore.myshopify.com/#joy-home`) as a menu link (Shopify Admin → Online Store → Navigation → Add menu item → URL = `#joy-home`) to open the loyalty widget directly. This works on every plan, including free.

### Q3: How do I test my program before launching, without giving real customers points?
**Frequency:** ~3 sessions 🔁 recurring
**Standard answer:** Use **Sandbox Mode**: Reward programs → Sandbox Mode → turn on → click **Test list** → enter the test email(s) (one per line or comma-separated) → Confirm. Only whitelisted emails earn points while sandbox is active; a yellow "Sandbox mode" banner shows in admin. Sign in to the storefront with a test account and perform the actions (order, sign-up, review) to verify. Turn sandbox off to go live. A common support case this week was a merchant thinking a program was broken when the real cause was the customer's email simply wasn't on the test list yet — always check this first.

### Q4: My loyalty program has very low customer participation — what can I do?
**Frequency:** ~2 sessions 🆕
**Standard answer:** Increase visibility, not the offer size, first: add a "Rewards" link to the header/footer menu (`#joy-home` deeplink), add the **Point Calculator** block to product pages so customers see "Earn X points" pre-purchase, add the **Sign-up** and **Reward Celebration** blocks to the Thank You page, and add a **Loyalty Dashboard** block to the account page. For redemption specifically, also see Q on low redemption rate below.

### Q5: We're bulk-importing existing customers into the program — will they get the sign-up bonus, and does their past spend count toward VIP tier?
**Frequency:** 1 session 🆕
**Standard answer:** Imported/pre-existing members do **not** receive the Sign-up reward or its notification email retroactively — that reward only fires through the 3 live trigger paths (login + active widget, widget popup join, or POS) after the program starts. A welcome bonus can be added manually via CSV import instead. Prior spend counts toward VIP tier only if the VIP Tier program's tracking start date is set back far enough (e.g. "from Jan 1, 2024") to include the historical window — Joy then calculates tiers automatically from that point forward.

## 2. Points — Earning

### Q6: A customer placed an order but didn't earn points — why?
**Frequency:** ~8 sessions (merged across several distinct causes) 🔁 recurring
**Standard answer:** Check in this order: (1) the order hasn't reached the reward trigger status yet (Paid or Fulfilled, set at Settings → Order); (2) the customer is a Guest, not a Member — guest checkouts don't earn if the rule targets members only; (3) the **Sandbox Mode / Test list** is on and the customer's email isn't whitelisted (this was a common cause this week — merchants testing a new rule saw "no points" and assumed a bug); (4) the order was a **draft order created in admin**, not placed via the storefront — by default Place Order programs only reward Online Store orders; if the merchant wants admin-created draft orders to count too, change the program's **Sales channel** setting to include "Online store and Admin draft orders"; (5) a conflicting rule condition (e.g. sale channel = both Online AND POS, which no order can satisfy); (6) order-level exclusions (order tag, source, payment gateway, B2B). For anything not covered by these, collect the order number + customer email and escalate.

### Q7: How does the Sign-up / "first order" bonus actually get granted?
**Frequency:** ~3 sessions 🔁 recurring
**Standard answer:** There's no separate "first order" earning rule — use the **Sign up** program (Reward programs → Earning programs → Sign up) instead; it fires once when a customer becomes a Member, which in practice is usually at or around their first order. The reward is only granted through one of 3 paths: the customer logs in to a customer account AND the Joy embed widget is active on the theme; the customer joins via the widget popup; or a POS guest is identified as a member. Leaving an email alone (checkout, newsletter, form) does not qualify, and the customer must have created their account on or after the Sign-up program's start date.

### Q8: Can I set a different / market-specific earning rate (e.g. only for Japan or Malaysia)?
**Frequency:** 1 session 🆕
**Standard answer:** Yes, via the **Rule Engine** (Advanced/Ultimate) — self-serve upgrade at Reward Programs → More actions → Rule Engine, then set customer/order conditions (e.g. market, currency, tags) on a Place Order rule with its own rate. Without Rule Engine there's no per-market rate split on lower plans.

### Q9: Points set to expire after inactivity (e.g. 6 months) don't seem to be expiring for a specific customer.
**Frequency:** 1 session 🆕
**Standard answer:** For **Full (inactivity) expiration**, the clock resets on **any** earn or spend activity for the whole balance — a customer who is periodically active will never fully expire under this rule, which is expected, not a bug. If the merchant wants points to expire on a fixed date regardless of activity, use **Fixed date expiration** instead; **Expiration by earning date (FIFO)**, where each batch of points expires independently, is Ultimate-only.

### Q10: Can I set decimal / fractional earning rates (e.g. 1.25 or 1.5 points per $1)?
**Frequency:** 1 session 🆕
**Standard answer:** The VIP tier "Bonus Points" perk field only accepts whole multipliers (2×, 3×, 4×) — no decimals. For a fractional rate, upgrade the earning program to **Rule Engine** (Reward Programs → Earning programs → More actions), then set a **Place order** rule with the decimal rate targeted at that tier via "Who to reward → Only customers in a VIP tier can earn points" (one rate field per tier). This does **not** require Shopify Flow.

### Q11: Bonus points for reviews with photos/videos — which review apps support it?
**Frequency:** 1 session
**Standard answer:** Photo/video-specific bonus splits are supported for **Loox** (Advanced plan, connect directly in Joy) and **Review Rocket**. For other review apps (e.g. Judge.me), Joy can't currently detect whether a review included media, so a photo/video-specific bonus isn't available — only a flat per-review reward.

### Q12: Does the "Write a review" points program require the customer to click the task in the widget first, or does any published review earn points?
**Frequency:** 1 session 🆕
**Standard answer:** Points are awarded via the review app's webhook when the review is **published** (subject to the Default status setting — see Q on review points below) — Joy does not check whether the customer opened the widget task first. There's no way to require "click the task, then review" as a sequence today.

### Q13: A customer's birthday reward didn't trigger even though their birthday was on file.
**Frequency:** ~3 sessions 🔁 recurring
**Standard answer:** All 4 conditions must be met: birthday saved ≥30 days before the actual date (anti-fraud rule); customer is a registered Member, not Guest; the reward's configured window (exact date / birth month / around-birthday) currently applies; and for Manual claim, the customer must click Claim. This week also surfaced two edge causes worth checking before escalating as a bug: a **minimum purchase requirement** on the birthday reward not being met by the customer's order, and (already fixed by dev) a bug affecting customers who shared the exact same birthdate. If all 4 standard conditions check out and it's still missing, escalate as a possible bug with the customer email, birthday date, and program settings screenshot.

## 3. Points — Redemption

### Q14: How does redemption actually work end-to-end?
**Frequency:** ~5 sessions 🔁 recurring
**Standard answer:** Customer logs in → opens the widget or loyalty page → **Redeem points** → picks a reward → clicks **Redeem** → then either **Apply** (pushes the code to cart) or copies the code to paste at checkout. The code does **not** apply itself — this is the most common "my discount vanished" report, where points were spent and a valid code exists but nobody entered it. Unused codes stay retrievable from **My Coupons** in the widget. Other redemption surfaces: cart drawer, checkout page (Shopify Plus + Ultimate), and POS.

### Q15: A discount code from redemption is rejected or won't combine at checkout.
**Frequency:** ~3 sessions 🔁 recurring
**Standard answer:** Identify the Joy coupon's Shopify discount class (Product/Order/Shipping) and the other active discount's class, then check Shopify's base combination rule for that pair before touching Joy's settings: Product+Shipping and Order+Shipping always combine; Product+Product only on different line items (same item needs Shopify Plus); Product+Order/Order+Order only for eligible merchants (no checkout.liquid customizations, not using Licensify); Shipping+Shipping never combines. If the pair is eligible per Shopify's rule, confirm the Joy program's **Combinations** setting has that class turned on — this only affects **newly issued** codes, not ones already in a customer's hands. If everything checks out and it still fails, escalate.

### Q16: Our redemption rate is very low (e.g. under 1%, or zero for 12 months) — what can we do?
**Frequency:** 2 sessions 🆕
**Standard answer:** Low redemption is almost always an awareness problem, not a setup problem. Turn on the **Reward reminder** popup (notifies customers once they have enough points to redeem), add the point balance to the nav menu, add a **Point Calculator** block to product pages, add a redemption section to the **cart drawer**, and add a **Sign-up** block to the Thank You page. If the program has many small redemption tiers, consider consolidating to a single **Dynamic Discount** program so customers see one clear "spend your points" action instead of a confusing list.

### Q17: If a customer refunds/cancels an order that used a redeemed discount, do their points come back?
**Frequency:** 1 session 🔁 recurring (same underlying mechanism as prior weeks)
**Standard answer:** Only if the **Refund Points** toggle is enabled on that specific redeem program (off by default) — Reward programs → Redeeming programs → [program] → turn on Refund Points. When enabled, points are refunded on a **fully cancelled** order; the coupon itself is not reactivated. Partial cancellations do not refund points for the removed items.

### Q18: How does free-gift redemption work, and can the customer change which product they picked after redeeming?
**Frequency:** 1 session
**Standard answer:** The customer redeems via the widget or loyalty page, clicks **Apply** to add the code + selected product to cart automatically — it can't be injected directly at the Shopify checkout page (a Shopify platform limit). Once a product is chosen, the code is locked to it. The only way to change it afterward is if **Enable Customer Self-Revoke Coupon** is on (Settings → Additional Features) — the customer can revoke the unused coupon, points return, and they can re-redeem a different product. Note this self-revoke/redeem-from-cart flow is not available on the Account Page (Loyalty Hub) — only in the widget/loyalty page, due to Shopify Customer Account limitations.

### Q19: Can points be redeemed for Shopify store credit instead of a discount coupon?
**Frequency:** 1 session
**Standard answer:** No — Joy's redemption programs only convert points into discount codes. Store credit is a separate earning path (configured on a Place Order program with reward type = Store Credit) that is issued directly and applied automatically at Shopify checkout; there is no redemption program that turns points into store credit. Note also that **Pending Points** (the anti-fraud holding period) does not apply to store credit — store credit is issued immediately via webhook, bypassing that hold, by design.

### Q20: Can a customer's points be transferred from one account/email to another?
**Frequency:** 1 session
**Standard answer:** There's no self-serve transfer. The team can manually adjust the balance down on the source account and up on the destination account on request — collect both customer emails and the amount, then escalate.

## 4. Widget

### Q21: The Joy widget / launcher button isn't showing on the storefront at all.
**Frequency:** ~8 sessions (merged across chunks) 🔁 recurring
**Standard answer:** Check in this order (in-app status badges can be inaccurate — go by these checks instead): (1) **App embed off** — Shopify Admin → Online Store → Themes → Customize → App embeds → Joy Loyalty - Widget → on → Save; (2) **"Hide widget button"** enabled, under On-site content → Widget → Widget design → Setup → Advanced → Display; (3) **"Display after login"** on, so guests never see it — test while logged in; (4) Customer eligibility set to "Manually assigned customers only," which hides the widget from everyone not manually added. A less common cause seen this week: the launcher's **Primary color** was set to white, blending invisibly into the page background — check color contrast if the above 4 are all fine. If none resolve it, collect the store URL and escalate.

### Q22: Can I move/reposition the widget launcher or a specific reward block (pixel-precise placement)?
**Frequency:** ~4 sessions 🔁 recurring
**Standard answer:** Rough clearance (e.g. move away from a checkout/Add-to-Cart button) is self-serve: **Settings → Launcher → Alignment**. For an exact pixel position, a mockup/target position, or placement relative to a specific theme element, built-in settings can't do it — that needs custom CSS from the team; collect a screenshot + device + page URL and escalate rather than trying to talk the merchant through DIY CSS. On-page **block order** (e.g. within the loyalty page) can only be reordered up/down via the Theme Editor's left panel drag — there's no left/right positioning control there.

### Q23: Can the widget show different settings on desktop vs mobile (e.g. hide the point balance on mobile only)?
**Frequency:** ~2 sessions 🆕
**Standard answer:** Not currently supported — launcher style/size/alignment and page-visibility rules (Show on specific pages) apply the same across devices; there's no per-device toggle today. This is logged as a product gap, not something to promise a workaround for.

### Q24: Can customers dismiss/close the floating widget button themselves (an "X")?
**Frequency:** 1 session 🆕
**Standard answer:** No built-in dismiss function exists — this is intentional, to protect program visibility/engagement, not an oversight. Only admin-side controls exist (on/off, page restriction). It can't be achieved with CSS alone since it requires real dismiss-and-remember logic per visitor. Logged as a feature request.

### Q25: How do I add redemption to the cart drawer, and why doesn't it work on my cart app?
**Frequency:** ~3 sessions 🔁 recurring
**Standard answer:** For Shopify's **native** cart drawer: On-site content → Product page tab → Redeem in Cart Drawer → Edit in Theme Editor → enable the app embed **Joy: Redeem in line** → Save. This binds to Shopify's native cart-drawer selectors and will **not** auto-attach to third-party slide-cart apps (e.g. qikify) or some page builders (e.g. PageFly). For those, ask which cart app the store uses, request theme access, and escalate for the team to add the matching CSS selector for that theme's cart button. The same root cause explains "redeem works at checkout but shows an error in the cart drawer" — reassure the merchant the coupon is valid and usable at checkout; only the cart-drawer attachment needs the fix.

### Q26: Should we move from the Classic/old widget to the Unified Widget?
**Frequency:** ~5 sessions (largely proactive outreach + reactive bug fixes) 🔁 recurring
**Standard answer:** Yes for most merchants — the Classic widget is being phased out, and several bugs reported this week (wrong colors/fonts/language, blank white button, stale leftover theme code) traced back to stores still on the deprecated widget. The Unified Widget also unlocks Store Credit display and the Reviews tab. Migration is handled by the team on request — no merchant-side setup risk to the live theme.

## 5. VIP Tiers

### Q27: Why doesn't a customer's VIP tier "points" total match their point balance?
**Frequency:** ~5 sessions 🔁 recurring
**Standard answer:** These are two **separate** metrics. **VIP tier points** = cumulative lifetime points ever earned (redeeming doesn't reduce it, on a Points-earned-based tier rule). **Point balance** = the spendable remainder after redemptions. Adjusting or resetting the point balance does **not** automatically recalculate tier points. Common causes of a mismatch: a manual point adjustment wasn't ticked "include in tier calculation" (only points from configured earning programs count toward tier by default); or some of the customer's points were earned **before** the VIP Tier program's tracking start date and so aren't counted. If numbers still don't reconcile after checking both, escalate with the customer email and both values for a manual recalculation.

### Q28: Newly added/promoted VIP members didn't get their tier's entry reward.
**Frequency:** 1 session
**Standard answer:** Common cause: the entry reward wasn't fully configured at the time of the initial tier launch, or the "grant tier entry rewards" option wasn't checked on a re-launch. The team can manually trigger entry-reward distribution for the affected list once identified — collect the tier name and affected customer emails and escalate.

### Q29: Can VIP tiers be configured differently per market (e.g. separate thresholds for Japan vs Malaysia)?
**Frequency:** ~2 sessions 🆕
**Standard answer:** No — VIP Tiers is a global, store-wide setting; there's no per-market tier configuration today. Logged as a feature request.

### Q30: Does the VIP "Bonus Points" perk support a fixed amount per order (not just a multiplier)?
**Frequency:** 1 session
**Standard answer:** The Bonus Points tier perk is multiplier-only (2×/3×/4×, whole numbers). For a **fixed** amount per order restricted to one tier (e.g. +10 points/order for Gold only), use a separate earning program instead: Reward Programs → Earning programs → Place an order → method "Fixed per order," then under "Who to reward" restrict it to that VIP tier.

### Q31: Migrating historical order/spend data and existing tier assignments from another platform (e.g. Magento) — will demotion/calculation logic behave correctly?
**Frequency:** ~2 sessions 🔁 recurring
**Standard answer:** Once historical order history is fully synced into Shopify, Joy's tier calculation (Amount Spent / Points earned / Number of orders) and demotion logic apply normally from that data. Tier assignment can be automated with an Amount Spent threshold from a chosen start date, or via CSV import if the historical data needs cleaning first. For ongoing tier maintenance: **Tier level control** (Advanced+) is simple inactivity-based demotion; **Tier Assessment** (Ultimate only, plus requires Joy support to enable) is full rolling-window spend/order/points re-qualification — see Q39 below for the plan-gate detail that surprised merchants this week.

## 6. Referral

### Q32: How do I check whether a referrer was actually credited their reward?
**Frequency:** ~2 sessions 🔁 recurring
**Standard answer:** Joy Admin → Customers → search the referrer's email → open their profile → check the referral/rewards activity log to see if the reward was issued or the referral is still pending (e.g. referee order not yet Paid/Fulfilled). If the referee's order is not yet paid/fulfilled it will show "Awaiting fulfilment" — not a bug, the reward fires once the trigger status is reached.

### Q33: Can I add a minimum order value, exclude specific products, or extend the 7-day cookie window for referrals?
**Frequency:** ~2 sessions 🔁 recurring
**Standard answer:** None of these are configurable today: referral completion only checks whether the referee placed **any** paid order (no minimum order value — even a $9 order completes it); there's no per-product exclusion rule for referral qualification (workaround: make the referee reward a % discount instead of a fixed amount, though this doesn't block the referrer's own reward); and the 7-day referral cookie window is fixed, not adjustable. All three are logged as feature requests.

### Q34: Does referral completion check order subtotal or total, and does the referee's discount code stay valid if their order comes in under a stated minimum?
**Frequency:** 1 session
**Standard answer:** Referral **completion** only requires a paid order — no subtotal/minimum check applies to completion itself (subtotal minimums are a points-earning concept, not a referral-completion one). The referee's discount code stays valid independently until its own expiration date regardless of order size; it isn't invalidated by not meeting a minimum.

### Q35: How is a referral invite actually sent — automated email, and to whom?
**Frequency:** 1 session
**Standard answer:** Yes, this is built-in: when a referrer enters a friend's email in the widget, a branded invite auto-sends via Joy's built-in email, Klaviyo, or Shopify Flow (merchant's choice). The email goes to the **referee** (carrying the referrer's unique link) — not to the referrer. Settings live at Joy Admin → Settings → Notifications. For Klaviyo: Referral program → Referral flow → Automated email sharing → choose the Klaviyo trigger "Joy: Referral Link Sent" and build the flow in Klaviyo.

### Q36: If a referrer earns a reward before ever creating an account, do they get an account automatically, and do the points show up later?
**Frequency:** 1 session
**Standard answer:** No automatic account is created, but the referral history and reward are still recorded against that email. Once the person eventually logs in with the same email, the recorded points appear.

## 7. Notifications

### Q37: If Klaviyo isn't connected, what actually sends Joy's loyalty emails?
**Frequency:** 1 session
**Standard answer:** Without Klaviyo, loyalty notification emails (welcome, points earned, redemption, etc.) send via Joy's own built-in default sender using the shared domain `send.avada.io` — not any third-party platform. The sender is customizable at Joy Admin → Settings → Email. Connecting Klaviyo instead lets the merchant build richer flows on Klaviyo's own triggers/properties.

### Q38: A customer received an expiration/reminder email that support can't find any record of Joy sending — did we send it?
**Frequency:** 1 session
**Standard answer:** Check Joy's own send logs first. If Joy's system logs show no record of sending it, the likely source is the merchant's own Klaviyo flow/segment (if Klaviyo is connected) rather than Joy — ask the merchant to check their own Klaviyo flows before assuming a Joy bug.

## 8. Integrations

### Q39: The Joy pixel shows "Disconnected" under Shopify Customer Events / Checkout Settings → Tracking and analytics.
**Frequency:** ~4 sessions 🆕 (KB already flags this as expected to rise around the Aug 2026 Shopify checkout/customer-events migration deadline)
**Standard answer:** First, ask the merchant to **re-authorize** the Joy app (reopen it / re-accept permissions) so Shopify grants the newly-scoped access, then re-check status. A working fix found by the team this week when re-authorizing doesn't surface a Connect option: toggle the **Referral Program** off then back on — this forces Joy to re-register its Shopify Web Pixel, since the pixel is tied to the referral feature. If that still doesn't clear it, escalate for the team to recreate the pixel connection on the backend, with a screenshot of Customer Events. Note: the pixel is primarily needed for the **Referral program's** data collection — if Referral isn't enabled, connecting the pixel is optional and doesn't block anything else (e.g. a Thank You page upgrade).

### Q40: Points/tier data isn't syncing to Klaviyo/Omnisend in real time even though the integration shows Connected.
**Frequency:** ~2 sessions 🆕
**Standard answer:** First confirm **Integrations → [Klaviyo/Omnisend]** truly shows Connected — Joy shows a warning banner on the Home page when a Klaviyo connection has silently disconnected (token revoked, app reconnected on the Klaviyo side), and a stale/missing sync is the most common cause of "0" or missing values in emails, not a content bug. For Omnisend there's a manual **Sync Again** button in the integration settings if a recent change hasn't propagated yet. If Connected status looks fine and sync is still stuck, check whether **Shopify metafield sync** was enabled long ago and got stuck — this can block the pipeline even to non-metafield destinations; the team can clear the stuck status on the backend. Disconnect/reconnect alone does not always resolve a stuck sync.

### Q41: Two different customer tags exist for members ("Joy member" vs another tag) — which is standard, and will all future members get tagged consistently?
**Frequency:** 1 session 🆕
**Standard answer:** There are two independent mechanisms that can look similar: the **auto-tag** feature at Settings → Additional Features → Auto-tag customers (recommended — customizable name, covers non-members too) and an older/manual tag. Recommend keeping the Auto-tag option and disabling the redundant one. Members created via channels other than direct storefront sign-up (e.g. imported, or created by another app) can be missed by tag sync until a re-sync is run — the team can re-sync the full customer list on request, then future members tag automatically going forward.

### Q42: How do I connect a subscription app (e.g. Recharge) so subscribers earn points/rewards?
**Frequency:** 1 session
**Standard answer:** Connect at Integrations → Subscriptions → Recharge (needs order + subscription read/write scopes, and discount + customer scopes for some flows). Connecting doesn't affect live subscribers until the program is actually launched. Subscription orders can earn points or store credit via a Place-Order-style program using a "subscription order = true/false" condition; note that **free-gift rewards do not sync to Recharge** — only free shipping, fixed, and percentage discounts sync and auto-apply to the customer's next Recharge order.

### Q43: Our review app isn't in Joy's supported list — can we still connect it, or use Shopify Flow?
**Frequency:** 1 session
**Standard answer:** Natively-connectable review apps are Judge.me, Yotpo, Air Reviews, Fera, Review Rocket, Loox, and Klaviyo Reviews. For apps not on that list (e.g. Ryviu), the workaround is a Shopify Flow-based setup: build a Flow using Joy's "Add point" action, triggered by the review app's own Flow trigger (e.g. "review published") — offer to switch to a natively-supported app as the simpler alternative if the merchant is open to it.

## 9. Pricing / Billing

### Q44: What causes the "Usage fee" line on top of the monthly plan charge?
**Frequency:** 1 session 🔁 recurring
**Standard answer:** All paid plans include a monthly free order quota (Essential 500 / Advanced 2,000 / Ultimate 7,000); once exceeded, additional orders are billed in batches of 100 at the plan's overage rate (Essential $15/100, Advanced $10/100, Ultimate $5/100). Usage counting is based on **all** Shopify orders across every sales channel (POS, marketplaces, etc.) by default, not just the online store. Ask for an invoice screenshot and confirm the order count for that cycle against Shopify Admin → Orders if the merchant disputes it.

### Q45: I upgraded plans mid-cycle and was charged the full new-plan price instead of a prorated difference — is that expected?
**Frequency:** 1 session
**Standard answer:** Yes — Shopify bills app plan upgrades as a fresh full charge for the new plan rather than a prorated top-up of the difference; this is Shopify's own billing behavior, not a Joy setting. If the merchant feels this is unfair for their specific case, collect the invoice and escalate for a refund/credit review — CS cannot approve credits directly.

### Q46: Two VIP features (Point Expiration by Earning Date, Tier Assessment) turned out to require Ultimate even though we're mid-way up the plan ladder — is that new?
**Frequency:** ~2 sessions 🆕
**Standard answer:** These are correctly Ultimate-only and this hasn't changed — the plan structure itself is unchanged, but "Expiration by earning date (FIFO)" is a relatively new feature launched Ultimate-exclusive, so merchants who haven't looked at it before are hitting the gate for the first time. Non-Ultimate alternatives: **Full (inactivity) expiration** is available on Essential+ with no upgrade needed; for VIP tier maintenance, Advanced gets **Tier level control** (simple inactivity demotion) instead of full rolling-window Tier Assessment.

### Q47: Is there a custom/tiered pricing option based on order volume instead of jumping to the next fixed plan?
**Frequency:** 1 session
**Standard answer:** No pay-as-you-go or stepped pricing exists below Enterprise — a merchant needing more order headroom must upgrade to the next fixed plan. Custom/volume pricing is only available for **Enterprise (5,000+ orders/mo)** via a sales demo at joy.so/book-demo, or the agency/partner program at joy.so/partners.

## 10. POS

### Q48: General POS malfunction — no points, tile won't load, sync errors.
**Frequency:** ~2 sessions 🆕 (as a standalone recurring topic this week)
**Standard answer:** Collect a screenshot/description, device model + OS version, Shopify POS app version, and confirm the latest **Joy Loyalty** POS extension is added (not the deprecated legacy tile). Recommend a self-fix first: update the Shopify POS app, then remove and re-add the Joy tile from scratch. If it persists, request POS staff access via `request.pos@avadagroup.com` (merchant adds this as a POS staff member and generates a PIN) and escalate with all collected info.

### Q49: A staff member can't see a customer's Joy balance/tier at POS even though the extension is installed.
**Frequency:** 1 session
**Standard answer:** Usually a Shopify app-permission gap, not a Joy bug — each POS staff account needs **Joy: Loyalty Program & Rewards** enabled under either Settings → Users and permissions (individual staff) or Settings → Users → Roles → Point of Sale permissions → Apps (role-based: "Use apps that work with Shopify POS" + "Manage POS UI extensions"). Also confirm cart has a customer assigned + products before expecting the Joy POS panel to populate — it won't interact without both.

## 11. Onsite Content / Loyalty Page

### Q50: How do I set up, customize, or reorder blocks on the loyalty page?
**Frequency:** ~3 sessions 🔁 recurring
**Standard answer:** Shopify Admin → Online Store → Themes → Customize → select the **Joy Loyalty** page template. Add a block via **Add section/Add block → Apps → Joy: [block name]**; remove via the trash icon on the block; reorder by dragging in the left panel. The order of programs **within** Ways to earn/redeem blocks is controlled separately in Joy Admin → Reward programs, not the block itself. Note: not every block has style variants — some (e.g. Ways to Redeem) only support toggle/reorder, and true custom styling needs to be escalated to the team.

### Q51: Text on the loyalty page / VIP tier benefits / widget isn't translating correctly for a non-default language.
**Frequency:** ~3 sessions 🔁 recurring
**Standard answer:** Program **names** translate under Joy Admin → Reward program → open the program → edit the name per language. For other text (e.g. VIP tier per-benefit bullet copy), use **Settings → Translations → pick language → Widget Design/Section Editor → Translations panel** to find and edit the exact string. If a translation is saved correctly on the backend but the storefront still shows the original language, suspect a third-party translation app (e.g. Translate & Adapt, Langify) overriding Joy's content — ask which translation app is in use and request app access if unclear.

### Q52: We're on an OS 1.0 theme and can't add newer Loyalty Page blocks (Hero Banner, How It Works, etc.) — what's the fix?
**Frequency:** ~2 sessions 🔁 recurring
**Standard answer:** OS 1.0 doesn't support these app blocks. The safe path: the team duplicates the live theme (live theme stays untouched), upgrades the **copy** to OS 2.0, and only publishes once the merchant confirms. Request theme/collaborator access and escalate. Recommend creating a **separate page template** for the loyalty page (not the Default template) to avoid affecting other pages that share it.

### Q53: A free-gift or VIP-perk product shows "unavailable"/"out of stock" even though it's actually in stock.
**Frequency:** 3 sessions 🆕
**Standard answer:** This surfaced repeatedly this week and traces to two causes: (1) the linked product **variant ID changed** after a Shopify-side product update, so the program still references the old, stale variant — fix by removing the old product from the program and re-adding the current version (recreating the reference); (2) a related Shopify-side change in how product status is handled, which the team has patched — removing and re-adding the product to the program resolves most remaining cases. This does **not** affect actual redemption as long as the product is genuinely in stock; escalate with the product URL and a screenshot if re-adding doesn't clear it.

## 12. Edge Cases / Bugs

### Q54: A customer shows as "Guest" in one view but "Member" in their profile, and isn't earning points consistently.
**Frequency:** 1 session
**Standard answer:** This typically happens when the customer's account was created through a channel other than the standard online-store checkout flow (e.g. imported, or created by a third-party app), which makes Joy's Member-status detection less reliable for that customer. The durable fix is setting the Place Order program's "Who to reward" to include **all customers** (not members-only), which prevents recurrence going forward; existing affected customers regain earning ability once they log in normally with the same email. For a one-off fix, the team can manually correct the specific customer's status.

### Q55: Can duplicate sign-up rewards via the same phone number but different emails be blocked?
**Frequency:** 1 session
**Standard answer:** Not currently — Joy's anti-cheat only checks browser/email/IP, not phone number, and account creation itself is controlled by Shopify, not Joy, so phone can't be enforced as a unique field. Logged as a feature request; the team can manually merge specific duplicate accounts found on request.

## 13. Other (Reporting / Analytics)

### Q56: Can I export the full customer list with points/join date/activity for accounting or program shutdown purposes?
**Frequency:** ~2 sessions 🔁 recurring
**Standard answer:** Self-serve export exists for point-earning **activity** in a date range with Customer name + Order ID + Points earned (Customers → Activities → set range → Export type = Earned). A simple "Customer + current point balance" list needs the **Export customers** button enabled first — this is a one-time backend toggle the team turns on per store on request (not self-serve by default). **Join date is not exportable** in either path today. Full historical earning/redeeming activity across all customers (not a filtered range) requires a separate backend export from the team.

### Q57: "Revenue by Joy" and "Total Joy sales" show different figures in Analytics — why?
**Frequency:** 2 sessions 🆕
**Standard answer:** No confirmed root-cause explanation was available in either chat this week — both were escalated to the internal team without a resolution captured. Treat this as an open item: collect the store URL and the date range where the discrepancy shows, and escalate rather than guessing at an explanation.
