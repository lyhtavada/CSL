## GAP detail (no equivalent in KB — recommend adding)

### Q9 — Point Calculator VAT/tax discrepancy + required variable syntax
**File:** `kb/reference/product-page.md`
**Why:** The Point Calculator section documents setup (Position/Design/Advanced) but not that the estimate is VAT-inclusive while actual points are calculated tax-excluded, nor the exact variable syntax (`{{earning_point_raw}} {{loyalty_point}}`) needed when editing the calculator's text. Confirmed via 3 chats this week, including one where a merchant broke the live value by removing the variable.

### Q17 — Discount-class switch technique + store credit can't be blocked from stacking
**File:** `kb/reference/points-advanced.md` (Discount combinations section)
**Why:** The Combinations section documents the basic toggle and Shopify's base rules, but not the technique of adding a product/collection condition to change a coupon from Order-class to Product-class for different stacking behavior, nor that Shopify's native store credit has no Combinations setting and can't be blocked from stacking with a discount code through Joy. Confirmed via 2 independent chats.

### Q19 — No auto-expire/auto-delete for used one-time codes
**File:** `kb/reference/redeeming-programs.md`
**Why:** Not documented anywhere in the cached KB. The team explicitly told a merchant "no plans to build this," which is a firmer answer than "not yet" — worth recording so agents don't leave the door open incorrectly. Include the two workarounds (filter by "Eligibility is not specific customer," or search by code prefix).

### Q20 — Reward cancelled/fails when redeemed via Cart Drawer Redeem block
**File:** `kb/reference/cart-drawer.md`
**Why:** The file documents setup and third-party slide-cart incompatibility but not this specific known limitation (a reward redeemed from the Cart Drawer block can get revoked/fail to apply). One confirmed chat this week; the practical fix (redeem from widget/loyalty page instead) is simple enough to document.

### Q22 — VIP tier changes need relaunch; entry-reward grant checkbox on relaunch
**File:** `kb/reference/vip-tiers.md`
**Why:** The file documents Launch generally and the "grant entry reward again after downgrade" setting, but not the specific relaunch-time **grant entry reward** checkbox that appears when you add/edit an entry reward on a tier that already has members — and the risk of mass-issuing it if checked carelessly. Confirmed via 2 detailed chats.

### Q24 — Store credit reward sources limited to 3 + forced full-balance use
**File:** `kb/reference/points-advanced.md` (Store credit section)
**Why:** The store credit section documents mechanics (calculation, rounding, per-tier rates) but doesn't state which **three** program types can grant it (Place Order, Milestone, Referral) or that a customer can't apply a partial amount — Shopify forces using the whole balance once selected. One detailed chat this week.

### Q33 — Widget can't display on Shopify's New Customer Account "Profile" page
**File:** `kb/reference/account-page.md` (or `kb/reference/widget.md`)
**Why:** Not documented as a known platform limitation anywhere in the cached KB, though it's directly relevant to the widget-not-showing troubleshooting flow. One confirmed chat.

### Q34 — Customers cannot edit their own birthday after first entry
**File:** `kb/reference/birthday.md`
**Why:** The file covers collection methods and format but not this rule. Confirmed explicitly by an agent in one chat this week; simple, stable fact worth adding.

### Q37 — Shopify Pixel "Connect" button reopens Joy app without completing
**File:** `kb/case/errors.md`
**Why:** Not documented anywhere — this is a new case entirely. Seen across 3 separate merchants this week (recurring pattern, not a one-off), with a consistent fix (re-authorize, then check Customer Events / App pixels status, or toggle Referral off/on).

### Q42 — Fixed notification variable (e.g. `{{birthday_rewards}}`) can't be edited/translated
**File:** `kb/reference/notifications.md`
**Why:** Not documented. One detailed chat surfaced the workaround (delete the variable and type custom text, or use the singular `{{birthday_reward}}` for value-only).
