## 1. Getting Started / Testing / Launch

### Q1: How do I test my program before launching, and does Sandbox mode keep everything off my live store? 🔁 recurring
**Frequency:** ~6 sessions
**Standard answer:** Turn on Sandbox Mode at **Joy Admin → Reward programs**. Once it's on, a **Test list** button appears at the top right — add your own email(s), Confirm, then sign in to your storefront with that whitelisted account and run through the actions you set up (place a real order, sign up, refer, redeem). Only whitelisted emails earn points while sandbox is active, so real customers are unaffected. Two important clarifications agents made this week: (1) Sandbox only controls **who earns points** — it does **not** hide the widget (once the app embed is enabled, all visitors see it) and it does **not** hold back on-site content edits, which publish live the moment you save. To preview design safely, duplicate your theme, enable the Joy embed on the duplicate, and use Shopify's Preview. (2) To confirm you're live vs. testing, check **Reward programs** for a yellow "Sandbox mode" badge — no badge means the program is live.

### Q2: Can your team just finish setting up / styling my program for me? 🔁 recurring
**Frequency:** ~9 sessions
**Standard answer:** Yes. Joy offers a free setup service where the team styles your Unified widget or loyalty page to match your store's branding, colors, and layout, and sends a preview link before anything goes live. For that, and for theme-side work, we usually need theme access via a 4-digit collaborator request code (Shopify Admin → Settings → Users → Security). Note the AI agent can guide but cannot make changes inside your store — plan/setting changes and styling are done by the human team.

### Q3: How do I check my whole setup / what's left before I go live? 🔁 recurring
**Frequency:** ~5 sessions
**Standard answer:** The team can review your earning, redeeming, VIP, notification, and widget settings and tell you what's configured vs. missing. Typical remaining pieces before launch: loyalty landing page, email notification/domain decision (Essential uses our domain; a custom sending domain needs Advanced), enabling the widget app embed, and confirming existing customers are on the right member/guest status and VIP tier. Then run a Sandbox test and switch it off to launch.

## 2. Points — Earning

### Q4: When does a customer get their points (and why is an order still "awaiting")? 🔁 recurring
**Frequency:** ~5 sessions
**Standard answer:** By default points post when the order is marked **Paid**. You can switch to **Fulfilled** under **Settings → Order → Reward by order status**. If the trigger is Fulfilled, points stay in "awaiting" until the order is fulfilled. Points can lag up to ~an hour because they depend on a Shopify webhook. If an order is well past the trigger status and still hasn't credited, share the customer email + order number so the team can check the activity log.

### Q5: A customer bought but didn't get points — why? 🔁 recurring
**Frequency:** ~8 sessions
**Standard answer:** Most common causes seen this week: (1) **Guest at checkout** — if your Place-order program is set to "All members," an order placed before the customer logged in/joined won't earn (fix: award to "All customers," or the team can manually credit that order). (2) **Program start date** — if the earning rule's start date is after the order date (sometimes changed accidentally), older orders won't auto-credit; the team can manually add and check whether others were affected. (3) **Recharge/subscription orders** — Shopify changed the subscription webhook property (`subscription_contract` → `subscription_contract_checkout_one`); set the purchase-location condition to **All channels** so subscription orders earn again; missed past orders can be credited manually. Always collect email + order number and confirm member-vs-guest before escalating.

### Q6: Can I add points for customers' past/previous orders? 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** Joy doesn't automatically backfill points for orders placed before a customer joined; points accrue on new orders going forward. For a bulk one-off, use **Customers → Import → "Add points to customer balances"** with the sample CSV. For specific past orders credited by actual amount, send the customer emails + order amounts and the team can do a one-off manual adjustment.

### Q7: How do points work across currencies / Shopify Markets? 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** Joy calculates on the **presentment currency** the customer actually pays in, converting from your primary currency using Shopify's exchange rate by default. If you don't want conversion, open the Place-order rule and set a **fixed point ratio per currency**. On Advanced you can enable **Apply different rates by currency** (Place order → Reward settings) to set independent rates per market (e.g. 1pt/1 MXN and 10pt/$1 USD) — set them proportional to the exchange rate so reward value stays consistent.

### Q8: Can I run a limited-time bonus rule (e.g. 1000 extra points over €100 until a date)? 🆕 new
**Frequency:** ~1 session
**Standard answer:** Yes, add it as an extra rule on the Place order program: **Reward programs → Place order → Add rule**, set the method (e.g. "One-time at threshold": 1000 points when order ≥ €100), then set the rule's **Schedule (Start/End date)** so it auto-disables at the end. Double-check the threshold value and end date after saving (agents caught a €99-vs-€100 and a 13/07-vs-12/07 mismatch this week).

### Q9: Sign-up bonus wasn't awarded even though the customer bought / is tagged member. 🔁 recurring
**Frequency:** ~4 sessions
**Standard answer:** Place-order points and the Sign-up reward are **independent** — a purchase alone doesn't trigger the sign-up bonus. The sign-up reward fires only when the customer actually **logs in on the storefront with the Joy widget active**, joins via the widget popup, or is identified at POS. Being tagged `joy_tag_member` means they're a member but not that the sign-up reward fired. It's granted once per customer and will trigger next time they log in while the widget is active. For accounts created before the sign-up program existed (or before launch), run **Settings → Pre-launch → Sign Up Account → Sync**; for one-off edge cases (e.g. logged in via Shop app and got redirected before the widget loaded), the team can manually add the points.

### Q10: Can I collect gender / age at sign-up? 🆕 new
**Frequency:** ~1 session
**Standard answer:** No — Joy's registration form supports **birthday** only (via the register form or Shopify Customer Metafields); neither Joy nor native Shopify collects gender or age at the moment of sign-up. To capture those, use a third-party custom-registration-fields app that syncs to Shopify customer profiles. If the goal is rewards, birthday is the built-in field and can drive automatic birthday rewards.

### Q11: How do I limit review points (frequency / verified buyers only)? 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** For Joy's native Write-a-Review program, set a **Review limit per customer** under the program's **Fraud prevention** section. For **Judge.me**, there's an **"Only reward verified buyer reviews"** toggle — Joy reads the `verified_purchase` field from Judge.me's payload, so if that's marked "not_yet" (email/verification pending or webhook delay) points are skipped; toggling the option off awards all published reviews (team can retroactively trigger skipped ones). For **Loox / Air Reviews** there's no direct rule, so the review reward and its limit are set up via **Shopify Flow**. Air Reviews connects at **Joy Admin → Integration → Air Reviews** with App ID + Secret key.

### Q12: How does cashback / store credit work? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:** Cashback runs through **Store Credit** — a native Shopify balance (real $, not points) applied automatically at checkout with no coupon. Enable Store Credit in **Shopify Settings → Customer Account** first, then in Joy pick **Store Credit** as the reward type in an earning program (a one-time Grant Access authorization covers all programs) and set your rate (e.g. 5% of order value). Store credit is calculated on the order **subtotal only** (shipping and tax excluded). Display in the customer's account depends on Shopify's store-credit UI — if it doesn't show even when the customer has a balance, that's a Shopify-side display matter.

## 3. Redemption

### Q13: Can customers redeem a variable/partial amount (e.g. 200 pts for £2, not just 100 pts for £1)? 🔁 recurring
**Frequency:** ~2 sessions
**Standard answer:** Yes. After the customer clicks **Claim** on a redeem option, they can adjust how many points to redeem — no change needed on your end. To set a maximum per redemption, open the Redeeming program → **Redeem value** → set **Maximum points per redemption**. Note: fixed-discount mode has no per-redemption cap; the min-cart-value and dynamic-discount options require **Essential+**.

### Q14: Two redeemed rewards / coupons won't stack at checkout ("conditions not valid" / can't combine). 🔁 recurring
**Frequency:** ~4 sessions
**Standard answer:** Shopify combines discounts by **type** (Order / Product / Shipping), not by which app made them, and only one **Product** discount can apply per item. Enable the matching combination under **Reward programs → Redeem programs → [program] → Discount combinations** for each coupon. If two coupons are the same discount category they won't stack; only different types (or different products/collections) combine. If everything's enabled and it still fails, re-test in an incognito tab (cache) before escalating. Also verify the coupon's own conditions (min purchase, excluded collections) — a "valid but not applicable" error usually means one of those conditions isn't met.

### Q15: Redeem screen goes blank / no discount code shown. 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** First rule out a display glitch: open the store in incognito / clear cache. If the code is being created but never shown, and the store is on a **legacy widget version**, this is a known limitation of the old codebase that's no longer maintained — the fix is upgrading to the **Unified widget** (data carries over untouched, team can set it up and preview before going live). For the newer widget, sometimes the cause is a white-on-white text color; the team can correct the text color via settings/CSS.

### Q16: How do I set up a "redeem points for a free product / free gift"? 🔁 recurring
**Frequency:** ~4 sessions
**Standard answer:** Use **Reward programs → Redeeming programs → Free gift**. The gift product must be **published and active** on the Online Store channel to be redeemable; it does **not** need to be visible — hide it by using a product template with the "Add to Cart" button removed (not by keeping it in draft). Redemption works by generating a discount code, so inventory decreases normally per order — monitor stock. On the Unified widget/storefront the free gift auto-adds to cart when redeemed; inside the Shopify New Customer Accounts / Loyalty Hub it only generates a copyable code (Shopify doesn't allow auto-add or auto-apply there).

### Q17: Can I control the display order of redeemable rewards? 🆕 new
**Frequency:** ~1 session
**Standard answer:** Reorder programs by dragging them in **Reward programs → Redeem programs** (grab the ≡ drag handle). If they won't drag on the widget itself, the order is controlled per widget version: for the Classic widget go to **On-site content → Classic widget → Setup → Display → Widget content blocks → Ways to Redeem** and drag there. Team can help if the handle isn't responding.

### Q18: Do redeemed free-gift coupons apply to recurring subscription orders (Loop / Recharge)? 🆕 new
**Frequency:** ~1 session
**Standard answer:** No — Joy's Free Gift redemption currently supports **one-time orders only**. Once the generated code is used (or when applied to a Loop/Recharge recurring order) it returns "Invalid code," because a free-gift code becomes invalid after first use and isn't designed for recurring contracts. Percentage/amount discount codes behave differently. Logged as a feature request; no native workaround for auto-applying a free gift to the next subscription delivery today.

### Q19: What happens to redeemed points if the earning order is later refunded? 🆕 new
**Frequency:** ~1 session
**Standard answer:** If "Auto-revoke points for cancelled/refunded orders" is enabled, Joy deducts the earned points on refund. If those points were already redeemed, the balance can go **negative** — Joy allows negative balances (only the system creates them; the customer earns their way back). You **cannot** manually push a balance below zero from the admin (this is intentional — manual adjust is a goodwill/correction tool, not a penalty). For corrections, set the balance to zero or a positive value; for genuine negative-balance scenarios, escalate for a case-by-case workaround.

## 4. VIP Tiers & Milestones

### Q20: I reset customers' points but their VIP tier didn't drop — why? 🆕 new
**Frequency:** ~4 sessions
**Standard answer:** VIP tiers on the **Points earned** rule are calculated on **lifetime points earned**, not the current balance. So resetting or expiring balances doesn't move the tier — the customer keeps the tier their historical earnings qualified for. If you want tiers to reflect current standing, the team can recalculate VIP tier points to match, or you can set the tier calculation to **Amount spent** (cumulative spend isn't reduced by redemptions). To keep redemptions from demoting customers, use Amount spent or an Exclusive tier. Recalculations can move some customers down (they keep any rewards already granted).

### Q21: How do I set per-tier earning rates, and what happens to a first-order customer with no tier yet? 🔁 recurring
**Frequency:** ~2 sessions
**Standard answer:** Configure per-tier rates on the Place-order program (the Bonus Points perk accepts **whole multipliers only** — 2×, 3×; fractional rates need a Shopify Flow bridge). New customers are auto-placed in the lowest tier (e.g. Bronze at $0 threshold) as soon as they become a member, so their first order already earns at the entry-tier rate.

### Q22: Can I do a quarterly VIP tier reset? 🆕 new
**Frequency:** ~1 session
**Standard answer:** A native **quarterly** reset isn't supported today (reset options don't include quarterly; logged as feature research). For a "gift-with-purchase every quarter" goal, the recommended approach is a **Milestone program** (tracks cumulative spend toward a threshold like AUD $300, quarterly reset keeps it recurring, the qualifying order can be tagged via Shopify Flow so the warehouse packs the gift — never added to cart, never a discount code) plus a cart progress nudge ("$40 to go") shown on the account page. Order/customer tagging for "the order that crosses the threshold" is built with Shopify Flow.

### Q23: Do milestones count from the program start date or lifetime history? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:** It depends on the milestone type. **Amount-spent** and **Points-earned** milestones only count orders on/after the program start date (everyone starts fresh). **Order-count** milestones count the customer's **lifetime** order total, so a customer with several past orders can trigger the 2/3/4/6-order milestones all at once right after launch. There's no native option to restrict order-count milestones to post-launch orders (logged as feature request). Milestone recalculation on large stores can take several hours to 12+ hours; the "retroactive" checkbox only looks back to the start date you set, not all-time.

### Q24: Customer didn't receive the tier entry reward. 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** Entry rewards are one-time on tier reach and are set under **Membership → VIP Tiers → [tier] → Entry reward** (NOT under Privileges/Perks) — re-**Launch** the tier after editing. Common causes of "not received": the notification/reward was enabled **after** the customer already reached the tier (not sent retroactively), or a re-calculation was run without the "Grant entry reward" option checked. The team can re-grant entry rewards for named customers (and choose whether to notify only those or everyone). Note the customer profile in admin doesn't yet show which milestones/perks a customer can claim (feature request).

### Q25: Can a tier perk trigger only after a customer accumulates X points, or a fixed-$ discount apply at order level (not per item)? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:** A perk that triggers on **accumulated points** isn't supported — perks apply as ongoing benefits (free shipping, % discount, fixed amount) while the customer holds the tier. Most high-AOV stores use free shipping or a % discount. Important Shopify behavior: a **fixed-amount** automatic discount restricted to specific products applies **per eligible item**, not once per order (e.g. $10 off × 7 items = $70) — this is Shopify's native discount engine, not a Joy bug; team is checking workarounds.

## 5. Referral

### Q26: How do I set up referrals, and is it on the free plan? 🔁 recurring
**Frequency:** ~6 sessions
**Standard answer:** Set up at **Reward programs → Referrals** — define the referee's reward (e.g. 15% off first order) and the referrer's reward (e.g. 200 points), plus sharing channels. Basic referrals work on **all plans including Starter/Free**, but Free caps how many referral orders can be rewarded (Starter 30 / Essential 100 / Advanced+ unlimited), and advanced features (customer/order tagging) need a paid plan. Remember to actually **Save** the referrer reward (agents saw several left blank). If using Automated email sharing, also enable **Settings → Notifications → Referrals**.

### Q27: Why hasn't the referrer/referee gotten their reward or coupon? 🔁 recurring
**Frequency:** ~4 sessions
**Standard answer:** The referrer is rewarded only **after the referee places an order using the referral link/code** and it reaches the trigger status (Paid or Fulfilled, per **Referrals → Program settings**). If set to Fulfilled, it shows "Awaiting fulfilment" until shipped — normal, not a bug. If the referral code hasn't been used at all, no reward fires yet. The referee sees their discount code in the referral notification but must **log into the store** for it to activate. A shared **link** can be opened by anyone; only the **invite-by-email** option restricts the code to the specified referee.

### Q28: Can I customize the referral link (custom domain) or edit/disable the referral popup? 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** Referral links can use your **custom domain** instead of the myshopify URL (each customer gets a unique link like `yourdomain.com?referralCode=xxxx`); the team can switch this. To edit or disable the referral popup: **On-site content → Widget → Referral** → modify design or choose "Do not show refer." Popup frequency controls: **Auto-show frequency** = times it auto-appears per visit (max 10); **Display frequency** = wait time before it reappears after being closed (30 min–30 days).

### Q29: Can I show the referrer's name / referee's reward as a variable in the invite email? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:** The "Referral Link Sent" email is the invitation to the referee. The referrer-name variable is available in that template (Joy provides it in the editor). In **Klaviyo**, use `{{ event.referrer_name }}`. To surface the friend's reward on the widget/loyalty page, edit the Referral description under **On-site content → Widget → Content & Translations → Referral**.

## 6. Notifications / Email

### Q30: How do I email customers when they've earned *enough* points to redeem (not after redemption)? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:** Joy launched a **Shopify Flow trigger** for exactly this: "Customer has enough points for reward," which fires when a customer accumulates enough to redeem (returns program name, minimum points, and customer details). Build a Flow: pick this Joy trigger → connect an email-send action. This is different from the built-in "Reward Redemption" coupon email, which is sent **after** a customer redeems (enable at **Notifications → Customer notifications → Reward Redemption**).

### Q31: Is there a native monthly "here are your points, come redeem" reminder email? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:** Not built in. A personalized points-balance email needs a marketing app — Joy syncs **points balance, VIP tier, member status, referral link, birthday** to Klaviyo/Omnisend in real time, so you build a segment (e.g. members with balance > 0) and send from there. Shopify's default email can't pull loyalty data. As alternatives inside Joy: the **Reward reminder** popup (shows point balance on-site) and Joy email templates support Liquid variables like `{{ points_balance }}`, `{{ earning_points }}`, `{{ coupon_code }}`, `{{ coupon_expiry_date }}` (these work only inside Joy's own emails). Logged as a feature request for a native balance-reminder notification.

### Q32: Coupon-expiration reminder email — is there a Klaviyo trigger? 🔁 recurring
**Frequency:** ~2 sessions
**Standard answer:** Joy now supports a **Coupon Expiration Reminder email** (customizable timing, e.g. 3/5/7 days before expiry) inside Notifications, and a Klaviyo **"unused coupon reminders"** trigger (enable it in the Klaviyo integration settings). Joy also syncs `coupon_expiry_date` to Klaviyo so you can build a date-based flow. The coupon/reward *name* isn't yet included as a property on that trigger (feature request). For reward-expiry specifically, you can also set Point expiration in Joy + notify via Shopify Flow.

### Q33: VIP tier / other notification email not received by a customer. 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** First check the email was enabled **before** the customer reached the tier — it's not sent retroactively. Have the customer search the sender address in inbox + spam. If the system shows "sent" but the customer never got it, escalate (note: accessible activity logs only go back ~3 months, so older events may not be verifiable). Confirm the VIP Tier Achieved template is on at **Notifications → VIP tier**.

### Q34: Can I personalize emails with per-customer data (e.g. next product in a subscription)? 🆕 new
**Frequency:** ~1 session
**Standard answer:** Joy email templates support standard variables (points balance, shop name, order details) but **not** arbitrary per-customer data like "next puzzle in the sequence." Joy also doesn't send subscription-renewal reminder emails — for those, use the subscription app's own tooling (Recharge/Loop) or a marketing app.

## 7. POS

### Q35: Can I rename the Joy POS tile / block? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:** No — the POS tile title ("Joy Loyalty") is the default and applies globally across the store, so it can't be renamed to a custom brand name. Add the tile via **help.joy.so/pos/add-joy-to-shopify-pos**. At POS, points are awarded automatically once an order completes (no need to tap the tile); tapping the tile is only for previewing a balance, redeeming a reward, or completing a Custom Trigger.

### Q36: Can I award points for buying across specific POS locations? 🆕 new
**Frequency:** ~1 session
**Standard answer:** No — Joy doesn't currently support automatic tracking/awarding based on purchases across specific POS locations, so there's no native way to award e.g. "100 points if the customer buys in all 3 stores." Logged as a feature request. A standard Place-order program works across all channels (POS + online).

### Q37: POS-created / older customers not getting the sign-up bonus. 🔁 recurring
**Frequency:** ~1 session
**Standard answer:** Joy updated its POS sign-up logic: when you select a customer in Shopify POS and open the Joy POS extension, any pending sign-up points are now awarded automatically. For returning customers who missed it, just add them to the cart and open the Joy POS extension to sync.

## 8. Integrations

### Q38: Which marketing/review apps does Joy integrate with (Spoks / Seguno / Klaviyo)? 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** Supported email/SMS sync integrations are **Klaviyo, Omnisend, Mailchimp, Drip, Sendlane, PushOwl** (they receive points, VIP tier, member status, referral link, birthday). Apps not on that list (e.g. **Spoks**, **Seguno**) have no native sync — being a Shopify app on both sides doesn't guarantee it. New integration asks are logged as feature requests (no committed timeline).

### Q39: How does Instagram earning work, and can I run two IG accounts? 🔁 recurring
**Frequency:** ~2 sessions
**Standard answer:** Instagram earning (comments, story replies, mentions, live comments) is **Advanced/Ultimate**. Connect one Instagram Business/Creator account at **Joy Admin → Integrations → Instagram** (one connection covers all IG programs); customers link their IG username in the widget. You **cannot** run two separate "Follow on Instagram" rewards for two accounts — the backend treats "Instagram Follow" as one global action, so once a customer completes the first, the second won't award. Workaround: a Custom Program / Submit Form. Also verify the follow link points to *your* IG profile (Reward programs → Follow on Instagram) — it defaults to a placeholder.

### Q40: How do I approve Google reviews / get notified of new review submissions? 🔁 recurring
**Frequency:** ~1 session
**Standard answer:** Approve pending Google review submissions at **Shopify Admin → Customers → [customer] → Joy panel → Activities → Google review submissions**; approving credits the points. There's **no** automatic email/Flow notification when a review is submitted (feature gap) — check that section periodically, or use Google Business Profile's own review notifications.

### Q41: Can Shopify Forms subscribers auto-become loyalty members with points? 🆕 new
**Frequency:** ~1 session
**Standard answer:** No. Just filling a Shopify Forms email-subscribe does **not** make someone a Joy member or award sign-up points. Joy membership/sign-up is triggered only by: logging into a Shopify account on the storefront with the widget active, joining via the Joy widget popup, or being identified at POS. The Flow/Forms integration is mainly for collecting data like birthday. On the base plan the manual-assign option isn't available; New Customer Accounts (email code, no password) lowers the sign-up friction.

## 9. Migration / Export / Import

### Q42: How do I migrate from another loyalty app (Smile, Square, AllInOne, etc.)? 🔁 recurring
**Frequency:** ~4 sessions
**Standard answer:** Migration is available on **Essential+** (not Starter). Self-serve import (**Customers → Import**) covers **points + birthdays** via CSV (customers must already exist in Shopify, matched by email; birthday column named `Birthday(MM/DD)`, format `03/03`). Bringing over more (VIP tier, customer status, phone/name) requires **assisted migration** — the team enables the Migration page and imports the file. Apps without a dedicated mapping (Square for Retail, AllInOne on PrestaShop) still migrate via a generic CSV. If a large import (e.g. 18k customers) appears stuck "processing," the team checks the backend.

### Q43: How do I export my customers / points / VIP tiers? 🔁 recurring
**Frequency:** ~6 sessions
**Standard answer:** The **Export** button under **Customers → More actions** must be enabled by the team first (that's why some stores only see Import). Once enabled, export includes name, email, phone, points, VIP tier, birthday, and status; you choose fields and date range. Export **by** individual tier isn't a one-click filter (you get all customers with their tier in one file). The customer **name** field and grouping-by-tier were noted as not fully supported/one-click this week (partly logged as feedback). For a plain Shopify customer export (no loyalty data), you can export directly from Shopify.

### Q44: Can I reset points / remove all coupons / re-award points at relaunch? 🆕 new
**Frequency:** ~3 sessions
**Standard answer:** Yes, the team handles these bulk actions. They can reset all customers' points to 0, and remove existing coupons — clarifying first whether to **revoke** (deactivate + refund the points) or just **remove** coupons **without** refunding points. They can also re-award fixed points by old VIP tier (e.g. give former tier members a one-time bonus). VIP program can be turned off by you anytime at **Membership → VIP tier program → Deactivate**. Large coupon-deactivation batches may need dev processing and can take hours. Note bulk point/coupon changes show in the customer's activity history and on the widget.

### Q45: How do I run a silent retroactive import without spamming customers? 🆕 new
**Frequency:** ~1 session
**Standard answer:** A retroactive sync **can** fire emails if the notifications are enabled, so before importing turn **OFF** the "Points earned" and "VIP tier" notifications at **Notifications**; then re-enable them after. Points for past orders use the earning rules configured at sync time and apply each customer's **current tier multiplier** — if you want the base rate for everyone, temporarily set all members to one tier / disable per-tier rates, then restore. Tier **entry rewards** are only granted for the tier a customer is assigned to (not every tier passed through), and can be kept off during import. Requirements: both the Rewards Program and Place Order rule must be enabled, and the Place Order start date must cover the historical orders. The import **can't** be tested on a single customer and **can't** be reversed from your end — the team can run it for you.

## 10. Widget / Loyalty Page / On-site Content

### Q46: My widget/dashboard shows "App embed 0 Active" or "Inactive" even though it's enabled. 🔁 recurring
**Frequency:** ~5 sessions
**Standard answer:** First confirm the embed is on: **Online Store → Themes → Customize → App embeds → "Joy Loyalty - Widget" → Save**, then hard-refresh the Joy dashboard (Cmd/Ctrl+Shift+R). If it still shows 0 Active / Inactive despite being enabled and displaying on the storefront, it's a **known dashboard display glitch** — the store is working normally; the team's dev fix corrects the status. A quick self-serve retry: toggle the embed off → Save → on → Save → reload the app. (The App **Pixel** under Checkout → Tracking is separate and only relates to the Referral program; it auto-connects when Referral is on.)

### Q47: Widget text / program name / custom point label won't save or doesn't show on the storefront. 🔁 recurring
**Frequency:** ~6 sessions
**Standard answer:** For the program name and header/welcome text, edit under **On-site content → Widget → Widget design → Unified widget → Setup → Content & Translations** (Classic: Content & Translation). The top "Loyalty Program" header is editable there (earlier it was hardcoded — now updatable). For "2000pt"-style labels, use **Settings → General → Custom point label** (toggle on, position after the number). If it saves but doesn't reflect live, hard-refresh in incognito to rule out cache; if it still reverts, escalate (a couple of genuine save bugs were confirmed and fixed this week). Program/earning-rule names shown on the widget are pulled from each program's name (edit them in Reward programs) and from Translations.

### Q48: Widget/launcher spacing, icons, colors, or CSS customization (and centering / adjusting spacing). 🔁 recurring
**Frequency:** ~9 sessions
**Standard answer:** Many visual tweaks are self-serve: launcher position at **On-site content → Widget → Setup → Launcher → Alignment** (bottom-left/right + offset); text colors under **Setup → Text theme colors**; earning-block icons via **On-site content → Loyalty page → Ways to earn → upload custom icon**; header image under **Setup → Header → Header background image** (8:5, 800×500, under 200KB or the upload silently fails). Pixel-level offset, centering icons/titles in "How it works"/"Ways to earn," heading-3 color, and gap adjustments are **CSS-only** — the team adds custom CSS to the theme (stored in `avada-custom.liquid`, which you can reuse on other themes). Custom CSS field also lives in **Unified widget → Setup → Settings → Custom CSS**.

### Q49: Can I hide the floating launcher icon but keep the program running? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:** Yes. **On-site content → Widget → Setup → Launcher** → toggle **"Hide widget button" On** (choose "on all devices" or per device). The loyalty program keeps working normally; customers can still access it via a loyalty page, blocks, or a deeplink. To restrict where the widget shows, use the page-restriction / Advanced → Display settings.

### Q50: Can I open the widget from a menu link / control who sees it (visitors vs. logged-in)? 🔁 recurring
**Frequency:** ~2 sessions
**Standard answer:** Yes — set a **deeplink** at **Settings → Developers → Deeplink** (e.g. `#joy-home`) and attach it to a menu item like "Rewards" so clicking opens the widget (the app embed must be enabled for it to fire). To control visibility, the **On-site content → Unified widget → Display** section sets whether the widget shows to all visitors or only logged-in customers; the team can flip "Display after login."

### Q51: Widget language reverted / not fully translated (Translate & Adapt, Lang Shop, etc.). 🔁 recurring
**Frequency:** ~4 sessions
**Standard answer:** Set the default language and translate strings at **Settings → Translations**; you can translate the widget, loyalty page, account page, checkout, and wallet passes (checkout can't auto-detect by IP — one default language via Theme Editor). Changing the default language / editing translations requires **Essential+**. If a widget that was translated reverts to English/mixed languages, it's usually a **third-party translation app** (Translate & Adapt, Lang Shop) overwriting Joy's content — Joy's language detection only syncs with **Shopify Translate & Adapt**, so with other translation apps or per-domain setups switch detection to **Browser language** or **Customer IP** (Settings → Translations). Also, empty strings after a Unified-widget upgrade can occur for brand-new fields that didn't exist in the old version; the team can reset translations to defaults to populate them.

### Q52: How do I set up / find the loyalty page (and link to it)? 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** Build it in **Online Store → Themes → Customize → [Joy Loyalty page template] → Add section → Apps → Joy blocks** (Ways to earn, Ways to redeem, VIP Tier benefits, Referral, How it works, Hero Banner, FAQs), or via **On-site content → Loyalty page**. The loyalty page is **Essential+**. It lives as a real Shopify page under **Online Store → Pages** — open it to get the public URL you can link from menus/footer. Using the widget **and** the loyalty page together is fine and recommended.

### Q53: How do customers see their points on the account page / Loyalty Hub? 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** The **Loyalty Hub** on the Shopify Customer Account page (which powers the points balance there) is **Advanced/Ultimate** only. On Essential/lower, that section won't appear under **On-site content → Account page** — customers see and redeem points via the widget, loyalty blocks, or a loyalty page instead. The Loyalty Hub supports both Legacy and New Customer Accounts. Inside New Customer Accounts, Joy can only generate a copyable code (no auto-add-to-cart / auto-apply — Shopify limitation).

### Q54: Thank-you / order-status page says "Joy isn't embedded." 🔁 recurring
**Frequency:** ~2 sessions
**Standard answer:** For the post-purchase Thank-you page, add Joy's **Sign-Up block** (**On-site content → Thank you page → Sign Up block → Setup → enable → theme editor → Add App Block → "Joy: Sign-Up Block" → Save**) and/or **Reward Celebration** / **Referral block** (Referral block needs **Advanced+**). If Shopify's warning is really about the widget embed, that's the App-embed toggle (see Q46). The Order Status page is a separate Shopify surface from the post-purchase Thank-you page.

### Q55: Can I show a homepage popup promoting sign-up / a specific offer? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:** Joy's **Visit website popup** (**On-site content → Popups → Visit website popup**, "Before Sign-In" state) can show a message to non-logged-in visitors, but it's oriented around the visit-to-earn reward rather than a free-form "10% off when you sign up" promo, which isn't natively supported. Alternatives: an **Instant Pop-up** (auto-opens the widget on landing), a site banner, or the **Reward reminder** popup. Note: in the Unified widget the Visit-website reward flow was being fixed this week — customers claim it in the widget after login instead of via the old standalone popup.

## 11. Analytics

### Q56: Why does "Revenue by Joy" show $0 even with thousands of members? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:** "Revenue by Joy" only counts orders where a **Joy-issued discount code was actually applied at checkout**. Members earning points but not yet redeeming = $0, which is expected, not a tracking bug. Check **Analytics** / **Customers → activity log** for redemptions. If redemption rate is near 0%, the usual causes are visibility/motivation gaps: no loyalty page or product-page point display, notifications off, first reward priced too high, or the widget hidden. Recommended fixes: add a low first reward (e.g. $5 at 150–200 pts), turn on social earning actions, add the **Point calculator** on product pages, and enable **Redeem in cart drawer** (Advanced+).

### Q57: Can I get a custom report / see which customers visited my store? 🔁 recurring
**Frequency:** ~2 sessions
**Standard answer:** The Analytics dashboard covers loyalty members, revenue by Joy, redemption rate, points earned/redeemed, filterable by date. Joy does **not** track store visitors/visits — only loyalty activities. For a custom CSV (customer email, earning/redeeming points, date range) the team can export customer activities; the customer **name** field isn't yet supported in that export. Bulk point updates for top customers are done via **Customers → Import → "Add points to customer balances."**

## 12. Pricing / Billing

### Q58: What does Joy cost / which plan do I need / any discount? 🔁 recurring
**Frequency:** ~5 sessions
**Standard answer:** Base fee + free order quota + per-100 overage: **Starter $0** (250 free orders, no overage); **Essential $29/mo** (500 free, $15/100); **Advanced $129/mo** (2,000 free, $10/100); **Ultimate $499/mo** (7,000 free, $5/100). Monthly order usage counts **all** store orders in the billing cycle, member or not. Free trials: 14 days Essential/Advanced, 30 days Ultimate; Starter free forever; one trial per store; 30-day refund after upgrade. For low-volume stores (under ~250 orders/mo) Starter is fine. Promotions run periodically (e.g. up to 50% off Essential / 30% off Advanced first 3 cycles, or a $50 credit/discount for an approved G2 review); custom per-tier pricing isn't something support can adjust directly — it's escalated. "Pro" is the old name for Essential.

### Q59: "Transaction limit" warning — I want unlimited transactions. 🔁 recurring
**Frequency:** ~6 sessions
**Standard answer:** A **transaction** in Joy is any point activity (earning or redeeming) on the widget — it is **not** a Shopify order or a pricing/plan matter. When a store hits the limit (e.g. "200 transactions"), reward programs get disabled. This is **not** resolved by upgrading: collect the store URL and have the team enable **unlimited transactions** for free (works on any plan, including Free). After enabling, the merchant refreshes the dashboard to clear the warning; if the app embed needs re-activating, toggle it on under Online Store → Themes.

### Q60: Can I pause my subscription instead of canceling? 🆕 new
**Frequency:** ~1 session
**Standard answer:** Yes — **downgrade to the Free (Starter) plan** at **Settings → Subscription → View plans → Starter**. Your setup, points, and customer data stay intact and you can upgrade again anytime. Alternatively keep the plan but set programs to Sandbox + notifications off. One billing note: if the current cycle already started, Shopify still charges the full cycle on your next invoice even after downgrade (standard Shopify behavior); if unused days remain, ask support to review for a possible refund. Billing timing/invoice due dates are managed by Shopify (Shopify Admin → Billing), not stored in Joy.

### Q61: When is my invoice / how is monthly order usage calculated? 🔁 recurring
**Frequency:** ~2 sessions
**Standard answer:** App billing is handled by Shopify and included in your Shopify subscription invoice, so Joy doesn't store the exact due date — check **Shopify Admin → Billing**. Monthly order usage counts all orders processed in your one-month billing cycle regardless of loyalty membership; exceeding the free quota adds the per-100 overage for your plan.

## 13. Members / Guests / Segments / Edge Cases

### Q62: How do I tell members from guests, and can I convert guests to members? 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** Only **members** can be assigned VIP tiers and earn/redeem via the account model. Customers who logged in / joined via the widget are members; guests just left an email at checkout. The team can mass-convert guests to members (recommended especially for guests holding a points balance) — but warn that some "guests" only dropped an email and may not be active shoppers. With New Customer Accounts, anyone whose email is saved in Shopify counts as a formal customer and can become a member. The `joy_tag_member` tag is added going forward when the sync feature is on; it does **not** backfill existing members — use the **Auto-tag customers → Re-sync** feature to tag all existing members.

### Q63: How do I exclude wholesale / B2B customers from the loyalty program? 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** Build a Shopify customer **segment** (e.g. tag contains "Wholesale"/"B2B"), then in **Settings → Loyalty Program → Pre-launch → Exclude segments** select it. Excluded customers won't earn/redeem and the widget is hidden for them (Exclude segments is **Advanced+**). Excluding doesn't auto-zero existing points — adjust to 0 manually if needed. Note this week: "Left program" / excluded customers could still see Redeem/VIP blocks on the **account page** (blocks didn't respect the status like the widget did) — this was flagged and fixed for Profile-page blocks; verify on your store.

### Q64: How do I disable / shorten the "JOY-" discount tag on customer profiles? 🆕 new
**Frequency:** ~1 session
**Standard answer:** The `JOY-XXXX` tag is added automatically to track which customer used which coupon and prevent reuse; it's not configurable from app settings. There's no self-serve toggle to disable or shorten it — logged as a feature request (team exploring a hide/"show more" or shortened format). Joy doesn't otherwise auto-tag customers with discount tags, so if other tags appear, check Shopify Flow or another app.

### Q65: 404 / customer profile won't open / customer can't see or redeem points. 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:** For 404s or a customer profile that errors when opened, it's usually a transient backend glitch the team can fix quickly (refresh after). For a specific customer who can view points as a guest but the widget disappears when logged in (reverse of expected), that's an account-level issue to escalate with the email — ask the customer to try incognito / another browser and, if possible, capture a jam.dev recording of the login. Widget-broken/blank-buttons cases are often a white text color blending into the background (team fixes via settings/CSS).

### Q66: Where do customers enter/edit their birthday, and what format? 🔁 recurring
**Frequency:** ~2 sessions
**Standard answer:** Customers can update their birthday from their loyalty profile on the storefront (account/loyalty page). Joy only accepts the format set in **Reward programs → Celebrate a birthday → Date format** (e.g. DD MM YYYY) — confirm that field matches what customers expect. The team can also manually activate/issue a birthday coupon for a specific customer; birthday-reward emails go out if the notification is enabled. On the Unified widget you can set a "No reward" option to prevent guests/entry-tier members from seeing a "$0" birthday code.

### Q67: My theme/site broke — is it Joy's scripts? 🆕 new
**Frequency:** ~1 session
**Standard answer:** Share a screenshot of the JS error so the team can investigate. In practice this week the reported "Identifier 'n' has already been declared" conflict traced back to a different auto-updated app, not Joy — Joy's scripts were just affected downstream. For genuine first-load speed concerns, set the widget font to **Inherit** (removes the Google Fonts request), use page restriction to limit where it loads, and consider the Unified widget (lazy-loaded, smaller first-paint bundle than Classic). The "upgrade to OS 2.0 / older API" banner is a default Shopify warning and can be safely dismissed.
