## 1. Getting Started, Setup & Launch

### Q1: How do I activate Joy on my storefront?
**Frequency:** ~14 sessions 🔁 recurring

**Standard answer:**
There are two pieces, and the widget is the essential one:

1. **Enable the widget embed** — Shopify Admin → **Online Store → Themes → Customize → App embeds** → toggle on **Joy Loyalty - Widget** → **Save**. Until this is on, the widget won't show, and the sign-up reward can't trigger either.
2. **Add the loyalty page (optional, paid plans)** — In the Theme Editor, select the **Joy Loyalty** page template from the page dropdown, then **Add section / Add block → Apps** and add the Joy blocks you want (Ways to earn, Ways to redeem, VIP Tier benefits, Referral block, FAQs).

If the Joy blocks don't appear under Apps, it's almost always one of two things: you're editing a generic page template instead of the **Joy Loyalty** template, or the app embed isn't saved. If the **Joy Loyalty** template isn't in the dropdown at all, your plan doesn't include the loyalty page — see Q37.

### Q2: Can your team set up and style my widget / loyalty page for me?
**Frequency:** ~18 sessions 🔁 recurring

**Standard answer:**
Yes — we offer a free setup service. Our team styles your loyalty widget and/or loyalty page to match your store's branding, colours and layout, and sends you a preview before anything goes live. You don't need to do anything except review it.

To get started we'll need **collaborator access** to your store. You can share your 4-digit collaborator request code from **Shopify Admin → Settings → Users → Security → Collaborator request code**, and our team will send the access request. If you don't have a code set up, we can send the request directly for you to approve.

If you have a reference design, a mockup, or a page you'd like us to match, share the link or a **high-resolution** image — low-res references slow things down because we can't read the detail. For multi-item change lists, we'll usually set up a shared document so nothing gets lost.

Note: pages built this way use custom code on your theme, so you'll be able to edit the **text** yourself but not the layout — send layout changes back to us.

### Q3: How do I test the program before launching, and how do I know it's ready?
**Frequency:** ~9 sessions 🔁 recurring

**Standard answer:**
Use **Sandbox mode**: **Joy Admin → Reward programs → Sandbox Mode → Turn on**. While sandbox is on, only accounts on your test list earn points — real customers are unaffected.

1. With sandbox on, a **Test list** button appears at the top right of the Reward programs page. Click it and enter the email addresses you want to test with (one per line or comma-separated) → **Confirm**.
2. Enable the Joy app embed on a **duplicate/draft theme** so you can interact with the widget without touching your live store.
3. Sign in on the storefront with a test account and run the actions you've configured — place an order, sign up, leave a review — then verify the points landed under **Joy Admin → Customers**.

Two things that trip people up in testing: if the test email isn't on the whitelist, it earns **nothing** (which looks like a bug), and the sign-up reward won't fire for an account that already existed before the program started — test with a genuinely new email.

When you're ready, ask us for a pre-launch review. We'll check your earning programs, redeeming programs, VIP tiers and widget status and flag anything missing.

### Q4: How do I pause or turn off the loyalty program without losing data?
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
You have several options, all of which keep your configuration and your customers' point balances intact:

- **Hide the program site-wide** — **Joy Admin → Settings → General → App status** → turn the app off. This hides the reward widget across your store.
- **Stop earning only** — turn off the individual programs under **Reward programs → Earning programs**. Existing balances stay untouched and customers can still redeem.
- **Pause everything** — put the programs into **Sandbox mode** and switch notifications off.
- **Downgrade to Starter (free)** — takes effect at your next billing cycle. Your data stays, and existing point balances remain redeemable.

Point expiration settings keep running as configured regardless of which option you pick, so check those if you're winding the program down.

### Q5: What's included on the free Starter plan?
**Frequency:** ~7 sessions 🔁 recurring

**Standard answer:**
Starter (free) includes **250 free orders per month** and covers the core loyalty loop: points earning, holding and redemption, the loyalty widget, referrals (up to 30), and the Joy panel inside your Shopify customer profiles. Points work fully on every plan, including Starter.

Not included on Starter — these begin on Essential or Advanced: points expiration, the dedicated loyalty page, birthday rewards, free gift and free shipping redemptions, analytics, fraud prevention, multi-language, Shopify Flow, VIP tiers, Rule Engine, milestones, POS and the Loyalty Hub.

You can compare plans and upgrade at **Joy Admin → Settings → Subscription → All plans**.

## 2. Points — Earning

### Q6: A customer placed an order but didn't get points — why?
**Frequency:** ~13 sessions 🔁 recurring

**Standard answer:**
Work through these in order — most cases are one of the first four:

1. **The order hasn't reached the reward status yet.** Points fire when the order hits the trigger set in **Settings → Order → Reward by order status** (Paid or Fulfilled). If you reward on Fulfilled, an unfulfilled order legitimately shows no points yet.
2. **The customer is a Guest, not a Member.** If your Place-order rule is set to reward members only (or only customers in a VIP tier), a guest checkout earns nothing. This is also why a customer can receive the sign-up reward *after* an order and still have no points for that order.
3. **The program's date range excluded it.** Check the program's start and end date — an expired end date silently stops all earning.
4. **Conflicting conditions on the rule.** A common one we see: sale channel set to *equals Online store* **and** *equals POS*. No order can be both, so nothing ever qualifies. Remove the conflicting conditions.
5. **Product/collection conditions.** If you run several rules with different eligible collections, the order may have matched a different rule than you expected — or none.
6. **Order-level exclusions** — **Settings → Order** filters by order tag, source or payment gateway, plus B2B/company orders, will block earning entirely.

If none of these explain it, send us the **order number and the customer's email** and we'll check the activity log directly. We can add the missing points manually.

### Q7: Why didn't a customer get the sign-up / welcome bonus?
**Frequency:** ~9 sessions 🔁 recurring

**Standard answer:**
The sign-up reward is not granted the moment a Shopify account is created. It fires through one of three paths:

- **Storefront** — the customer **logs in**, then loads any page where the **Joy embed widget is active**. If the embed is off, the reward can't trigger even for a valid login.
- **Widget popup** — the customer opens the widget and clicks **Join**.
- **POS** — a guest buyer is identified as a member at the register.

Leaving an email alone — through a form, checkout, or a newsletter opt-in — does **not** earn it, even though Shopify may mark that customer as "Enabled" and Joy may count them as a Member.

The other frequent cause: **the account was created before the sign-up program started.** By default only accounts created on or after the program's start date qualify. If you want your existing customer base to receive it too, use **Settings → Pre-launch → Sync Sign Up**, or contact us and we'll run it for you — and tell us if you want notifications suppressed so customers aren't emailed.

For a one-off, just add the points manually at **Joy Admin → Customers → [customer] → adjust points**.

### Q8: Can I set different point values for specific products or collections?
**Frequency:** ~5 sessions 🆕 new

**Standard answer:**
Yes. Create **multiple Place-order rules**, each with its own earning rate and its own product/collection condition, at **Joy Admin → Reward programs → Earning programs → Place order → Add rule**.

- To let rules **stack** (a customer buying from two bonus collections in one order earns from both), leave **"Stop giving rewards after this program"** off — that's the default.
- To make one rule **override** the others, give it **Priority 1** and turn **"Stop giving rewards after this program"** on, then set your base rule to a lower priority. This is also how you run a limited-time double/triple-points campaign alongside a permanent base rule.
- Points can be awarded **per item quantity** as well as per amount spent, and auto-reversal on cancellation, full refund and partial refund is supported via the auto-revoke toggle on the rule.

Running more than one Place-order rule requires the **Rule Engine**, which is available on **Advanced and Ultimate**. On Essential you have a single Place-order rule — for a temporary campaign you'd manually change the rate at the start and change it back at the end.

There's currently no way to drive point values from a product metafield or bulk import.

### Q9: How do I run a limited-time bonus (double points, birthday month, campaign week)?
**Frequency:** ~5 sessions 🔁 recurring

**Standard answer:**
Create a **second Place-order program** with the campaign rate and a date range, then control precedence with priority:

1. **Reward programs → Earning programs → Place order → Add rule**
2. Set the campaign rate and the **start/end dates** (or the **dynamic date** option for a recurring window such as the customer's birth month)
3. Set the campaign rule to **Priority 1** and tick **"Stop giving rewards after this program"**
4. Set your normal Place-order rule to **Priority 2**

The campaign rule is then evaluated first and blocks the base rule while it's active; when it expires, earning reverts to the base rate automatically.

Two things to check: your **store timezone** (Shopify Admin → Settings → General) so the campaign starts when you expect, and that this requires **Rule Engine (Advanced+)** since it means running more than one Place-order rule.

Note that points are locked at the rate in effect when the earn event was recorded, so an order placed before the campaign starts keeps the old rate even if it fulfils during the campaign.

### Q10: Do shipping, taxes and gift cards count toward points?
**Frequency:** ~3 sessions 🆕 new

**Standard answer:**
By default, points are calculated on the **order subtotal** — shipping and taxes are excluded. If you want to include them, turn on **"Reward for additional fee"** on the Place-order rule.

**Gift cards are different:** if a gift card is processed as a normal order, the customer will earn points on it. To prevent that, add a product/collection condition on your Place-order rule that **excludes** your gift card products (or add an Advanced condition excluding gift cards from the store-credit earning base).

### Q11: How do I add points for customers' past orders?
**Frequency:** ~6 sessions 🔁 recurring

**Standard answer:**
It depends what you're trying to achieve:

- **Just to welcome existing customers back** — the simplest option is a flat bonus (say 100–200 points) applied to everyone via a CSV import at **Joy Admin → Customers → Import**, paired with an announcement email.
- **Genuine retroactive credit for real past orders** — tell us the **date range** and whether VIP tiers should be recalculated too, and our team will run the past-order points update. For an all-time backfill you can also use **Settings → Sync points for past orders** yourself.

Two cautions from recent cases: tell us **which customers already received manual points** so we don't double-credit, and be aware that a sync runs against your whole customer base — if you only want a subset (e.g. "people who signed up yesterday"), say so up front, because stopping a sync mid-run and reversing the wrong awards is messy.

If you're recalculating after an import, remember points and Amount Spent don't refresh on their own — you need to **Launch** (or re-launch) the relevant program to trigger recalculation.

### Q12: Why aren't visit / social / Instagram / Google review points being awarded?
**Frequency:** ~7 sessions 🔁 recurring

**Standard answer:**
For all of these, **the customer must be logged in at the moment they perform the action.** Joy identifies customers by their account session, not by IP or device, so a logged-out visitor can't be credited. This isn't stated prominently on the setup screen — we've flagged that internally.

Beyond that:

- **Social follow / share** is **trust-based**. Social platforms don't expose APIs or webhooks that let us verify a follow, so points are awarded when the customer clicks through to your profile. Most customers do follow through, but the click is what's tracked. This applies to Joy the same way it does to other loyalty apps.
- **Instagram-specific programs** (comment, story reply, story mention, live comment) need an Instagram **Business or Creator** account connected at **Joy Admin → Integrations → Instagram** (check for the "Connected" status), and the customer must link their Instagram username in the widget.
- **Google reviews** sit in an approval queue by default. See Q14.

### Q13: What is the "Complete birthday info" reward, and when does the birthday reward itself fire?
**Frequency:** ~8 sessions 🔁 recurring (Complete-birthday-info specifics 🆕)

**Standard answer:**
These are two separate things:

**Complete birthday info reward** grants points the moment a customer submits their birthday through the loyalty widget for the first time. It's immediate and unrelated to their actual birthday. *(If you're testing this and see 0 points awarded: there was a bug here that our team has since patched. Accounts that already logged the activity can't re-trigger it — add the points manually for those, and test with a fresh account.)*

**The birthday reward** fires around the birthday itself, and four conditions must all be met:

1. **The 30-day rule** — the birthday must be saved **at least 30 days before** the birthday. Enter it any later and the reward defers to next year. This is deliberate anti-abuse protection. This is by far the most common reason a customer "didn't get" their birthday reward.
2. The customer is a **registered member**, not a guest.
3. The date falls inside the window you configured (exact date, birth month, or a custom range) at **Reward programs → Birthday reward**.
4. The claim method matches — **Automatic** adds the reward on its own; **Manual** requires the customer to click Claim inside the window.

Birthday scans run at **0:00 UTC-7**. Customers can't edit their own birthday once saved — you can update it in the customer profile in Joy admin.

If a customer missed out because of the 30-day rule and you'd like to reward them anyway, send us the customer's email and we'll trigger it manually. There's also a **Trigger birthday reward** button in the customer profile you can use yourself.

**To get advance notice yourself** (e.g. to prepare a physical gift), Joy exposes a **"7 Days Before Customer's Birthday"** trigger to **Shopify Flow** — build a workflow with that trigger and a Send email action to your own address.

### Q14: A customer left a review but got no points.
**Frequency:** ~6 sessions 🔁 recurring

**Standard answer:**
Check these in order:

1. **Is the review app connected?** **Joy Admin → Integration → [your review app]** should show **Connected**, and a **Write a review** program should exist under Reward programs. A connection can silently drop — we've seen this cause exactly this symptom.
2. **Is the customer a member, and is the review published?** Points only go to members, and only for published reviews.
3. **Is the "Default status" setting on Pending?** This is the most common cause. **Settings → General → scroll to the bottom** → **Default status for Product reviews** / **Default status for Google Maps reviews**. On **Pending**, points wait for your approval; on **Approved**, they credit automatically. Approve pending records at **Customers → Activities → Review activities** (or the Google Reviews tab). There's no bulk-approve, so an existing backlog has to be cleared one by one.
4. **Anti-fraud limit.** The Write-a-review program has a frequency limit — e.g. "1 per hour". A customer who posts several reviews back to back earns for the first only. Change **Limit** to Lifetime (or turn the limit off) at **Reward programs → Write a review**, and credit the blocked ones manually.
5. **Judge.me's "not eligible for coupon" message is not about Joy.** That's Judge.me's own Coupons feature, shown on every review regardless of Joy points, and usually disabled. Check the customer's **Review activities** in Joy instead.

Also note Joy only rewards **new** reviews created after the integration is connected — historical reviews aren't backfilled. And webhook delivery from the review app can lag, so a review may sync a little later than expected.

### Q15: Can I award points only for reviews from verified buyers?
**Frequency:** ~2 sessions 🆕 new

**Standard answer:**
Yes. The Write-a-review program has a verified-buyer option — when it's on, Joy checks the review webhook from your review app and only awards points if the review is flagged as a verified purchase. Reviews from non-purchasers won't earn.

Since customers can still *submit* a review without buying, it's worth updating the program description in the widget so it reads something like *"Earn points for every review from a verified buyer"* — otherwise customers expect points they won't receive.

### Q16: Can I use store credit instead of points?
**Frequency:** ~5 sessions 🔁 recurring

**Standard answer:**
Yes — store credit gives customers a real cash-value balance on their Shopify account that's applied automatically at checkout, with no coupon to paste. Select **Store Credit** as the reward type on a supported program; the first time you do, an inline banner asks you to **Grant Access**, and that one-time grant covers all programs.

**Important limitation:** store credit is only supported on **some** earning programs — Place order, Place subscription and Referrals. It is **not** available for Sign up or social/Instagram programs. This is a current gap and has been logged with our product team; there's no workaround today.

Other things worth knowing:
- Store credit is calculated on the **order subtotal** (shipping and tax excluded).
- Joy simplifies the displayed rate by default (2 credits per $100 shows as 1 per $50). The "don't simplify" checkbox changes the display only, not the actual rate.
- With **Nearest** rounding, a small order can round down to $0 — enable **decimal store credit** if you need exact fractional amounts.
- Once you've granted permission and have at least one active store credit program, the balance shows automatically across the widget balance card, loyalty page, account pages, point calculator and thank-you page — no toggle needed.

### Q17: Can points expire, and how do I set that up?
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
Yes. Set it up at **Joy Admin → Reward programs → Point Expiration → Turn on**. There are three types:

| Type | Plans | Behaviour |
|---|---|---|
| Full expiration | Essential+ | The whole balance expires after N days of **inactivity**; any earn or spend resets the timer for the entire balance |
| Fixed date | Essential+ | All points expire on a set calendar date regardless of when they were earned |
| Expiration by earning date (FIFO) | Ultimate | Each batch of points expires N days after it was earned |

Point expiration is **not available on the free Starter plan**.

If points seem to have expired early, check which type is on — the Full-expiration clock runs from the **last activity** (earn or spend), not the last order date. Compare the `expired` event in the customer's activity log against their last activity; if it doesn't line up with any of the three logics, send it to us and we'll check the setting's history.

## 3. Redemption & Discount Codes

### Q18: How do customers actually redeem, and does the code apply automatically?
**Frequency:** ~11 sessions 🔁 recurring

**Standard answer:**
The main path is the widget or loyalty page: the customer logs in, opens the floating widget, goes to **Redeem points**, picks a reward and clicks **Redeem**. Joy generates a unique one-time code. They then either click **Apply** to push it to the cart, or copy the code and paste it at checkout.

**The code does not apply itself at checkout.** This is the single most common "my discount vanished" report — the points were spent, the code was issued and is valid, but nobody entered it. Unused codes are always retrievable from the widget's **My coupons** section.

Other redemption surfaces:
- **Cart drawer** — see Q20.
- **Checkout page** (Quick Redeem, coupon list, redeem-at-checkout) — see Q19.
- **POS** — staff look up the customer's balance and apply the reward to the cart.

One quirk worth knowing: if a customer clicks Apply while their cart is empty, the discount is held and takes effect once items are added — but the page may need a refresh before the cart reflects it.

### Q19: Can customers redeem directly at checkout?
**Frequency:** ~6 sessions 🔁 recurring

**Standard answer:**
Only on **Shopify Plus** stores with **Checkout Extensibility**, and on the **Ultimate** plan (Advanced is possible via a sales conversation). This is a Shopify platform restriction on who can customise checkout, not a Joy limitation — if your store is on Shopify Basic, checkout blocks aren't available at any Joy plan level.

Where it is available, turn it on per program at **Reward programs → Redeeming programs → [program] → Redeem value → Redeem at checkout page**. Cancelling refunds the points instantly.

**If you're not on Plus**, the practical equivalents are:
- The **cart drawer** redeem block, where the balance shows and the cart total updates instantly before checkout (Essential+)
- A **Ways to redeem** block added to your cart page
- The widget or loyalty page

Note that checkout UI extensions don't support language auto-detection by IP or browser — you can set only one language at the checkout level.

### Q20: How do I add the redeem block to my cart drawer?
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
Available on **Essential, Advanced and Ultimate**.

1. **Joy Admin → On-site content → Product page tab** → find **Redeem in Cart Drawer** → **Edit in Theme Editor**
2. In the Theme Editor, enable the app embed **Joy: Redeem in line**
3. **Save**

If it doesn't appear afterwards, the usual reason is that **Joy: Redeem in line** was never toggled on — it's a separate embed from Joy Loyalty - Widget.

**Third-party slide carts and page builders** (qikify, PageFly, custom drawers) are the other common case: the embed binds to Shopify's native cart-drawer selectors and won't attach automatically. Tell us which cart app you use and grant theme access, and our team will add the matching CSS selector.

If a coupon errors in the cart but works at checkout, that's the same root cause — the code is valid, only the cart-drawer display needs the selector fix.

### Q21: A redeemed code isn't working at checkout.
**Frequency:** ~7 sessions 🔁 recurring

**Standard answer:**
The three causes, in order of frequency:

1. **Discount combination isn't enabled.** By default Joy coupons don't combine with other discounts, so if an automatic discount (free gift, sitewide sale, free shipping) is already applying, Shopify prioritises it and the Joy code is rejected. Fix it at **Reward programs → Redeeming programs → [program] → Combinations**, and choose which classes (Order / Product / Shipping) may stack. Shopify's own rules still apply: one discount per product, one shipping discount per order.
   **Important:** combination changes only affect **newly issued** coupons. Codes already in customers' hands keep the settings they were created with.
2. **The code's own conditions aren't met** — minimum order value, eligible products or collections, sales channel.
3. **The discount is larger than the cart.** A fixed-amount reward bigger than the cart total reduces it to $0. Shopify permits this, but some third-party apps (fee/bundle apps in particular) throw a validation error at $0 and leave the checkout button unresponsive. **Set a minimum cart value on the redeem program** so a large fixed-amount code can only apply to a qualifying cart.

If combinations and conditions all look right, send us the code and the order and we'll audit it.

### Q22: Can I change a coupon's expiry date or conditions after it's been issued?
**Frequency:** ~3 sessions 🆕 new

**Standard answer:**
No — once a coupon has been generated, its conditions and expiry can't be edited. If a customer's coupon is about to expire or has expired, the practical fix is to issue them a replacement discount code (either by revoking and re-redeeming, or by creating a code directly in Shopify Admin → Discounts).

Expired coupons are automatically hidden from the widget, so customers won't see dead codes.

**Related:** to **deactivate** a code without refunding the points, don't use Joy's **Revoke** — Revoke always converts the unused coupon back into points by design. Instead deactivate the code directly in **Shopify Admin → Discounts**. Note the status inside Joy may not update to Expired immediately afterwards. For bulk deactivation there's no self-serve option — send us the store URL and the list or criteria.

### Q23: A redeemed free-gift code is rejected on subscription renewal orders.
**Frequency:** ~1 session 🆕 new

**Standard answer:**
This is a known limitation with **Free Gift** rewards specifically, when the code is applied through a subscription portal (Loop, and similar) rather than a normal cart and checkout.

Free Gift codes are backed by a Shopify Function that inspects the cart lines at checkout to identify the gift variant and cap the discount to the configured quantity. Subscription portals apply codes to an existing subscription contract instead of a live cart, so the Function can't resolve the variant and Shopify rejects the code — the portal usually surfaces this as a generic "invalid discount code".

**This affects Free Gift rewards only.** Amount, percentage and free-shipping rewards use a different, subscription-compatible path and work normally on renewals. We don't have a workaround for Free Gift on existing subscriptions yet; it's with our development team.

### Q24: My product doesn't appear when I try to select it for a redeem reward.
**Frequency:** ~2 sessions 🆕 new

**Standard answer:**
Only products **published to the Online Store sales channel** sync to Joy and appear in the reward product picker. Products left as **Draft** (or removed from the Online Store channel) won't be selectable.

Merchants usually hit this when they want a reward product that shouldn't be publicly browsable. Two ways to handle it:

- **Set the product to Active but hide the buy path** — group the reward products under a dedicated product template and hide the Buy button on that template. Customers can't purchase them normally but can still redeem them with points.
- **Combine with a VIP tier perk** — **Membership → VIP Tiers → [tier] → Tier privileges → Add perks → Exclusive products/collections** restricts purchase to selected tiers, with an unlock message for everyone else.

Either way the product has to stay Active in Shopify for the reward program to reference it.

### Q25: Can customers redeem a flexible amount, or their whole balance at once?
**Frequency:** ~6 sessions 🔁 recurring

**Standard answer:**
Yes — use **Dynamic Discount** rather than Fixed Discount, at **Reward programs → Redeeming programs → [program] → Redeem value → Dynamic Discount**. Set your conversion (e.g. 100 points = $1) and the customer can choose how many points to apply, in multiples, on the storefront.

Dynamic mode also exposes three optional limits:
- **Minimum points required to redeem**
- **Maximum points per redemption** — clear or raise this if you want customers to be able to spend their full balance in one go
- **Maximum discount as a % of cart total**

**Fixed Discount** works the opposite way: one set amount per redemption, no thresholds, so a customer with 1,000 points redeems one tier at a time.

To protect your margins, the "maximum discount as a % of cart value" limit is the right lever — it caps how much of any single order can be paid for with points regardless of how large a balance the customer has accumulated. There's no universal recommended figure; set it against your average order value and margins.

### Q26: How do I control which rewards show, and in what order?
**Frequency:** ~3 sessions 🔁 recurring

**Standard answer:**
The order of options inside the **Ways to redeem** / **Ways to earn** blocks is controlled from the **Reward programs** menu — drag the programs into the order you want (e.g. lowest to highest point cost). It's not set in the block itself. Tell us your preferred order and we can reorder them for you.

More redeem options appear on the loyalty page as you create more redeeming programs, so a sparse-looking "Ways to spend" section usually just means only one or two programs exist.

For per-option icons, open the program at **Reward programs → Redeeming programs → [program]** and use the **AI icon** section (enter a prompt, regenerate until it matches), or upload your own icon at **On-site content → Loyalty page → Ways to redeem**. Free-product rewards pull their image directly from the product's own media in Shopify.

### Q27: How do customers know a reward has a minimum order value?
**Frequency:** ~2 sessions 🆕 new

**Standard answer:**
Joy displays it automatically. Any reward with a minimum purchase requirement shows a line such as *"Applicable for $85 minimum orders"* in the reward details — on both the widget and the loyalty page — and again in the coupon details under My Rewards after redemption. The condition is never hidden.

For **Free Gift** rewards you can also add your own **description** to each reward, which then displays on the widget and the loyalty page.

One behaviour worth explaining to customers: the minimum order value is checked **when the coupon is applied at checkout**, not when it's redeemed. So a customer can redeem at any time, but the discount only takes effect once their cart reaches the minimum.

## 4. VIP Tiers & Milestones

### Q28: Can different VIP tiers earn points at different rates, including decimals like 1.5x?
**Frequency:** ~4 sessions 🔁 recurring (decimal answer 🆕 changed)

**Standard answer:**
Yes, including fractional rates.

The **Bonus Points perk** on a tier accepts **whole multipliers only** (2x, 3x, 4x). For fractional rates such as **1.5x**, use the **Rule Engine**: upgrade your Earning program to Rule Engine (under **More actions** on the Earning programs page), then set a **Place order** rule with the decimal rate targeted at that tier.

The other route on the Place-order program itself: open **Reward programs → Earning programs → Place an order**, set **"Who to reward"** to **"Only customers in a VIP tier can earn points"**, and the form shows one earning-rate field per tier.

**Requirements:** a VIP Tier program must already be set up and enabled (otherwise the tier option is greyed out with "You haven't setup VIP Tier yet"), and Rule Engine is available on **Advanced and Ultimate**.

You don't need Shopify Flow for this — earlier guidance suggesting a Flow bridge for decimal rates is superseded. If you'd like, tell us the rates per tier and we'll configure it for you.

### Q29: How do I set up a discount that applies automatically for each tier?
**Frequency:** ~5 sessions 🔁 recurring

**Standard answer:**
Set each tier's discount up as a **Privilege (perk)**, not an entry reward — privileges apply automatically on every qualifying order while the customer holds the tier.

**Joy Admin → Membership → VIP Tiers → [select tier] → Tier privileges → Add perks →** choose the privilege type (Discount Percentage, Discount Amount, Free Shipping, Free Product, Bonus Points, Exclusive Products, Custom Reward) → set the value → **Save** → **Launch** the tier. Repeat per tier; a customer only receives the discount for the tier they're currently in, not a cumulative stack.

Two things to check if a perk isn't applying:
- **Discount combination.** Tier perks are automatic discounts. If another discount is already on the cart and combination isn't enabled, the perk won't apply. Enabling combination fixes it — but be aware it then stacks with your sitewide sales, so decide which behaviour you want.
- **Use "Set maximum discount amount"** on the perk to cap how much value any single order can take from it. Scaling this cap alongside the tier percentage is a reasonable approach.

Fixed-amount perks previously applied per eligible item; there's now an **"Apply discount only once per order"** option that restricts the deduction to once per order total, matching Shopify's native behaviour.

### Q30: A tier entry reward wasn't given / can I give it again?
**Frequency:** ~5 sessions 🔁 recurring

**Standard answer:**
**Entry rewards** fire once, when a customer first reaches the tier, and they are **not retroactive** — customers who were already in that tier before you created or edited the reward won't receive it. Similarly, customers who joined your program before the VIP tier program was launched are assigned a tier retroactively but do **not** trigger the entry reward.

Set entry rewards at **Membership → VIP Tiers → [tier] → Entry reward → Add reward** → choose type → Save → **Launch** to apply. A common mistake is configuring the coupon under **Tier privileges** instead of **Entry reward** and then wondering why it never appears.

**To re-grant an entry reward when someone drops a tier and re-reaches it**, enable **"Allow giving entry reward again after being downgraded"** at **Membership → VIP Tiers → Tiers tab → Tier configuration settings → Customer management**. This covers demotion, manual admin edits and tier imports. With it off, the entry reward is strictly once per customer per tier.

### Q31: All my customers' tiers changed / points look wrong after I launched or edited VIP tiers.
**Frequency:** ~7 sessions 🔁 recurring

**Standard answer:**
This is almost always a re-assessment, not lost data. Changing a threshold, changing the calculation rule (Points earned / Amount spent / Number of orders), re-launching VIP Tier, or running a tier import makes Joy re-evaluate **every** customer against the new rule.

The most common specific cause we see: **the VIP tier program's start date**. Tier points are only calculated from orders placed on or after that date. If you set the start date to today, everyone starts at zero. Set it back to the date you actually want to count from (e.g. your store's first year of trading) and re-launch, and Joy will recalculate tier points from that point forward and reassign customers. Launching does **not** affect point balances.

Also important: **VIP tier points and point balance are two separate metrics.**
- **Point balance** = what customers can spend; it goes down when they redeem.
- **VIP tier points** = cumulative points earned, never reduced by redemption. This is why a customer with a small current balance can legitimately sit in a high tier.

Because of this, adjusting or resetting a point balance does **not** recalculate tier points — there's no self-serve toggle to re-sync them. If tier points need to be rebuilt from a source file, send us the file, the affected customers and the reset timestamp.

For large customer bases, a recalculation can take several hours to complete; the per-customer activity log shows progress. If tiers change **without** you having edited anything, let us know the date — we'll investigate what triggered it.

### Q32: Can I demote customers who stop buying, or reset tiers periodically?
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
Two mechanisms:

- **Tier demotion** — a simple inactivity downgrade. If a customer hasn't earned in the configured period, they drop a tier.
- **Tier Assessment** — a rolling-window re-evaluation, which is what you want for "keep your tier based on spend over the past year". Configure at **Joy Admin → Membership → VIP Tier → Assessment**, using **Assessment cycle**, **Assessment cycle start date**, **Assessment offset** (the lookback window) and a **threshold to maintain tier** (labelled Spending / Order count / Points depending on your tier metric).

Tier Assessment is available on **Advanced and Ultimate only**, and additionally needs to be **enabled by our team for your store** — it isn't a self-serve toggle yet. Confirm your plan, then contact us and we'll turn it on.

A **quarterly** tier reset isn't available as a preset option today; it's been raised with our product team.

Also worth planning for: customers currently have no on-widget indication of how long they have before demotion or how much more they need to spend to maintain their tier. That's a logged feature request — until it ships, communicate it via your tier emails.

### Q33: Can I manually assign a customer to a tier?
**Frequency:** ~3 sessions 🔁 recurring

**Standard answer:**
Yes — **Joy Admin → Customers → [customer] → Assign to exclusive tier**. Exclusive tiers are manually assigned only and sit outside the automatic VIP progression, which makes them right for ambassadors, wholesale accounts and influencers. Each customer can be in one exclusive tier at a time, and members of an exclusive tier don't progress through the regular tiers concurrently.

The red warning you'll see when assigning is expected: it means the customer's **tier qualification points** will be set to that tier's entry threshold. Their **redeemable point balance is not changed**. It's safe to confirm.

### Q34: How do milestones work, and can I show progress?
**Frequency:** ~3 sessions 🔁 recurring

**Standard answer:**
Milestones are available on **Advanced and Ultimate**, at **Joy Admin → Reward programs → Milestones → Add milestone**. Types include number of orders, amount spent, earned points, number of reviews, number of referrals, inactivity, subscription cycles, and **Mixed milestone** (a sequential journey combining several steps).

Use **Milestone settings → Progression mode** to control what happens when a customer clears several milestones at once — **Only the highest milestone reward** or **All milestone rewards**.

Two current limitations to plan around:
- Milestone **progress cannot be displayed on the customer account page**, and a single milestone can't repeat. If you want a repeating ladder, VIP tiers with entry rewards are usually the better structure.
- A milestone can't award "double points on your next order" — that's a Place-order earning rule and can't be expressed inside a milestone journey. Gift cards also can't be chosen as a free-gift reward.

Edit a milestone's display name and description at **Milestone settings → [milestone] → description**; reorder the milestone block in the widget by drag-and-drop under **Widget settings → Sections**.

## 5. Referral

### Q35: When exactly does the referrer get rewarded?
**Frequency:** ~5 sessions 🔁 recurring

**Standard answer:**
The flow is: the referrer shares their unique link → the referee clicks it, lands on the referral page and enters their email to claim → a **7-day cookie** is stored → the referee places an order **with the same email** → both sides are rewarded.

The **referee's** reward is issued at the claim step. The **referrer's** reward stays pending until the referee actually places a qualifying order, and then follows your shop's earn-status setting: on **Paid** (the default) it's granted as soon as the order is paid; on **Fulfilled** it waits, and the referral shows **"Awaiting fulfilment"** in the meantime — that's normal, not a failure.

Common reasons a referrer doesn't get rewarded:
- The referee used a **different email** at claim vs checkout
- The cookie expired — more than 7 days between click and purchase
- The order **subtotal is $0** — anti-cheat requires more than $0
- Anti-cheat blocked it because both parties shared a browser, email or IP address
- The referee's order was **fully refunded** and auto-revoke is on
- The referrer hit the per-program referral cap, or the **Starter plan's referral limit** (30 referrals; Essential allows 100, Advanced and Ultimate are unlimited)
- The **app pixel** is disabled — check Shopify Admin → Settings → Customer Events → Joy, and toggle the program off and on to re-sync
- The program is still in **Sandbox** — a "running in test mode" message means no real rewards are issued

When testing, don't test on a machine where you're logged into your own store — the referral page may show only the code without prompting for a friend's email. Use incognito, another account, or a phone.

### Q36: Can the referrer be rewarded when the referee just signs up, without an order?
**Frequency:** ~2 sessions 🆕 new

**Standard answer:**
Not natively — the referrer's reward is tied to the referee placing a qualifying order, by design, to prevent fraud from fake sign-ups. This trigger can't be changed in the app settings.

There is a **Shopify Flow workaround**:

1. Create a Flow with a trigger and a **Reward Points** action
2. Set the email variable to the **referrer's** email address
3. When the referee opens your store via the referral link, enters their email and clicks **Claim**, the Flow fires and awards points to the referrer

**Important:** set the referrer reward to **"No Reward"** inside Joy first, otherwise points are issued twice — once by the Flow and once by the native referral feature. Update your customer-facing copy to match the new mechanic.

### Q37: Where do customers find the referral link, and can I change the popup or the wording?
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
There's no separate referral landing page — customers access referral sharing through the **loyalty widget** or, on Advanced+, the **Referral Management block** on the account page. You can also add the **Joy: Referral block** to your loyalty page and the **Referral block** to your thank-you page for visibility, and use the `#joy-referral-program` deeplink.

You can change the **referral redirection URL** (where the referee lands) at **Joy Admin → Reward programs → Referrals** — the default is your homepage.

To **turn off the referral invite popup**, go to **Joy Admin → On-site content → Popups** and toggle it off. Referral popup design lives under **On-site content → Widget → Referrals → Setup**. Customers can still reach referral through the main widget even with the dedicated popup disabled.

Reward wording that comes from system variables (for example how a reward is phrased as "$10 of coupon") is currently fixed and not editable from the dashboard — that's a logged feature request.

## 6. Members, Guests & Opt-in Enrollment

### Q38: What's the difference between a Member and a Guest, and who earns points?
**Frequency:** ~8 sessions 🔁 recurring

**Standard answer:**
- **Member** — can earn and redeem, and sees full status in the widget.
- **Guest** — can earn only if guest earning is enabled on your programs, cannot redeem, and sees general info only.
- **Left program** — earns nothing, sees nothing. Use this for staff, test accounts and wholesale.

How customers become Members depends on your setup. With **New Customer Accounts**, anyone Shopify identifies as "Enabled" is treated as a Member — including someone who only left an email at checkout or in a newsletter form. With **legacy accounts**, they must register.

Being a Member is **not** the same as having earned the sign-up reward — see Q7.

If you want a stricter definition of membership, use **opt-in enrollment** (Q39).

### Q39: I turned on opt-in / "Join Program" — why did existing customers stop earning?
**Frequency:** ~4 sessions 🆕 new

**Standard answer:**
With opt-in enrollment on, a customer must **actively click "Join Program"** (while logged in) to become a Member. Until they do, they're a Guest — and if your Place-order rule rewards members (or VIP tier members) only, a Guest's orders earn nothing, even after your program is live. Their activity log will show the order recorded but no points.

This catches merchants out most often when opt-in is enabled *after* launch: customers who signed up in the gap were treated as Members, earned points, and then the rules changed underneath them.

Two things to be aware of if you're cleaning this up:
- Points already awarded before opt-in was enabled don't disappear on their own. If you want them cleared, or want a specific date to be the true "start" of your program, tell us the exact date and scope and we'll run it — this needs a manual pass from our team.
- **Entry rewards won't retroactively fire** for customers who joined before the tier program went live. If you want them issued, that's also a manual pass.

One thing we can't do: Shopify doesn't send a clear webhook for customer sign-up under the new customer accounts model, so we can't automatically restrict membership to "only people who deliberately created an account". Opt-in is the closest available control.

### Q40: A customer has two accounts / their points are split.
**Frequency:** ~3 sessions 🔁 recurring

**Standard answer:**
Shopify creates two separate customer IDs when identifying details don't match exactly — most often when someone buys in store via POS with a different email or phone than their online account. Joy reflects whatever Shopify has, so it sees two customers.

Merging depends on **Shopify's** customer merge, not Joy. Confirm both emails are the same person, merge them in Shopify, and if the point balances don't combine afterwards, send us both emails and the expected total and we'll consolidate the points into the surviving account.

**If a customer's email was entered incorrectly at POS**, we can remove the misplaced points and activity from the wrong account — but we can't move them without the correct email, because Joy's customer data is synced from Shopify. Create the correct Shopify customer first, let it sync, then the points can be adjusted onto it.

### Q41: A customer isn't showing in Joy, or search doesn't find them.
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
All customers should sync from Shopify to Joy automatically after install. If your counts don't match, send us the store URL and we'll trigger a re-sync.

Separately, there was a **customer search issue** where lookups by name returned nothing even though the customer existed (email search sometimes worked). Our team has fixed this — if you still can't find a customer by name, let us know and we'll check. In the meantime you can always search by **email**, or by order ID or coupon code from the Quick Search bars on the Joy homepage and Reward programs page.

## 7. Widget & On-site Display

### Q42: The widget isn't showing on my store.
**Frequency:** ~9 sessions 🔁 recurring

**Standard answer:**
Check these four, in order — in recent cases the cause was #2 or #3 far more often than #1:

1. **App embed** — Shopify Admin → Online Store → Themes → Customize → **App embeds** → **Joy Loyalty - Widget** on → Save.
2. **"Hide widget button" is enabled**, or the widget is hidden on all devices, under **On-site content → Widget → Widget design → Setup → Advanced → Display**.
3. **"Display after login" is on**, so guests never see it. Test while logged in before concluding it's broken.
4. **Customer eligibility is set to "Manually assigned customers only"** in Settings → General, which hides the widget from everyone not manually added.

Also note the **"App embed 0 Active" / "Inactive"** status inside Joy can be inaccurate — it's synced from your theme and can be thrown off by a theme conflict. It does **not** stop points from being earned. If earning is working normally in the activity log, treat the status badge as cosmetic and let us know so we can check the sync.

Send us the store URL and we can look at your display settings directly and switch anything blocking it.

### Q43: The launcher button overlaps my cart / chat / navigation. Can I move it?
**Frequency:** ~22 sessions 🔁 recurring (largest topic this week)

**Standard answer:**
It depends how precise you need to be:

**Rough clearance** you can do yourself: **Joy Admin → On-site content → Widget → Widget design → Setup → Settings → Launcher** → adjust **Alignment** (bottom left / bottom right), button size and border radius. You can also use **Advanced → Display → Page restriction** to hide the widget on pages where it conflicts.

**Exact placement** — above the Add-to-Cart bar, below a sticky header, bottom-centre, matched to another button's size and offset, or aligned to a specific theme element — is **not** achievable through the built-in settings. It needs custom CSS applied by our team. Send us:

- a screenshot or mockup showing the target position
- the page URL
- the device (desktop / mobile, and which OS if it's mobile-specific)

and share your collaborator code. We'll apply targeted CSS and send you the result to verify.

A related case worth flagging: if the launcher sits correctly on load but **jumps position after you tap it**, that's a separate rendering issue — tell us the device and OS, and we'll apply a fix rather than treating it as a positioning request.

Also: if a floating button near yours isn't ours, we can't move it. We check the storefront first — several times this week the conflicting element belonged to another app.

### Q44: Can I put the loyalty entry point in my navigation menu instead of a floating button?
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
Yes, using deeplinks. Add a menu item whose URL is one of the Joy anchors:

- `#joy-home` — opens the widget at home
- `#joy-ways-to-earn`
- `#joy-ways-to-redeem`
- `#joy-referral-program`

**Shopify Admin → Online Store → Navigation** → open the menu you want (Main menu or Footer) → **Add menu item** → name it (e.g. "Rewards") → paste the anchor as the link → Save. Note the **Add menu item** button is inside the individual menu's editor, not on the list of menus.

You can append the anchor to a specific page URL too — e.g. `yourstore.com/pages/membership#joy-ways-to-redeem` opens that page with the redeem section expanded.

Once deeplinks are set up you can disable the floating launcher entirely (**Advanced → Display → Hide widget button**). Full deeplink reference: **Settings → Developers → Deep links**.

One limitation: the navigation menu supports **text links only**. A custom gift icon can't be placed in the nav bar through Joy.

### Q45: The widget opens automatically on every visit — how do I stop that?
**Frequency:** ~2 sessions 🆕 new

**Standard answer:**
That's the **Instant popup** setting. Turn it off at **On-site content → Widget → Widget design → Setup → Advanced → Display**.

If what you actually wanted is for the widget to open only *after a customer logs in*, that specific conditional behaviour isn't supported today. The two closest options are:

- **Display after login** — hides the widget from guests entirely, so it appears (and can open) only for logged-in customers
- **Instant popup off** — the widget stays closed until the customer clicks the launcher

Separately, if you want customers redirected back to the page they were on after logging in (rather than to the Shopify account page), that's configurable — ask us and we'll set it up.

### Q46: How do I change the images, colours and text in the widget?
**Frequency:** ~9 sessions 🔁 recurring

**Standard answer:**
Everything lives in the widget editor: **Joy Admin → On-site content → Widget → Widget design → Setup**.

**Images** are edited block by block, not from one central page. A preset or industry theme only sets *sample* images — it never locks them.

| Image | Where |
|---|---|
| Program logo | Header → Logo (upload, paste URL, or "Use store logo") |
| Header background | Header → Header background image (8:5 ratio, 800×500px, under 200KB) + overlay opacity |
| Default avatar | Body → Membership card → Default avatar (1:1, 200×200px, under 200KB) |
| Guest / member card banner | Body → Membership card → Guest card / Member card image |
| Custom image block | Body → Membership card → `+` → Image banner / Image with text |

The layered "card over hero image" look people ask about comes from the **header background image plus the overlay opacity slider** — no custom CSS required.

**Colours, fonts, layout** — Settings → Design (preset themes, primary/background colour, layout, border radius, fonts, button and card colours). **Launcher** styling is under Settings → Launcher.

**Text and labels** — Settings → **Content & Translations**, an inline editor for every widget string. It has **Revert to default** and **On-brand** (AI rewrite) buttons.

A **"Your Logo" placeholder** showing on your widget is expected, not a bug — it's the default when no logo has been uploaded. Add one at Header → Logo.

For anything the editor can't reach (pixel-level spacing, custom layouts, per-block backgrounds), there's a **Custom CSS** field under **Advanced**, or send us the request and we'll apply it.

### Q47: Should I be on the Classic widget or the Unified widget?
**Frequency:** ~7 sessions 🔁 recurring

**Standard answer:**
The **Unified widget** is the current version and where all new development goes. The **Classic** widget is being deprecated and won't receive new features.

Check which you're on at **On-site content → Widget → Widget design** — you'll see two cards with a "live" badge on the active one. Switch with the **Switch to Unified** button at the section heading. All your data — points, programs, customers, translations — carries over untouched, and both versions never run at the same time.

Unified gives you a full sidebar editor with live preview, far more customisation, better mobile behaviour, store credit displayed across the storefront, and a built-in Reviews tab. It shows as a popup on mobile, not full-screen.

Two caveats:
- A few features still fall back to Classic UI even on Unified stores: milestone program UI, the interactive website popup, wallet pass / QR, submit-receipt, and the branded reminder popup.
- Some older layouts (certain membership-card overlay styles) exist only in Classic. If you specifically need one, we can switch you back — but switching **will discard your current Unified design**.

We're happy to migrate and restyle your widget for you, with a preview link before anything goes live.

### Q48: Can I add a custom customer field to the widget?
**Frequency:** ~1 session 🆕 new

**Standard answer:**
Not currently. The Unified widget's profile section shows a fixed set of fields — name, email, birthday, phone and marketing consent — and custom customer metafields can't be surfaced there.

If you're collecting extra customer information, the two supported routes are:

## 9. Notifications & Email

### Q53: How do I edit the emails Joy sends, and the logo on them?
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
Notifications are **off by default**. Enable them at **Joy Admin → Settings → Notifications** — there's a **global toggle** (master switch; if it's off nothing sends) and then per-program toggles.

To edit content: **Settings → Notifications → [e.g. Earn points] → Edit** — subject, body and CTA are all editable.

The **logo** is set once at **Joy Admin → Settings → Email → Logo** and applies to every notification email. If your logo isn't showing there, check it was actually uploaded to that field specifically — it's separate from your widget header logo.

Available notifications cover: earn points, redeem points, birthday rewards, POS redemption, referral coupons and points, referral invites, and VIP tier reach.

**Two things to know:**
- The **preview and test email use placeholder tier names** (Bronze, Silver, Gold), not your configured tier names. Real sends use your actual tiers. This is expected — nothing to fix.
- Buttons in emails need a destination. A "Redeem points" button with no link falls back to your homepage, which may not be a page where the widget displays. Point it at a page where your widget is enabled, using a deeplink such as `yourstore.com/cart#joy-ways-to-redeem`.

### Q54: Joy emails are landing in spam / the sender won't verify.
**Frequency:** ~3 sessions 🔁 recurring

**Standard answer:**
Your sender options are:

| Option | Plans | Domain |
|---|---|---|
| Joy default sender | All | Joy's |
| Simple Custom Sender | Essential+ | Joy's shared `send.avada.io` |
| Custom SMTP | Essential+ | Yours |
| Custom email sending domain | Advanced, Ultimate | Your subdomain |

**Simple Custom Sender** sends through our shared domain, so SPF/DKIM authenticate against `send.avada.io` while the visible From is your domain. If your domain's DMARC policy is `reject`, alignment will fail and mail gets filtered. Add an SPF record including `mailgun.org` (only one SPF record per domain — check with mxtoolbox), and don't weaken your DMARC just to work around this.

**The robust fix** is a **custom sending domain** (Advanced+): use a subdomain like `rewards.example.com` so your root domain's reputation is protected. **Settings → Email → Custom sending domain → Add domain**, add the SPF and DKIM records Joy shows you, wait for propagation, then **Verify**. Custom SMTP is the other full-control route.

If the sender simply won't verify, check the verification link was actually clicked (check spam), validate the address, and resend. If it's still unverified after a few attempts, send us the details.

**One note for new stores:** notifications are disabled for the first few days after install as an anti-abuse measure. Send us your store URL and we'll review and enable it — typically 1–2 business days.

### Q55: Can I stop customers being emailed during a bulk update?
**Frequency:** ~3 sessions 🆕 new

**Standard answer:**
Yes — tell us before we run it. When our team performs a bulk tier reassignment, points import or retroactive sync, we can **disable notifications for the duration** so none of your customers receive emails about the change.

Please flag this explicitly when you request the work. It's a common and reasonable request — nobody wants thousands of "you've reached a new tier" emails going out because thresholds were adjusted.

For your own ad-hoc control, the **global notification toggle** at Settings → Notifications turns off all Joy emails at once, and you can re-enable individual events afterwards.

## 10. Integrations

### Q56: My Klaviyo email shows the wrong value, or `n/a`, for points or tier.
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
Almost always the wrong **lookup type**:

- Data that lives on the **profile** uses `person|lookup` — e.g. `{{ person|lookup:'Joy Loyalty Points'|default:'' }}`, `'Joy Vip tier'`, `'Joy member status'`, `'Joy Referral URL'`, `'Birthday'`
- Data carried by the **triggering event** uses `event|lookup` — e.g. `{{ event|lookup:'Customer points'|default:'0' }}`

Using `person|lookup` for event data returns `n/a`. These are the only supported variable formats.

**For tier emails specifically**, there's a known timing issue: profile properties sync asynchronously, so a "you've reached a new tier" email can be sent while Klaviyo still holds the customer's *previous* tier — producing an email that announces one tier and lists another tier's rewards. Until the permanent fix ships, use the **event** properties instead of the profile property:

- `{{ event|lookup:'New tier name'|default:'' }}`
- `{{ event|lookup:'Current tier name'|default:'' }}`

These pull the tier at the exact moment the event fires and are accurate immediately.

If Joy metrics don't appear in Klaviyo at all, disconnect and reconnect the integration at **Joy Admin → Integrations → Klaviyo** to generate a fresh key and re-stream events. Joy's metrics are `Joy: Earn Point`, `Joy: Redeem Points`, `Joy: Tier Achieved`, `Joy: Points Eligible Reward`, `Joy: Birthday`, `Joy: 7 Days Pre Point Expiration`.

Coupon reminder triggers now also carry `{{ event.coupon_name }}` so you can reference the coupon's display name rather than just the code.

### Q57: The Joy pixel shows "Disconnected" in Shopify Customer Events — is my program broken?
**Frequency:** ~2 sessions 🆕 new

**Standard answer:**
No. **Joy does not depend on customer-event tracking to award points.** Joy receives order, sign-up and customer data directly from Shopify and applies your program rules — so points, balances and tiers are unaffected by the pixel's status. All you need is the program enabled in Joy and the app embed active on your theme.

The pixel is used for referral attribution, so if referrals aren't tracking, it's worth checking. Try re-authorising the Joy app (reopen it and re-accept permissions) so Shopify grants the current scope, then re-check the status. If it's still Disconnected and referrals are affected, send us the store URL and a screenshot and our team will recreate the pixel — there's no reliable manual reconnect in the current Shopify UI.

### Q58: How does Joy connect to my review app / subscription app / other tools?
**Frequency:** ~6 sessions 🔁 recurring

**Standard answer:**
**Review apps** — connect at **Joy Admin → Integration → [app]**, then create a **Write a review** program. Natively supported: Klaviyo Reviews, Air Reviews, Judge.me (needs their Awesome plan or above for API access), Yotpo, Fera, Review Rocket. Loox, Okendo, Tydal, Reviews.io, Stamped and Growave connect via **Shopify Flow templates** (search "Joy" in Flow). Apps outside this list — including AG Product Reviews — aren't supported.

**Subscription apps** — Joy works with any app using Shopify Selling Plans and Contracts. Joy Subscription auto-connects, Shopify Subscriptions and Recharge are supported (Recharge is auto-detected from Shopify subscription orders; nothing to connect). For apps that aren't natively integrated (Seal, BOLD, Subi), Shopify doesn't pass **renewal** data to apps, so connect Shopify Flow and import the **"Joy Loyalty - Subscription Order Data Sync.flow"** template.

**Email / SMS** — Klaviyo, Omnisend, Mailchimp, Drip, Sendlane and PushOwl, all plans, at **Joy Admin → Integrations**.

**Support tools** — Chatty and Gorgias surface the customer's loyalty profile inside your inbox, all plans.

**Mobile apps** — Shopney and Tapcart, **Ultimate only**, using API keys from Settings → Developers.

**Shopify Flow** — Essential+. If a Joy trigger or action errors, the usual cause is that the integration toggle isn't enabled at **Joy Admin → Integrations → Shopify Flow**.

### Q59: Does Joy have an API?
**Frequency:** ~3 sessions 🔁 recurring

**Standard answer:**
Yes — **REST API v2** and the **Webhook API**, covering customers, point transactions, rewards, VIP tiers and referrals, plus real-time events and headless/Hydrogen support.

**Both are exclusively available on the Ultimate plan.** Lower plans receive a `PLAN_UPGRADE_REQUIRED` error. Credentials are generated at **Settings → Developers → Manage keys → Generate key** (App ID + Secret Key) — note that generating a new key invalidates the previous one. Docs: `devdocs.joy.so/joy-rest-api-v2/rest-api-v2`.

If the API is out of budget, two lighter-weight alternatives cover many use cases:
- **Magic Tags** (Advanced+) — add or subtract points by applying a Shopify customer tag like `Joy: Add 500 - Place order #111`, which pairs well with Shopify Flow
- **Shopify Flow** actions — add points, subtract points, add store credit, update tier, send referral invite

## 11. POS

### Q60: How do I set Joy up on Shopify POS, and what does my plan cover?
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
**Install the tile:** on the POS mobile app, tap **Add tile → Select App → Joy Loyalty → Add**. On desktop, Shopify Admin → **Point of Sale → POS apps → Joy Loyalty POS Extension** → add to the smart grid. The Shopify POS app is mobile-only, so you manage everything else through Shopify Admin.

**Plan gating:** POS is on **Advanced and Ultimate**. Essential POS supports earn-only points display; **in-store redemption requires Advanced or higher**. Online redemption works on Essential.

**Enable your programs for POS:** programs are not POS-enabled by default — set **Sales channels** on each earning and redeeming program to include POS. Watch out for contradictory conditions here: setting a rule to *equals Online store* **and** *equals POS* means no order can ever match.

**"No program available" at the register** usually means one of: the plan doesn't include POS redemption, the customer lacks points, no redeem program is POS-enabled, or the extension isn't installed on that device.

If the extension loads slowly or intermittently fails, have staff log out and back in on the device to clear the cached session, confirm the POS app and device OS are current, and remove and re-add the tile. If it persists, send us the device model, OS version and POS app version.

### Q61: A POS customer didn't get points — can I add the customer to the order afterwards?
**Frequency:** ~3 sessions 🔁 recurring

**Standard answer:**
No, not automatically. If no customer is attached to the sale **at the time of payment**, Shopify's order notification reaches Joy with no customer information, so no points can be awarded — even if the email is added later when emailing the receipt. This is how Shopify POS works at the platform level.

**The fix is procedural:** train staff to search for and attach the customer (by email or phone) *before* completing payment. With the Joy Loyalty tile on the device they can also see the customer's balance and tier at that moment. Once attached, points and VIP tier spend are credited automatically.

Past missed orders have to be credited manually per customer in Joy admin.

**This also removes the need for receipt scanning.** Merchants often ask whether customers can photograph a receipt afterwards and have it approved — that's possible via the **Submit receipt** program (Advanced+), but it's more friction for both sides. Attaching the customer at checkout means nothing to claim later. Customers don't need to register on the spot: staff just add their phone or email to the order, and the customer can log in whenever they like to see their points.

Points can also post **later than expected** — they fire from a Shopify webhook that can be delayed on Shopify's side, sometimes 40–90 minutes. This is most painful at POS where customers want to redeem immediately. For repeated delays, send us the order number, order time and when points actually posted.

## 12. Migration, Import & Export

### Q62: How do I export my customers, points and VIP tiers?
**Frequency:** ~8 sessions 🔁 recurring

**Standard answer:**
The **Export customers** button has to be enabled by our team before it appears on the Customers page. Send us your store URL and we'll switch it on — or tell us the columns and period you need and we'll run the export and email you the file (usually within about 5–10 minutes).

The default export may not include the **VIP tier** column; we can add it on request. A tier-only file can be re-imported to bulk-update tiers without touching points.

**For point activity over a date range** (rather than current balances), use **Customers → Activities** → set the date range → **Export type = Earned** → enter your email → start export.

For an accounting-style report combining **customer name, order ID and points earned**, tell us the exact columns and period and we'll generate it. A full programmatic export via API is **Ultimate**.

### Q63: How do I migrate from another loyalty platform?
**Frequency:** ~5 sessions 🔁 recurring

**Standard answer:**
Migration is available on **Essential, Advanced and Ultimate**. Joy can migrate: customer name, email, phone, VIP tier name, birth date, customer status (member / guest / left) and point balance.

There are dedicated guides for Smile.io, Rivo, Yotpo Loyalty, LoyaltyLion, Stamped Loyalty, Bon Loyalty and Appstle. For **anything else** — Square, PrestaShop, Growave, WooCommerce, or any platform that can export customers with point balances — use the **generic CSV** route.

**Two paths:**
- **Import** (self-serve, no enabling needed) — **Customers → Import**. Covers point balances and birthdays. This is enough for most Square/PrestaShop point migrations and works on your current plan.
- **Migrate** (assisted) — the full data set including tiers, status and phone. The tool at **Settings → Migration** is **locked until our team enables it**, so if you can't find an upload button that's expected, not missing functionality.

To get migration enabled, tell us **which app you're moving from** and **what data you want to migrate**. Sync typically takes 5–6 minutes, up to 20 at most. Files over 10MB can't go through chat — share a Drive or Dropbox link.

**Two things that don't migrate:** previously issued **discount codes** from your old platform can't be imported as Joy coupons. If those codes exist in Shopify Discounts, you can surface up to 10 of them in the widget via **Unified Widget → External Discount → Show external discounts in My coupons**. Wishlist data from other wishlist apps also isn't currently migratable.

After any import, remember points and Amount Spent don't recalculate on their own — **Launch** the relevant program to trigger recalculation.

### Q64: My import went in with the wrong values / "Non-existent customers" error.
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
**"Non-existent customers"** means an email in your CSV doesn't exist as a Shopify customer yet. Customers must exist in Shopify first, and emails must match exactly — no typos or trailing spaces.

Re-importing the same file **updates** existing customers matched by email rather than creating duplicates, so there's no need to delete anything first. Import actions available: add points to existing balances (negative values subtract), reset balances, and update birthdays. The birthday column must be named `Birthday(MM/DD)` in zero-padded `MM/DD` format (`03/03`, not `3/3`).

If a file went in with wrong values, send us the corrected file and we'll reset the balances to match it. You'll get an automated email when the import completes.

Note that adjusting points has a **floor of zero** — you can't push a balance negative, so an over-credit can only be removed down to the customer's current balance. And adjusting points does **not** change tier status or tier points; those are separate metrics (see Q31).

## 13. Pricing, Billing & Plans

### Q65: I want unlimited transactions.
**Frequency:** ~5 sessions 🔁 recurring

**Standard answer:**
First, a clarification that matters: a **"transaction" in Joy is any point-related activity** — each time a customer earns points (for example from an order) or redeems points for a reward. It is **not** the same as a Shopify order or a payment. Merchants often assume they've hit an order limit when it's actually the activity count.

Unlimited transactions is **not a plan feature and not an upsell** — it's enabled per store by our team. Share your store URL and we'll verify the account and enable it. Once it's done, just reload the app; there's nothing for you to configure.

### Q66: How does billing work, and why is there a usage fee on top of my plan?
**Frequency:** ~6 sessions 🔁 recurring

**Standard answer:**
Joy is billed as a **base monthly fee plus a free order quota, with per-100 overage** beyond it:

| Plan | Base | Free orders/month | Overage |
|---|---|---|---|
| Starter | $0 | 250 | — |
| Essential | $29/mo | 500 | $15 per 100 |
| Advanced | $129/mo | 2,000 | $10 per 100 |
| Ultimate | $499/mo | 7,000 | $5 per 100 |

Usage is tracked from the **start of your trial**, while Shopify billing starts after the trial ends — so your usage period and your billing cycle are offset, which is the usual explanation for a confusing first invoice. Charges appear on your regular Shopify billing date at **Shopify Admin → Settings → Billing → Bills**.

Free trials are 14 days for Essential and Advanced, 30 days for Ultimate, and can be used **once per store** — reinstalling doesn't grant a new one. Merchants who subscribed before **9 February 2026** keep their previous rate permanently, so your price may legitimately differ from the current published rate.

Upgrades take effect immediately; downgrades take effect at the next billing cycle with data intact. There's a **30-day refund policy** after upgrading if you're not satisfied.

If a charge doesn't look right, send us a screenshot of the invoice and the order count for that period and we'll check it with our billing team.

### Q67: Can I get annual billing?
**Frequency:** ~2 sessions 🆕 new

**Standard answer:**
Not currently — all plans bill on a recurring 30-day cycle. That's because usage fees are calculated dynamically each cycle based on order volume above your quota, and on plan upgrades mid-cycle.

For annual contracts or enterprise arrangements (5,000+ orders/month), we can put you in touch with our sales team for custom pricing. Agency and partner pricing is also available.

### Q68: Can orders from a specific channel be excluded from my quota?
**Frequency:** ~3 sessions 🔁 recurring

**Standard answer:**
Yes, but with an important trade-off: **excluded orders are removed from the loyalty program entirely** — they earn no points and trigger no rewards, as well as not counting toward usage. It's all or nothing.

Joy counts **all Shopify orders** toward the quota regardless of channel, including POS, marketplaces, and orders you create manually in Shopify Admin (draft orders that are never completed don't count). Importing customers alone does **not** count — only actual Shopify orders do.

To exclude a set of orders:
1. Apply a **consistent tag** to every order from that channel — applied automatically, never renamed, since Joy filters on exact tag match
2. Confirm you accept that those orders won't participate in loyalty
3. Send us the store URL, the tag, the reason and the approximate order count, and we'll configure the exclusion

### Q69: Can I get a discount, a longer trial, or access to paid features to test?
**Frequency:** ~5 sessions 🔁 recurring

**Standard answer:**
Pricing is uniform across merchants, so we can't adjust an individual plan's price or quota on request. Promotional offers do run from time to time and apply automatically at subscription.

For trial extensions or temporary access to paid features, tell us your store URL, what you're trying to test and which plan or feature you need, and we'll pass it to the team for review. Please note we can't promise approval — the decision sits with our sales team.

**Development stores** are a special case: they can't accept app charges until they're transferred or move to a paid Shopify plan, so they can't upgrade Joy through the App Store. Let us know and we'll route it appropriately.

## 14. Analytics

### Q70: What does "Revenue by Joy" mean and where do I see the underlying orders?
**Frequency:** ~2 sessions 🆕 new

**Standard answer:**
**Revenue by Joy** (also shown as "Joy assisted") is revenue from orders that used a **Joy-issued discount** — a coupon or reward redemption — for the selected date. The Joy percentage is Joy-assisted revenue divided by your total sales for that period.

Find it at **Joy Dashboard → Analytics → Revenue by Joy**. The order table sits **below the chart** and can be filtered by date, with an **Export** button above the chart. (It's not in the Activities log — that's the point-activity audit trail, a different thing.)

Other metrics on the Analytics page: loyalty members, referred revenue, redemption rate, points earned and points redeemed. Analytics requires **Essential or above**.

To slice loyalty data inside Shopify's own reports, turn on **Settings → General → Show metafields on Shopify admin**, which pushes point balance and VIP tier to customer metafields, and use the **Joy-assisted order tag** (Settings → Order → Order tag synchronization, with **Sync all tags** to backfill).

One gap: there's **no native repeat-purchase-rate-by-tier report** yet. It's logged as feedback; the workaround is the "Returning customers – Joy active redeemers" metric in Shopify Analytics combined with auto-tagging active redeemers.

## 15. Translations & Multi-language

### Q71: My widget or loyalty page content isn't translating.
**Frequency:** ~6 sessions 🔁 recurring

**Standard answer:**
First, set your default language at **Joy Admin → Settings → Translations** — several cases turn out to be the default still sitting on English. Then pick each language and edit the labels per surface. Changes apply to the live storefront immediately.

**Plan gating:** editing English content is on all plans; **changing the default language and editing content** requires Essential+; **Detect Language** (auto-select by IP/browser) requires Advanced+.

**If some strings still won't translate**, the most common cause is a **third-party translation app** (Translate & Adapt in particular) overriding Joy's page meta content and freezing the text. Check for overridden Joy rows in the translation app for the affected language and remove them. Pasting a custom translation directly into the meta field row is what causes this.

Note that **loyalty page** content is generally translated through Translate & Adapt (it's theme content), while the **widget** uses Joy's own Detected Translation settings. Program names are translated at **Reward programs → [program] → select language → edit the name**; VIP tier names at **Membership → [tier]**.

Some strings — notably VIP tier descriptions inside Customer Accounts — can still show untranslated. Tell us which surface and we'll log it.

Checkout extensions don't support language auto-detection; you can set one language at the checkout level.

### Q72: Which languages are supported?
**Frequency:** ~2 sessions 🔁 recurring

**Standard answer:**
The **storefront** supports 38 languages, all fully customisable — every label, message and button can be edited to match your brand voice. Surfaces covered: the loyalty widget, loyalty page, account page (Loyalty Hub), Shopify checkout extensions, and Apple/Google Wallet passes.

The **Joy admin interface** currently supports six languages — English, French, Spanish, German, Italian and Japanese — set at **Settings → In-app languages**. This is separate from your storefront translations.

If a language you need isn't in the list, tell us which one and your store URL and we'll pass the request to the team.

### Q73: Currency symbols are being translated into words.
**Frequency:** ~1 session 🆕 new

**Standard answer:**
This was a real bug: our auto-translation engine lacked an exclusion rule protecting currency formats, so the `$` symbol was being translated into its text equivalent in some languages. Our team has updated the translation rules so currency symbols are strictly protected and never converted to text, and the fix is live.

If you're running multiple markets with different currencies and see any price rendering incorrectly, send us the market and the affected surface and we'll check it.

**A related note on Translate & Adapt:** if our team assists with translations, we will ask before using auto-translate. Shopify's two-language limit in Translate & Adapt refers to how many languages can be **auto-translated**, not a one-time credit that's consumed — if you delete existing translations but keep the same languages active in Settings → Languages, you can run auto-translate again on those languages. You can also export a CSV, supply your own translations and re-import, which bypasses auto-translate entirely.

## 16. Errors, Access & Edge Cases

### Q74: A button in the app does nothing when I click it (Grant access, Grant Markets Access).
**Frequency:** ~3 sessions 🆕 new

**Standard answer:**
This is usually a **permissions** issue, not a bug. Permission-granting actions must be performed by the **store owner or a staff member with full admin permissions**. When a limited-permission staff account clicks Confirm, Shopify blocks the request silently — so nothing appears to happen.

Ask the store owner to log in, open the Joy app, and click the button again. It should go through immediately.

**What "Grant Markets Access" enables:** it gives Joy access to your Shopify Markets configuration, which unlocks **region-specific referral rewards** — different reward structures per market (e.g. a different discount for your US market than your existing one). Without it, Referral Rewards by Region is unavailable.

If it still fails from a full-permission account, send us a short screen recording and your collaborator code and we'll investigate.

### Q75: I'm getting a 404, a blank page, or the admin won't load.
**Frequency:** ~4 sessions 🔁 recurring

**Standard answer:**
Try a **hard refresh** first (Ctrl+Shift+R / Cmd+Shift+R) and give it a moment — a fair number of these clear on their own.

If it persists, send us:
- which page or feature you were opening
- what you clicked, and at what step the error appeared
- a screenshot

Two known-normal behaviours worth checking before treating something as a bug:

- **"Your Logo" placeholder** — that's the default when no logo has been uploaded. Add one at **On-site content → Widget → Setup → Header → Logo**.
- **"Automatic Discount Limit Reached"** — Shopify caps a store at **25 automatic discounts total**, across all apps. Remove an unused one in Shopify Admin → Discounts before creating a new one. This is a Shopify limit, not a Joy one.

For storefront console errors, unexpected redirects or analytics issues, send the store URL, the exact page and action, and a screenshot of the console error — many of these turn out to be theme or Liquid issues rather than Joy itself.

### Q76: Do you have a GDPR data processing agreement?
**Frequency:** ~1 session 🆕 new

**Standard answer:**
Yes. Our published documents are:

- GDPR overview: `joy.so/gdpr/`
- Data Processing Addendum: `joy.so/data-processing-addendum-dpa/`

**No separate signature is required** — using the app's services constitutes agreement to the DPA terms, so the DPA is already in effect for your store.

If your legal team needs a countersigned copy or has specific questions about sub-processors or data residency, let us know and we'll route it to the right team.

### Q77: I changed my primary domain and Joy still shows the old one in account links.
**Frequency:** ~1 session 🆕 new

**Standard answer:**
Joy doesn't hardcode or cache your shop domain — the widget renders Shopify's native Liquid routes (`routes.account_url`, `routes.account_register_url`) server-side, so it outputs whatever Shopify supplies.

If those routes still return the old domain, the source is Shopify's **customer accounts** configuration, not Joy. You can confirm this yourself: with the Joy app embed **turned off**, your theme's own sign-in buttons will redirect to the old domain too. Under new customer accounts, Shopify generates `account.{primary_domain}`, and that value comes from the Customer Accounts OAuth configuration.

This can break navigation inside in-app browsers (Instagram, TikTok), which handle cross-domain redirects poorly. We can't intercept it on our side — the redirect originates from Shopify. Raise it with Shopify support to have the account domain updated.

Note also that Joy has no separate customer account system: the login button simply points to Shopify's login, and the widget never auto-redirects a logged-out visitor — it only shows a login button when clicked.

### Q78: My reward/points balance shows a raw variable string instead of a value.
**Frequency:** ~2 sessions 🔁 recurring

**Standard answer:**
Send us a screenshot and the store URL — these are rendering bugs and we fix them at source rather than asking you to work around them. Two we resolved this week:

- A **currency formatter** wasn't handling a particular Shopify money format, so a reward description rendered a raw variable instead of a formatted amount (e.g. "€10 off"). Fixed and deployed.
- A **`{{loyalty_point}}` placeholder** showing literally in the VIP tier progress text on the account page. That one is editable yourself if the placeholder was mistyped: **account page editor → Loyalty dashboard → setup panel** on the right. Progress text supports `{{remaining_points}}`, `{{remaining_spend}}`, `{{remaining_orders}}`, `{{next_rank}}`, `{{loyalty_point}}` and `{{loyalty_orders}}`, and Joy auto-fills the right variables once you choose your tier calculation method.

If a change you made in the app isn't reflected on the widget (for example a perk you deleted still showing), that's a sync issue rather than a settings problem — tell us and we'll clear it.
