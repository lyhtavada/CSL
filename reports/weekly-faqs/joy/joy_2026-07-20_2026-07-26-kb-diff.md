## GAP detail (no equivalent in KB — recommend adding)

### Q12 — Manual points excluded from VIP tier calculation by default
**File to add to:** `kb/reference/points-advanced.md`, in the "Adjusting a customer's points has a floor of 0" section (or a new subsection right after it).
**Why:** `points-advanced.md` documents that adjusting a balance doesn't re-sync VIP tier points, but doesn't mention the **"include in tier calculation" checkbox** available when making a manual adjustment. Two chats this week hit exactly this — merchant expects manual points to count toward tier progress by default and it doesn't. Worth an explicit callout since it's an easy self-serve fix once known.

### Q16 — Redeemed discount doesn't scale with order quantity
**File to add to:** `kb/reference/redeeming-programs.md`, under "Discount types" or a new "How redemption value is applied" note.
**Why:** Not stated anywhere in the cached KB. Confirmed via two independent chats as expected/by-design behavior (order-level discount, applies once regardless of quantity) — should be documented so agents don't have to reason it out each time.

### Q18 — Imported coupons can't be revoked via the normal Revoke button
**File to add to:** `kb/reference/migration.md` (Data migrated / limitations section) and cross-referenced from `kb/reference/redeeming-programs.md`.
**Why:** `migration.md` documents that old discount codes aren't imported as Joy coupons at all, but doesn't cover the separate case where an external/imported coupon **is** surfaced in Joy (e.g. via "Show external discounts in My coupons") and then can't be revoked normally. Confirmed via two chats, same root cause both times — team manually hides + credits points. No workaround exists yet; document as a known limitation with the manual-fix procedure, mark it as escalate-only (no self-serve fix).

### Q21 — No renewal/reassessment for Exclusive VIP tiers
**File to add to:** `kb/reference/vip-tiers.md`, in the "Tier Assessment" section — add an explicit line that Assessment applies to auto-progressing tiers only, not Exclusive tiers.
**Why:** The KB's Tier Assessment section describes the feature thoroughly but never states the boundary against Exclusive tiers. One merchant asked specifically about requiring annual re-qualification for a manually-assigned ambassador tier and there's no mechanism — worth a one-line clarification to save agents from re-deriving this from the Exclusive-tier limits list each time.

### Q29 — Cart drawer showing redeem/points to logged-out guests
**File to add to:** `kb/reference/cart-drawer.md`.
**Why:** File not read directly this run, but grep found no guest-hide toggle documented anywhere in the KB set. This was reported as a shipped fix (dev team added a theme-setting option to hide the redeem-inline block for unauthenticated visitors) in one chat this week — should be documented once so agents can point merchants to the toggle instead of escalating each time it recurs. Recommend Liz/team confirm exact toggle name/path with product before publishing, since this agent only saw it from the merchant-facing chat side, not a doc.

## PARTIAL detail (KB covers the base case, missing a sub-point)

### Q17 — 100-variant discount limit is a Shopify platform cap, not a Joy setting
**File:** `kb/reference/redeeming-programs.md`
**Missing sub-point:** The file covers product selection and variant eligibility for redeem rewards, but doesn't mention the ~100-variant hard limit on the Shopify Discount API, or that it counts variants (not products) — which is the actual source of confusion in two chats this week (merchant selected <100 products but hit the error because of variant count). Add a short note plus the workaround (group into a Collection).

### Q26 — Referral analytics / export status field meaning
**File:** `kb/reference/referral.md`, `kb/reference/analytics.md`
**Missing sub-point:** `analytics.md` documents "Referred revenue" as a metric; `referral.md` documents the Paid/Fulfilled-based reward timing (which explains "Awaiting fulfilment"). Neither documents the **export view's** specific status column values ("Created At", "Completed At", "Pending") or the discrepancy one merchant reported (Completed At timestamp showing while status is still Pending). Recommend adding an export-fields glossary to `referral.md`, and flagging the Completed-At/Pending mismatch to the product team as a possible display bug rather than publishing it as expected behavior.

### Q30 — Product/redeem-item names can't be auto-translated by Joy
**File:** `kb/reference/translations.md` (not read directly this run — inferred from cross-references in vip-tiers.md/onsite-content.md; recommend Liz confirm exact file before patch)
**Missing sub-point:** The translation troubleshooting guidance (Translate & Adapt overriding Joy content) is well covered elsewhere in the KB set per prior weeks' diffs, but the specific case of a **redeem reward's product name** being pulled directly from the Shopify product title (and therefore untranslatable via Joy's own translation settings — needs Shopify's product-title translation instead) doesn't appear to be called out. Worth a one-line addition.

### Q32 — Omnisend sync parity with Klaviyo
**File:** `kb/reference/integrations-email.md` (not read directly this run — grep confirmed the file exists and covers ESP list)
**Missing sub-point:** Prior weeks' KB summary (Q56/Q58 in last week's mined file) documents Klaviyo variable syntax in detail but Omnisend is only listed as a supported ESP without describing the same profile-property sync (points/tier/member status/referral link/birthday) or the manual "Sync Again" button. One chat this week confirmed this parity explicitly — worth adding a short Omnisend-specific note alongside the Klaviyo section so agents don't have to infer parity.

### Q34 — Marketplace/multichannel orders counted toward usage quota
**File:** `kb/reference/pricing.md`
**Missing sub-point:** `pricing.md` (per last week's diff, Q68) documents that all Shopify orders count toward quota including POS and marketplaces, and that channel-based exclusion is possible via order tagging. This week's chat is consistent with that policy, but surfaced a specific precedent — a merchant got Target+/Marketplace Connect orders excluded from their bill after dispute/escalation. Not a KB contradiction, just worth a note that this exclusion has been granted before for marketplace-channel orders specifically, so agents can cite precedent when a similar request comes in (still needs escalation each time, not self-serve).
