## 1. AI Agent — Setup, Training & Done-for-You

### Q1: How do I set up and train the AI agent for the first time? 🔁 recurring
**Frequency:** ~70 sessions
**Standard answer:**
Three steps: (1) **AI agent → Training data → Manage** — add Products, Collections, Discounts, Markets, FAQs, and Custom knowledge; (2) **AI agent → Instructions → Manage** — set the AI's role, tone, welcome message, and behaviours; (3) **AI agent → Test AI → Test now** — check responses before going live (the Test feature does **not** consume your AI-conversation quota). Then **Activate** the AI agent so it works on the live storefront, not only in Test. Most "the AI is just guessing / says hi generically" cases are stores where Training data and Instructions were never filled in and the data-source toggles are still off — start there. Advanced AI features (Store Instructions, Scenarios, expanded Data Sources) require a paid plan.

### Q2: Can your team set the AI up for me? (Done-for-you setup) 🔁 recurring
**Frequency:** ~120+ sessions (the dominant opener)
**Standard answer:**
Yes — our team does a guided, done-for-you setup **free of charge on any plan**. To tailor it we'll ask for: your assistant's **name + welcome greeting**, your **support email**, **availability** (respond 24/7 or only when your team is offline), your **brand tone**, which topics should always go to a human (refunds, complaints, custom quotes, pricing), and your key **policy/FAQ page URLs**. We enable the right data sources (Products, Collections, Discounts, store policy pages), configure human handover, and add Custom knowledge / FAQs, then test in **AI agent → Test AI** before **Activating**. Note: we set up alongside you in-chat and never need your store password — collaborator access only, and only when hands-on investigation is genuinely required.

### Q3: How do I add custom Q&A / a sale campaign (e.g. 4th of July) / a specific discount code to the AI? 🔁 recurring
**Frequency:** ~15 sessions
**Standard answer:**
Add custom Q&A at **AI agent → Training data → Manage → Custom knowledge → Add data → Q&A** (for a small set) or **Multiple Questions** (download the CSV template, fill Topic/Question/Answer/Status, re-import). For a **sale campaign**, add Q&As like "What's on sale?" / "Is there a discount code?" there. For a **discount code**: all your Shopify discounts sync automatically, and you pick which one the AI is allowed to share in **Training data → Discounts** — the AI shares it **only when a customer asks**. If you want the AI to **offer** the code proactively, put it in the welcome message or set up a proactive-chat popup on your homepage (Proactive Chat). Set the code's end date in Shopify, then re-sync so the AI has the current data.

### Q4: How do I make the AI follow a specific flow / stop it asking for order numbers / create a custom scenario? 🔁 recurring
**Frequency:** ~10 sessions
**Standard answer:**
Two levers. For a repeatable process, add a scenario at **AI agent → Instructions → Manage → Assistant skills → Custom scenarios → + Add scenario** — name it after the topic customers mention and write the step-by-step flow (returns, custom-order intake, "collect name + email + reason," etc.). For behaviours like "don't ask customers for an order number" or "recommend best-sellers first," add a rule under **Instructions → Manage → General instructions → Behaviours**. Important gotcha this week: the AI's **default after-sales flow** (cancellations/refunds/delivery issues) automatically asks for an order number — several non-retail merchants (e.g. a school-absence intake form, S324) hit this. If your store doesn't do sales, you often need to turn down the default after-sale/shopping skills so they stop overriding your custom instructions; if a scenario still isn't followed after save + Test AI, send the conversation ID.

### Q5: How do I upload files / a relational database / my FAQ CSV to train the AI, and how long until it's used? 🔁 recurring
**Frequency:** ~10 sessions
**Standard answer:**
**AI agent → Training data → Manage → Custom knowledge → Add data → Files** (PDF, CSV, TXT, JSON; keep each file ≲1–2MB; CSV is best for structured Q&A). A relational/Airtable database is fine — export the tabs you need as CSV with columns like Topic / Question / Answer / Status (type `qna`) and upload; for large or messy exports our team can structure and upload it for you. Processing is usually a **few seconds to a few minutes** after upload finishes — if you add data on a schedule (e.g. daily at 2pm), upload it a little ahead so it's indexed in time, then confirm in **Test AI**. For website content, add individual page **URLs** (the domain alone only trains on the homepage); use **Custom knowledge → Sync Store Page → Add Q&A** to auto-scan your policy pages and generate ~15 draft Q&As you can review and keep.

### Q6: How do I check if the AI actually did a good job / where do I read past AI conversations? 🔁 recurring
**Frequency:** ~5 sessions
**Standard answer:**
Read the actual conversations in **Inbox** (each chat shows whether the AI or a human handled it). For aggregate performance — AI involvement, resolution, conversation counts — go to **Analytics** (Overview and AI agent tabs). Note that during setup the Inbox chats you see are usually your own **Test AI** sessions; give it time for real customers to use it. There's no live "how many visitors are browsing right now" counter — Analytics covers conversation/AI metrics, not real-time visitor count (logged as a feature interest, S174).

## 2. AI — "No access to my data" / Wrong or Hallucinated Responses

### Q7: The AI says "I don't have access to that" or gives wrong info for a product that IS active and synced. 🔁 recurring
**Frequency:** ~12 sessions
**Standard answer:**
Work through it in order: (1) confirm the product shows **Active/Enabled** in **AI agent → Training data → Products** and that the source toggles (Products, Collections, FAQs) are actually **ON** — several stores had products synced but the data toggle left off, so the AI couldn't use it (S346); (2) check the source shows a nonzero **"X items learned"** and a recent **Last updated** (S177); (3) remember **product-page/spec metafields and images aren't reliably indexed**, so data stored only there (size charts, technical specs) may not reach the AI — re-enter it as text in **Custom knowledge**. If a correctly-synced, active product still isn't found, click **Review sources** under the AI's answer to see what it used, then send the **conversation ID** — retrieval misses like this are escalated and fixed with an added instruction hook. Tip: having several sources that cover the same topic with slightly different wording can make the AI inconsistent — deactivate duplicates.

### Q8: The AI made up a fact (wrong location, wrong phone number, a category we don't sell, a product/discount we don't have). 🔁 recurring
**Frequency:** ~10 sessions
**Standard answer:**
"No sources" under an answer usually means the AI was **hallucinating** because the correct fact isn't in its training. Fix it by adding the correct fact: put the exact answer in **AI agent → Training data → Manage → Custom knowledge** (Q&A) and, for a wrong phone number or a stray claim, use **Review sources** under that answer to find and correct the source it pulled from (S231, S295). For scope drift ("it keeps talking about home & garden when we sell fragrances," S236), tighten **Instructions → General instructions** so the AI only speaks to your actual catalog. Write the **correct** statement rather than "don't say X" — negative phrasing can leak into replies. If a wrong fact persists after you've corrected the data, send the conversation ID.

### Q9: On my multi-market / multi-language store, the AI can't find a product when I use its translated-domain URL. 🆕 new
**Frequency:** ~3 sessions (one very large, unresolved)
**Standard answer:**
This is a real limitation with multi-market stores: the AI recognizes products by your **primary-domain** product URL, but a **translated-domain URL** (e.g. a `.pl` storefront vs the primary `.com`) may return "no information," even when the product is Active and synced on both stores (S234). Searching by **product name or SKU** usually still works; pasting the translated URL is what fails. Workarounds while this is investigated: reference products by name/SKU in your instructions, and make sure each market's store has fully synced its products. This is escalated as a product-side issue — send the two store URLs, the product/SKU, and an example of the failing question so the team can trace it. (Logged as an ongoing technical case.)

### Q10: The AI keeps appearing / replying on my translated pages even though I turned the AI agent OFF. 🆕 new
**Frequency:** ~2 sessions
**Standard answer:**
If you deactivated the AI agent but it still shows (uncustomized) on non-English pages, the usual cause is a **translation app overwriting Chatty's metafields** on those language variants (confirmed root cause this week, S167). First confirm the AI toggle is off and clear cache/try incognito; if it still shows only on translated pages, this needs our team — share which language pages, and we'll correct the metafield handling (fixed successfully this week). Same root cause also drove some inbox display glitches on translated stores.

## 3. Notifications — Desktop Sound, Email & Mobile ⚠️

### Q11: My agents stopped getting desktop sound / banner notifications (Chrome), even though settings are correct. 🆕/🔁 (frequency sharply UP) ⚠️
**Frequency:** ~10 sessions
**Standard answer:**
First-line self-check: in **Settings → Notifications**, confirm the relevant triggers have **Web/desktop notifications on** and a **sound option** selected, and click **Subscribe** if prompted; in the OS, make sure the browser tab isn't muted, Do-Not-Disturb/Focus is off, and the browser is allowed to play notification sounds (macOS: **System Settings → Notifications → [browser] → Allow + Play sound**). Important known issue surfaced this week: on **macOS + Google Chrome**, push-notification **sound** is a documented **Chrome/macOS compatibility problem, not a Chatty bug** — visual banners work but sound doesn't (S325, S345); Safari behaves differently. If sound fails across multiple devices/browsers after all of the above, escalate with device model + OS + browser version, and the team will investigate and confirm a fix (S238 was fixed on Chatty's side, so escalate — don't assume it's only the browser).

### Q12: My email notifications for customer chats stopped arriving (a test email still works). 🔁 recurring ⚠️
**Frequency:** ~6 sessions
**Standard answer:**
If a *test* notification lands but real customer-chat notifications haven't arrived for weeks, don't stop at the settings toggles. Two confirmed root causes this week: (a) the notification email had been **unsubscribed on the backend** — Chatty's system had it marked as manually unsubscribed, so no emails were sent until re-enabled (S152); and (b) notifications are configured **per member account**, so an email can still be receiving (or missing) alerts based on that member's own **Settings → Notifications**, not just the admin's (S333). Collect the email address(es) that should receive alerts, confirm each member's notification settings, and escalate so the team can check the backend logs — they can see whether any notification was actually sent.

### Q13: I'm getting notifications even though I turned ALL notification toggles off. 🆕 new
**Frequency:** ~2 sessions
**Standard answer:**
Notification settings in Chatty are **per member account**, not global. If your admin account has everything off but your team still receives emails, the alerts are coming from **another member's** notification settings (or a second connected email). Check every member under **Settings → Notifications** and turn theirs off too (S333). If notifications still arrive after all member accounts are set to off and no email account is connected, escalate with a screenshot and the receiving addresses so the team can trace it.

## 4. Human Handover & AI Availability

### Q14: I want only AI (or only humans) on live chat — no live agents, just collect the email and follow up. 🔁 recurring
**Frequency:** ~12 sessions
**Standard answer:**
Set the handover destination to match your staffing at **AI agent → Instructions → Manage → Assistant skills → Customer support skills → Human handover → "Where does the customer go?"**: choose **Collect info & follow up by email** if you have no live agents (the AI collects the customer's details, emails a summary to your team, and shows a **Response time promise**); choose **Transfer to human in Chatty inbox** if an agent will join the same chat; or **Show contact methods** to let the customer pick a channel. To run **AI-only** live chat, keep the AI active and set the destination to email/contact methods. To run **humans-only**, deactivate the AI agent and keep the **Live chat** block on. If you staff chat only some hours, set the **offline behavior** (Leave a message / Show contact methods) and whether the AI keeps replying (**Allow only outside business hours**). Confirm your support email is set so summaries reach you.

### Q15: How does the AI hand off when it can't answer, and how do I get emailed when it escalates? 🔁 recurring
**Frequency:** ~6 sessions
**Standard answer:**
Auto-handover triggers live under Human handover → "When should AI hand off to your team?": "Customer asks to talk to a person" is always on; **AI cannot answer**, **Customer repeats question**, and **Negative sentiment** are toggles; use **Intent rules → + Add rule** for topics that should transfer immediately (cancellations, wholesale, legal). Pick a destination under "Where does the customer go?". To be **emailed** when the AI escalates, go to **Settings → Notifications → Email Notifications** and enable the escalation/unanswered notification, then set the recipient email. If you keep no live agents, use the **Collect info & follow up by email** destination so customers are told they'll get an email, not left waiting on a phantom live agent.

### Q16: A human agent joined but the AI keeps replying, or I can't assign a chat to the AI. 🔁 recurring
**Frequency:** ~4 sessions
**Standard answer:**
Once a human joins/takes over an **Open** conversation, the AI steps back and no longer appears in the Assignee dropdown — this is by design (S323). A recent app update briefly broke the ability to re-assign an Open chat to the AI agent; that was fixed by the dev team, so if you can't assign to the AI after an update, refresh and, if it persists, escalate with the conversation ID. If the AI is replying **over** a joined agent, confirm the agent formally **Joined** the chat and that AI availability isn't forcing "always reply," then escalate with the conversation ID and which agent joined.

## 5. Widget / Chatbox — Position, Header Icon, Appearance

### Q17: Can I put a chat icon in my header nav (next to search/account) instead of the floating bottom-right bubble — and open the chatbox from it? 🆕 new
**Frequency:** ~3 sessions
**Standard answer:**
The built-in **Position** control only anchors the floating button to a page corner with an offset — it can't embed an icon into your theme's header. To add a header icon that opens the chat, use a **deep link**: **Chatbox → Advanced → Deep links**, copy `#chatty-chat` (opens Live Chat) or `#chatty-home` (opens the chatbox home), and add it to a header menu item via **Shopify Admin → Content → Menus**, or as a button/icon in your theme. Matching a custom icon to your theme design and placing it precisely in the header needs a small theme/CSS change — share the reference design and grant collaborator access, and TS can implement it (done this week, S250). If you also want the floating bubble **hidden** so chat only opens from that header icon, see Q18.

### Q18: How do I hide the floating widget so it only opens from my own icon/link? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:**
You can hide the floating chat bubble on specific pages via **Chatbox → Advanced → Display settings → Display pages → Hide on specific pages**. To keep the widget available (so a deep-link/header icon still opens it) while it isn't visible in the corner, this generally needs a targeted CSS adjustment from our side that hides the launcher but keeps "Display chatbox on your store" enabled — collect collaborator access and we'll apply it (done this week, S250).

### Q19: How do I launch the chat from a URL / deep link (open a specific tab)? 🆕 new
**Frequency:** ~3 sessions
**Standard answer:**
Deep links are in **Chatbox → Advanced → Deep links**. Append the fragment to any store URL or use it on a button/menu item:
- `#chatty-home` — opens the chatbox home
- `#chatty-chat` — opens the Live Chat tab
- `#chatty-tracking` — opens the Order Tracking tab
- `#chatty-help` — opens the FAQs tab
Example: a "Track my order" nav item pointing to `https://yourstore.com/pages/contact#chatty-tracking`.

### Q20: The button/bubble isn't centered, overlaps another element, or Position changes don't affect mobile. 🔁 recurring
**Frequency:** ~9 sessions
**Standard answer:**
Self-serve: **Chatbox → Appearance → Chatbox button → Position** — drag the dot or set an **Anchor + Horizontal/Vertical offset**. Known limits this week: the Position control's two offset values don't cleanly split desktop vs mobile, and cosmetic issues (the bubble not centered in the circle, overlap with a Google/translate icon or add-to-cart, different ideal offsets per device) aren't fully self-serve — collect a screenshot, the page, and device, grant collaborator access, and TS applies a targeted CSS fix (done repeatedly this week, e.g. S231, S250, S343, S304). Merchants can supply exact px values per device (e.g. "mobile 93px, desktop 105px") to speed it up.

### Q21: How do I change the store/AI name shown in chat, add a logo/avatar, or fix the chatbox header text? 🔁 recurring
**Frequency:** ~8 sessions
**Standard answer:**
Different fields control different spots: the **chatbox header heading** is at **Chatbox → General → Header**; the **store name/logo** is at **Settings → General → Store information**; the **AI assistant name and avatar** are under **AI agent → Settings** (top-right) / **Instructions → General instructions**. If you renamed the AI but the storefront still shows the old text — especially on a non-English store — the **Translation** version is likely "Outdated": **Settings → Translation → Auto-translate → Save** and confirm it flips to "Updated." During a live chat (human), customers currently see your **store logo + store name**, set in Store information; a team member's personal avatar shows only if they've uploaded one under their profile.

### Q22: How do I remove the Chatty branding / the "Explore this product" popup / the "typing…query" status text? 🆕 new
**Frequency:** ~4 sessions
**Standard answer:**
The **branding line** at the bottom of the proactive popup isn't a self-serve toggle — our team can hide it for you (S39). The **"Explore this product" / product-recommendation popup** is a Proactive Chat campaign: deactivate it in **Proactive Chat** (S167, S236) — but note some "explore products" popups actually come from a *different* app, so confirm which app owns it. The **"typing…/query…" status text** the AI shows before answering can't be turned off in settings today; if you want just the three-dot indicator, our team can add a small CSS snippet to hide the wording (done this week, S231).

## 6. Widget Not Showing / Can't Type / App Embed

### Q23: The chat widget isn't showing, or the message box shows but I can't type / my messages don't appear. 🔁 recurring
**Frequency:** ~12 sessions
**Standard answer:**
Sequence: (1) **Shopify Admin → Online Store → Themes → Customize → App Embeds → Chatty** ON (toggle off/on + Save if it was already on), and reload the storefront; (2) **Chatbox → General** → turn the chatbox **On** and confirm **Blocks → Live chat** is enabled; (3) if a **pre-chat form** is asking for name/email, that must be filled before the input appears. For "I can send but my own bubble doesn't show," or the input field never renders even with everything enabled, it's usually **cache** (hard-refresh: Ctrl+F5 / Cmd+Shift+R, or incognito — this resolved several cases, S205, S322) or a backend render issue — if it persists after that, grant collaborator access and escalate with device/browser + a screen recording. If clicking the App Embed toggle "does nothing," refresh the theme editor, toggle again, and **Save** in the top-right before closing (S299).

### Q24: How do I test the chat on one page only, without embedding it site-wide (embedded chatbox)? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:**
Use the **embedded chatbox**: **Chatbox → Advanced → Embedded chatbox** adds the full chat interface to one specific page template (via the theme editor) instead of floating everywhere. Two prerequisites: the **Chatty (Core) app embed** must be enabled in the theme (App embeds panel), and **Chatbox → General → Blocks → Live chat** must be on. If you want the embedded box on one page but no floating bubble elsewhere, turn off "Display chatbox on your store" in Chatbox → General and keep the app embed on. If the embedded section is added but still doesn't render with all of the above set, escalate with a screenshot of the page + theme editor (S168).

## 7. Inbox — Resolve / Reopen, Missing Chats, 404 ⚠️

### Q25: I get 404 / inbox won't load / resolved chats reappear in Open / new chats don't show / inbox auto-scrolls to newest. 🔁 recurring (frequency DOWN but still live) ⚠️
**Frequency:** ~10 sessions (explicit "404" opener ~3–4)
**Standard answer:**
First-line: **hard-refresh and open the inbox in an incognito window** — this clears the transient 404 and "inbox is waiting / can't load conversations" state for many merchants. If it persists, or you see resolved chats back in **Open**, new chats not appearing, the view **auto-scrolling back to the newest message** when you try to read an older one, or **login "No shops found"** (several traced to Shopify's **Spring 2026** update, S264/S84), collect conversation/session IDs, affected emails, store URL, a screenshot/Jam/Loom, and timestamps, and escalate. Some translated-store cases were caused by a **translation app overwriting metafields** (S257). Tell the merchant it's a system-side issue we're investigating and we've logged their details. Don't advise reinstalling. **Internal note for Liz:** volume dropped vs last week but the defect family is clearly not fully fixed — keep on the dev radar.

### Q26: Can I un-resolve / reopen a conversation, or turn off the Resolve button? 🆕 new
**Frequency:** ~4 sessions
**Standard answer:**
By design, once a conversation is marked **Resolved** it moves to the Resolved tab and there's no "Unresolve" button — it reopens automatically only when the customer sends a new message (and after ~5 days of inactivity a new message starts a brand-new conversation). There's no standard setting to disable the Resolve button, but our team **can disable it on your account** on request (done this week, S162), and it can be logged as a feature request for a native toggle. If you want to keep older Open conversations from disappearing after you resolve one, set a **reminder** on them so they resurface in the unresolved view (S360). (Chatty also has no "delete conversation" option — conversations can only be resolved, S61.)

### Q27: Some inbox messages / older conversations / recent orders aren't showing in a chat. 🔁 recurring
**Frequency:** ~5 sessions
**Standard answer:**
First check all inbox **tabs** (All / Unread / Resolved / Mine) and clear any **channel filter** and date range — anonymous chats show under a random visitor name, so search by date, not email. A brief loading lag can hide messages; wait and toggle tabs. If genuine data is missing (older conversations you know exist, or the **recent-orders** panel inside a chat is blank), it can tie into the inbox loading defect (Q25) — collect the customer email, approximate date/time, and a screenshot, and escalate. For missing order data specifically, the team may request **collaborator access with the Orders permission** to trace it server-side (S360).

## 8. Products, Sync & Analytics

### Q28: Products I deleted in Shopify weeks ago are still in Chatty / how do I force a resync? 🆕 new
**Frequency:** ~3 sessions
**Standard answer:**
Chatty auto-syncs products daily (around 12:00 AM PST), but deleted products don't always drop out on the next run. Trigger a manual resync in **AI agent → Training data → Products** (More actions → resync), and you can also deactivate the stale products in the list so the AI stops using them. If deleted products keep reappearing after a manual resync, that's not expected — send an example product and we'll reset the sync on our side (done this week, S128). "Product training" simply means Chatty reads your product data (title, description, price, variants) so the AI can answer product questions; raising the product limit doesn't change your price by itself, but larger training limits are tied to higher plans (S147).

### Q29: How do I verify Chatty's assisted revenue / chatty-assisted vs chatty-direct orders? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:**
Chatty tags attributed orders in Shopify with **chatty-assisted** or **chatty-direct**. To review the revenue side, open **Analytics → Overview / Revenue** in Chatty, which shows assisted-revenue metrics and the related orders (S342). Note the tagged order won't necessarily map 1:1 to a named contact in the Inbox (anonymous/attributed sessions), so reconcile via Analytics rather than by searching the Inbox for the buyer's email.

## 9. Channels — Email, WhatsApp, Messenger/Instagram

### Q30: My email channel won't verify — it's an alias, or a forwarding/spam problem. 🔁 recurring
**Frequency:** ~10 sessions
**Standard answer:**
Email connects by **forwarding**: in **Settings → Channels → (your email) → Manage**, copy the Chatty forwarding address (`…@chattyemail.com`), add a **forwarding rule in your own mail provider** to it, then click the verification link — verification only completes once forwarding exists on your side. Key alias case this week: an **alias** (e.g. `support@` as an alias of `info@`/`sales@`) often **can't be verified separately** — Chatty authenticates via the **primary mailbox** and your provider (Gmail, etc.) manages the alias display, so connect the real mailbox (S311). If an alias still won't verify, our team can re-send verification / verify it manually in some cases (they did this week for a couple of stores). For **outgoing replies landing in spam** (S362), the fix is on the sending-domain side: set the "reply as" address correctly and add the right **SPF record** (e.g. `include:amazonses.com`) — after DNS updates it can take up to 48h to settle. To enable AI on email, toggle Email under **AI agent → Settings → AI channels** (auto-replies after ~5 min if no agent responds).

### Q31: How do I change the admin/notification email (the address that receives chats)? 🆕 new
**Frequency:** ~3 sessions
**Standard answer:**
There are two different emails. The **admin email** (the account that receives chat/contact-form notifications and logs into the Inbox) is tied to your Chatty account — our team enables the change, then you **reload → Edit profile → Change email → verify the new address** (S19). The **support/"reply-as" email** shown to customers is set in the email-channel and AI settings. If you want the admin account switched to a different email entirely (e.g. `support@`), note that on Free/single-seat plans we can only **replace** the existing account, not add a second one; a verification code is sent to the new address to confirm (S362).

### Q32: How do I connect WhatsApp, and why does it error / stay "Pending"? 🔁 recurring
**Frequency:** ~6 sessions
**Standard answer:**
Connect under **Settings → Channels**; to get **AI replies** on it, also enable the channel under **AI agent → Settings → AI channels**. To show a WhatsApp contact button on the widget, use **Chatbox → General → Contact → Add contact method → WhatsApp**. Requirements to connect the WhatsApp Business API: a Meta Business Manager with **Business Admin** role, completed **Business Verification**, **2FA** on the number, the number not live on the personal WhatsApp app or another API provider, and all permissions granted during OAuth. **"Pending"** = Meta-side verification (usually 24–48h). If you hit **"AVADA group company limited cannot onboard customers at this time"** (S133), that's a Meta-side onboarding error, not something you can fix — send a screenshot and we'll investigate. To release a number/partner access from a WABA you've migrated away, that's managed in your Meta Business settings (S121).

### Q33: I want to change / remove the auto messages that go out on Instagram & Facebook. 🔁 recurring
**Frequency:** ~2 sessions
**Standard answer:**
Chatty connects and syncs Messenger/Instagram conversations; standard IG/FB **automations** (instant replies, away messages) are set in **Meta Business Suite**. However, Chatty-side messages a customer sees can come from **Quick Replies** (e.g. an Auto-Resolve closing message at the top of **Manage Quick Replies**) and the **chatbox welcome message** — check there first, and delete duplicate quick replies causing confusion (S331). If a merchant sees an auto message they can't locate in either place, escalate; in one case this week the messages only stopped after **turning Chatty off for IG/FB**, confirming Chatty as the source even though it couldn't be reproduced — flag such cases for deeper investigation.

## 12. Translation & Language

### Q37: The chatbox/AI shows the wrong language, or a language stopped displaying (e.g. Hebrew reverted to English). 🔁 recurring
**Frequency:** ~8 sessions
**Standard answer:**
For **UI labels / welcome text / proactive popup wording** in the wrong language: **Settings → Translation** — select the language, **Auto-translate** (or edit strings), Save, and confirm the status flips from **"Outdated" to "Updated."** For the AI **replying** in the wrong language, add a behaviour under **Instructions → General instructions → Behaviours**: "Always respond in the same language as the customer" (and, in an AI-drafted email, it should match the conversation language). Note: Chatty auto-supports ~19 languages; others (e.g. Hebrew, Arabic) are added as a **Custom language** under Translation. If a previously-working language **reverts to English on its own** (S11) — often caused by a translation app overwriting metafields — that's a bug: confirm it's still "Published" in Translation, then escalate with the store URL. The Chatty admin UI itself isn't available in every language (e.g. Arabic dashboard, S306).

### Q38: Can I change the source/primary language my FAQs are entered in, and how many languages does my plan cover? 🔁 recurring
**Frequency:** ~3 sessions
**Standard answer:**
Auto-translation applies to synced/dynamic content, not to the source text you type into FAQs — Chatty doesn't re-translate your own source FAQ content into other languages automatically (S76). You can change the language you enter new content in via the in-app language switch, and going forward add new sources in that language. The number of languages is **plan-based** (Basic covers a limited set of languages, so adding more may require an upgrade) — check **Subscription → View details**, and third-party translation tools (e.g. T-Lab) aren't currently supported as a substitute. FAQ content lives on Chatty's servers, not as a Shopify metaobject.

## 13. Mobile App / PWA

### Q39: Where's the Chatty mobile/desktop app, why won't it show in the App Store, and when's a native app coming? 🔁 recurring
**Frequency:** ~8 sessions
**Standard answer:**
Chatty's app is a **Progressive Web App (PWA)** — it's not on the App Store/Play Store, so there's nothing to search for. Install it from **app.chatty.net** (or **Inbox → Download Chatty app** / **Settings → Notifications → Chatty mobile app → Download app**) by adding it to your Home Screen. On **iPhone it must be installed via Safari specifically** (Share → Add to Home Screen); installing via Chrome can leave notifications/sound not working (S345, S353). A blank white screen after install usually means it needs a **fresh reinstall** (remove the icon → reopen in Safari → re-add). Desktop PWA installs from Chrome/Edge's address-bar install icon or Safari's Add to Dock. **New this week:** a **native iOS/macOS app has been submitted to Apple and is expected to be approved in ~2–4 weeks** (S345) — a change from the prior "PWA only" answer, so you can tell interested merchants it's coming.

### Q40: I get on-screen banners but no notification sound on Mac. 🔁 recurring
**Frequency:** ~5 sessions
**Standard answer:**
See Q11 — on **macOS + Chrome**, banners work but push-notification **sound** is a known Chrome/macOS compatibility limitation, not a Chatty bug; Safari behaves differently. Confirm macOS **System Settings → Notifications → [browser] → Allow + Play sound for notifications** and that the browser/tab isn't muted or in Focus mode. On the installed PWA + Safari, sound generally works (S345 confirmed this and flipped a 2★ review to 5★ once resolved). If it still fails after these checks, escalate with Mac model + macOS + browser version.

**Frequency:** ~12 sessions
**Standard answer:**

- **Basic** $19.99/mo — 100 AI conversations/mo, 500 products, 100 custom answers, 50 URL & File, 5 team members, 12-month chat history, full chatbox customization.
- **Pro** $68.99/mo — 500 AI conversations/mo, 8,000 products, 1,000 custom answers, 500 URL & File, 10 team members, unlimited chat history, full AI channels + analytics, API/webhooks.

If a store consistently exceeds even Plus (e.g. 2,000–3,000/mo, S282), that's an **Enterprise/custom plan** conversation — route to the PM. ### Q42: My bot says I've run out of AI conversations even though I upgraded. 🔁 recurring
**Frequency:** ~4 sessions

An "out of chats" flag right after upgrading is usually a limit/usage state that hasn't refreshed — the team can verify your current plan's included conversations and reset the counter (done this week for a store that had moved to a higher plan, S276). ### Q43: How do I cancel/downgrade, and can I get a refund? 🔁 recurring
**Frequency:** ~6 sessions

A **30-day money-back guarantee** applies if you didn't continue after the first month, cancelled before the first cycle ended, or accidentally chose a paid plan without using it. For a refund, collect a **screenshot of the Shopify charge** (app name, cycle, amount); per CS process, **CS cannot approve refunds without CS Leader sign-off** — resolve the underlying issue first where possible (several cancellations this week were AI-quality or notification-driven and were saved once fixed), then create the Trello card for the CS Leader. ## 15. API, Integrations & Data Export

### Q44: Where's the Public API / can I forward chats to my own server, and which plan unlocks it? 🆕 new
**Frequency:** ~3 sessions
**Standard answer:**
The **Chatty Public API** supports pulling conversations and messages (e.g. list a conversation's messages) and there are **webhooks** for events like `customer_message` and `ai_response`, which can push chats to your own server in near real time (S221). **API key generation and webhooks are Pro/Plus only** — on Free/Basic you'll need to upgrade to Pro or Plus to generate a key. Point merchants to the official Chatty Public API docs for the base URL, auth headers, and endpoints. For contact/order data there's also a self-serve **Contacts → Export** (CSV sent to your email).

### Q45: Can I export my conversations / product-specific FAQs (a date range or specific records)? 🔁 recurring
**Frequency:** ~5 sessions
**Standard answer:**
You can export a **single conversation** from its ⋮ menu, and **Contacts** via **Contacts → Export**. There's **no bulk date-range conversation export in the UI** — for a date range (e.g. "Jun 23–29") or a set of product-specific FAQs, contact support with the **date range/records + the email to send to**, and the team exports it (CSV or JSON) and emails it (done several times this week: S138, S286, S320, S286). If the CSV won't parse, open it in Excel/Google Sheets, or request JSON. This came up repeatedly — the recurring manual export is worth flagging for a native bulk-export feature (already logged, S138).

### Q46: Can I use OpenAI / a stronger AI model, or switch the AI model in Chatty? 🆕 new
**Frequency:** ~2 sessions
**Standard answer:**
Chatty runs on a secure, enterprise-grade large language model built for support, with regular upgrades — there's **no option to plug in OpenAI or swap the underlying model** yourself (S306, S338). If a merchant feels replies are weak, the fix is almost always **data/instruction quality**, not the model: enable Shopping skills (**AI agent → Instructions → Assistant skills → Shopping skills**), tighten instructions, and add Custom knowledge, then re-test. Log the OpenAI/model-choice request as product feedback with their specific example. (Related unresolved item this week: on Messenger/Instagram the AI sometimes sends **product links instead of rich product cards** with image/price — escalated as a channel-side issue, S306.)
