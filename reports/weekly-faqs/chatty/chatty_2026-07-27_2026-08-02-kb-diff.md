### Q18 — mined-FAQ error (not a KB problem)

The published mined FAQ (`chatty_2026-07-27_2026-08-02.md`, Q18) states "Language allowances by plan: Free 1, Basic 2, Pro 9, Plus unlimited." This is **wrong** — it conflates the KB's two separate columns. `kb/faq/translation.md` → "Translation Language Limits" is correct and states:

| Plan | Languages the chatbox can use | Of those, auto-translated |
|------|-------------------------------|----------------------------|
| Free | 1 | none (manual) |
| Basic | **3** | 2 |
| Pro | **10** | 9 |
| Plus | Unlimited | Unlimited |

So the correct figure to quote for "how many languages can I add" is **Basic 3 / Pro 10**, not 2/9 (2 and 9 are the *auto-translate* counts, a different number). This same wrong 1/2/9/unlimited figure also appears in last week's report (Jul 20–26, Q30) — it has been repeating uncorrected for at least 2 weeks. Recommend fixing the standard answer text (no KB patch needed, KB is already right) and adding a note to the mining prompt to pull both columns next time.

### Q5 / Q21 — Metafield selection limits per plan (GAP)

Two merchants this window (S204 Turkish, S372 English) hit a **"metafield selection limit"** error while configuring which product metafields the AI can search against, and CS manually raised it (20 → 30, 20 → 50) as an ad-hoc accommodation. `kb/faq/ai-training-setup.md` documents *how* to toggle synced metafields (`Manage metafields`) and that non-standard/third-party metafields aren't synced, but **does not document a per-plan metafield count limit or how CS should handle an increase request** — unlike products/custom-answers/URLs, which have a documented case flow (`kb/case/ai-product-limit.md`). No verified default number exists yet to publish (the two observed increases were case-by-case, not confirmed plan defaults) — **skipping a patch, logging as a GAP for PM/product to confirm the actual default limit** before this becomes a documented case flow.

### Q9 — AI carries over previous product's context on product pages (GAP, same open issue flagged last week too)

`kb/faq/ai-training-setup.md` → "AI Page Context Detection" documents the intended behavior (AI should use the current product's data) but has no entry for the known failure mode where the **AI Product Assistant embedded on product pages** answers using a stale/previous product's info while the product card itself updates correctly. This exact bug was already flagged as unresolved in the Jul 20–26 report (Q15) and is still unconfirmed-fixed this week — recommend a "Known Issue" note once engineering confirms status, not before.

### Q9 — "AI mentions unrelated product categories" / stale catalog mismatch (PARTIAL)

`kb/faq/ai-training-setup.md` → "AI Using Wrong Store's Catalog" covers the case where the AI clearly answers from a **different store's** catalog (contact support with conversation ID). It doesn't cover the milder case observed this week (S339): AI referencing categories/product counts inconsistent with what's actually synced for the *same* store (160 actual products vs. AI referencing ~1,830). Same resolution path (conversation ID → support investigates) likely applies — recommend adding a sentence to the existing section rather than a new one, but no new fact to add without an engineering-confirmed root cause.

### Q13 — Conversations no longer auto-assigning to first replying agent (GAP, new active bug)

`kb/faq/inbox.md` → "Who a Conversation Gets Assigned To" documents the intended assignment behavior; there's no entry yet for the regression multiple merchants (S398 explicitly, detailed report) hit this week where auto-assignment on first reply stopped working, paired with conversations only appearing in "All" after being manually resolved. This reads as an active engineering defect rather than a settings issue — no self-serve fix exists yet, so nothing to publish; flagging for a "Known Issue" KB note once the team confirms a fix/ETA.

### Q8 — "Review sources" is a **test-zone** feature (PARTIAL, minor wording risk)
