## OUTDATED — Detail

### Q9 — AI conversation session window: 3 days or 5 days?

**Contradiction:** `kb/faq/ai-conversations.md` states:

> "Sessions last up to **5 days**, with automatic expiration after inactivity... **The Same Customer Within 24 Hours Counts Once**"

This week, CS agents told **two separate merchants** (independently, different sessions) that the window is **3 days**:

> "There's a **3-day session window** that determines when a new conversation starts. If a customer comes back with more questions within 3 days of their last message, it's still counted as the same conversation..." (session 8acc1ae1)
> "...session/message ends on... session expiration [3-day]..." (session 1bcf4573, from Linda)

**Fix:** this needs a real verification with product/eng before editing the KB either direction — the KB says 5 days + a separate 24-hour same-customer rule, while live agents this week said 3 days with no mention of the 24-hour rule at all. Flagging for Liz to confirm the correct current mechanic with Fennic before either file gets patched, rather than guessing. **No payload drafted for this one** — see Notes.

### Q13 — FAQ page font mismatch: which setting actually fixes it?

**Contradiction:** `kb/faq/faqs-page.md` says:

> "go to **FAQs → Appearance → Font** and switch to **"Default"**"

This week a merchant's screen had **no such option** under FAQs → Appearance, and the fix CS actually applied was via **Settings → General → Font** (confirmed as a real settings location — `kb/faq/general-settings.md` lists "Font" under the **Settings → General** tab). This suggests the FAQs → Appearance → Font path may be stale/renamed.

**Fix:** update `faqs-page.md`'s "FAQ Page Font Doesn't Match the Theme" section to point to **Settings → General → Font** as the primary fix, with a note that some accounts may still show a FAQs → Appearance → Font control — flag both until confirmed which is current.

### Q29 — Order attribution: Shopify order tags or metafields?

**Contradiction:** `kb/faq/analytics.md` (`## Verifying Assisted Revenue & Order Attribution`) says:

> "Chatty tags attributed orders in **Shopify** with one of two order tags: `chatty-assisted`... `chatty-direct`"

This week, a CS agent (Jade) told a merchant the mechanism **changed to metafields**:

> "We have recently changed how Chatty writes its attribution on the Shopify order page. Previously, we added tags to the assisted orders, but they have been replaced by the **Chatty Assisted** and **Chatty Direct** metafields." — with an official doc link: `help.chatty.net/analytics/Chatty-Attribution-Metafields`

This looks like a genuine, recent product change that the cached KB hasn't caught up with yet (the KB does document *other* July/Aug 2026 attribution changes in the same file, so it's actively maintained but missed this one, or the metafield doc link is merchant-specific/wrong).

**Fix:** verify with the product/eng side whether this is a global rollout or a partial/beta change, then update `analytics.md`'s attribution section accordingly (tags → metafields, with the Shopify Settings → Metafields filtering steps this week's agent walked the merchant through).

## GAP — Detail

- **Q6b** → *(no matching file)*: no KB coverage of the "two Markets/domains on one Shopify store share ONE Chatty config" limitation — only the AI Agent name/Store name can differ per Market; FAQs, contact info, and widget settings are shared store-wide. This is a real limitation merchants hit when running region-specific storefronts (UK+US) on a single Shopify backend.
- **Q10** → `kb/faq/proactive-chat.md`: no coverage of Custom Recommendation search terms colliding with Shopify's native "Best Selling" logic when a merchant uses modifier words like "great" or "best" as triggers — causes irrelevant best-sellers to surface instead of the intended product type.
- **Q14** → `kb/faq/faqs-block.md`: no coverage of two confirmed root causes for a Published FAQ not appearing in the FAQ block's question picker: (1) the FAQ's category is still in **Draft** status (hides it even though the FAQ itself is Published), (2) the block's category **search only loads the first ~20 categories** — a category further down won't be selectable until reordered near the top.
- **Q24** → `kb/case/email-channel-issues.md`: covers the *corporate IT-managed forwarding block* case, but not the distinct **SPF/DMARC misconfiguration on the merchant's own sending domain** blocking Chatty's `amazonses.com` sending server — a different root cause with a specific fix (`include:amazonses.com` in the domain's SPF record) and its own doc (`help.chatty.net/live-chat/channels/email/fix-email-delivery-issues-with-amazon-ses`).
- **Q27** → `kb/faq/klaviyo.md`: documents the standard pre-chat-form → Klaviyo sync (contact info only, no consent/list), but doesn't cover the separate **"Subscribe Newsletter" Proactive Chat campaign**, whose submissions go to Chatty Contacts + Shopify's own email list — **not** Klaviyo at all, and carry no marketing consent. Merchants conflate the two.
- **Q35** → `kb/case/ai-wrong-responses.md` / `kb/faq/ai-training-setup.md`: no coverage found of the confirmed limitation that **subscription products cannot be added to cart via AI chat** (customer must select a plan first, which the in-chat flow doesn't support) — distinct from the general "Disabled product" exclusion mechanism, which IS documented.
